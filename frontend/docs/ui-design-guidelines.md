# 前端 UI 设计规范

本文定义 WineStock 后续业务页面必须遵守的 UI 设计规则。
它负责回答“页面应采用什么结构和交互模式”；具体颜色、圆角、阴影和动效 token 以 [`visual-style.md`](visual-style.md) 为准，实施后的状态与量化验收以 [`ui-consistency-checklist.md`](ui-consistency-checklist.md) 为准。

本文适用于 `frontend/` 中新增或重构的页面、业务组件和共享控件。
页面专属文档可以补充业务字段和流程，但不能静默放宽本文规则。

## 规范关键词

- **必须 / 不得**：验收阻断项，不满足时不能以单页特例或视觉接近为由通过。
- **应 / 优先**：默认方案；偏离时必须说明现有模式为什么不能表达业务语义。
- **可以 / 允许**：满足所列前提时可选，不代表可以绕过其它强制规则。

## 设计决策顺序

新增页面或交互前必须依次确认：

1. 页面属于列表管理、工作流、表单编辑、详情浏览还是临时操作。
2. 现有页面模式和共享组件能否表达相同语义。
3. 桌面与移动端共享哪些状态、请求和操作。
4. 哪些差异来自真实业务，而不是局部实现习惯。
5. 如何在宽桌面、断点附近和移动端量化验收。

没有业务语义差异时，不得建立新的页面骨架、控件外观、状态表达或动效语言。

## 全局设计原则

### 相同语义使用相同表达

- 相同层级的标题、字段、按钮、状态、列表和临时浮层必须复用同一结构与样式。
- 页面名称由路由目录单点声明；侧栏、移动 Header 和页面标题不得维护不同文案。
- 同一操作在不同页面不得随意切换图标按钮、文字按钮、链接或菜单表达。
- 业务差异只改变必要内容，不改变无关的间距、边框、控件高度和交互反馈。

### 稳定骨架与最小变化

- 页面状态变化必须保留已经建立的页面骨架，只更新真正变化的数据、数字、控件或局部反馈。
- 搜索、筛选、排序、刷新和分页不得替换整套页面结构或清空仍然有效的旧结果。
- 动画范围必须与状态变化范围一致：工作流步骤可以切换舞台，后台刷新只反馈列表局部状态，数字变化只动画数字。
- 加载、空数据、错误和零条结果不能各自演变成一套互不相同的页面布局。

### 只展示必要信息

- 只显示字段名称、当前状态、明确命令和操作前必须知道的后果。
- 控件已经表达的事实不得通过说明文字、状态标签或第二个按钮重复表达。
- 未获得可靠数据前不得展示容易被误解的推导值、服务状态或业务结论。

### 共享优先

- 页面负责业务状态、请求、分页和操作编排；共享组件负责通用结构、样式和交互细节。
- 搜索、选择、字段、密码、图片、Dialog、Notice 等已有共享组件必须优先复用。
- 相同视觉模式在第二个页面出现时，应评估提取共享组件或共享样式，避免复制近似实现。
- 共享组件不得依赖某个业务页面的 SCSS 才能正确显示。

## 页面骨架

### 列表管理页面

标准顺序为：

```text
页面标题与必要上下文
工作区
  列表工具栏
  结果区域
  列表尾部
临时操作：Dialog / Drawer / 移动操作面板
```

- 桌面端的工具栏、结果和列表尾部应收在一个连续工作区中，不拆成多个漂浮卡片。
- 页面标题只识别页面和提供必要上下文；搜索、筛选、刷新、新建和设置属于列表工具栏。
- 移动 Shell 已显示路由标题时，页面内部不得重复同名大标题。
- 移动端可以解除桌面工作区外框，但工具栏、结果和尾部顺序不得改变。
- 不得为了尚未发生的编辑长期预留空白列；临时编辑优先使用 Dialog、Drawer 或独立工作流。

### 多步骤工作流

- 各步骤必须共享标题、步骤指示器、舞台边界、工具栏和导航按钮位置。
- 上一步与下一步使用对称文案、相同尺寸和相同按钮等级；真正提交业务状态时才升级为主按钮。
- 动态摘要不得推动主要导航按钮；非必要摘要在窄屏可以隐藏。
- 步骤切换使用稳定舞台和统一方向动效，不能让两个步骤同时处于可操作状态。

### 表单编辑页面

- 同层级字段统一使用“字段标题在上、输入控件在下”的结构。
- placeholder 只提供示例，不能替代字段名称。
- 同一表单列系统内的字段高度、宽度和间距必须一致；错误状态不得插入可见文字行改变字段或网格高度。
- 长描述、复杂图片或确有空间需求的字段可以跨整行；普通短字段不得机械拉满全部剩余宽度。
- 页面不得复制通用字段的标题、红框错误状态、隐藏错误说明、必填标记和无障碍结构。

## 列表与表格模式

### 桌面三段式目录

同时承担对象识别、参数浏览和业务判断的列表，标准结构为：

```text
固定身份区 | 弹性参数区 | 固定判断或操作区
```

- 左区承载名称、编号、图片和关键身份；右区承载判断、状态或行级操作；中区承载可压缩的辅助参数。
- 左右区必须保持不透明背景，并继承当前行的普通、悬浮和选中背景。
- 左右区在横向滚动起点、任意位置和最大位置的坐标变化必须为 `0`。
- 分段边界只由固定区的强边线或竖向阴影表达；中间字段不得绘制会随内容移动、破坏三段关系的分隔线。
- 阴影不得扩大 `scrollWidth`；优先使用不参与滚动尺寸计算的内阴影或等价实现。
- 表头、数据行和列表尾部必须使用相同的分段与对齐逻辑。

### 宽度与滚动

横向滚动是最后手段，必须遵循以下顺序：

1. 宽度充足时列表铺满容器，`scrollWidth` 必须等于 `clientWidth`。
2. 优先压缩内容短、允许截断或允许弹性变化的参数列。
3. 再压缩身份区等仍能保持识别能力的区域。
4. 判断区和操作区不得压缩到标签、数字或按钮溢出。
5. 达到各段按真实内容测得的可读下限后，才允许中区横向滚动。

- 列宽应使用 `minmax()`、`clamp()` 或等价弹性规则，不得用随意的大 `min-width` 提前制造滚动。
- 日期、状态和短数字不得无上限占据剩余宽度。
- 操作区下限必须包含完整按钮宽度、间距、边框和内边距。
- 固定区内容不得溢出自身后再把滚动区域撑大。
- 页面本身不得出现横向滚动；必要滚动只能属于明确的列表中区或其它局部容器。

### 连续列表与编辑表格

- 浏览型数据优先使用连续列表；需要直接编辑多字段的数据使用表格。
- 动态模板属性应放入稳定的复合单元格，不为每个动态字段生成横向表头。
- 数据行使用横向分隔线、统一背景和轻量悬浮反馈，不把桌面每一行做成独立大卡片。
- 列表尾部承担分页加载、分页失败、继续加载和已加载全部状态，不占用普通数据单元格。

### 移动列表

- 移动端必须重组相同信息语义，不得缩放桌面表格或制造页面级横向滚动。
- 列表项可以使用克制的单列卡片，但身份、状态和操作位置应在同类页面间保持一致。
- 移动卡片圆角不超过 `8px`，避免大圆角、厚阴影和过度留白。
- 桌面和移动端共享同一份筛选、总数、分页和业务操作状态。

## 工具栏与控件

### 列表工具栏

- 搜索、筛选和排序字段按控件底边对齐；数量、刷新、新建和设置组成稳定操作组。
- 动态数量和刷新文字不得推动操作按钮或改变工具栏高度。
- 桌面、窄桌面和移动端复用同一组控件与事件，只调整布局，不维护两套操作。
- 自动搜索组件只负责输入与防抖；页面负责请求、取消旧请求和重建分页。
- 筛选字段使用字段控件；tab 用于内容页切换，分段控件只用于高频互斥输入模式，不用于普通筛选。

### 按钮与图标

- 熟悉且高频的刷新、新建、设置、关闭等操作可以使用统一线性图标按钮。
- 目录工具栏存在明确且高频的创建入口时，建议将该入口使用主题色填充的 `icon-button--primary`，相邻刷新、设置等辅助操作保持中性；尺寸、图标语言和间距仍需一致。
- 同一局部操作组通常只保留一个主题色图标按钮；子分组、表单字段、候选项和行内加入等上下文新增继续使用中性按钮，避免削弱主操作层级。
- 高风险、结果不易撤销或需要明确命令名称的操作使用文字按钮。
- 图标按钮必须提供 `title` 和 `aria-label`，并复用统一尺寸、线宽、边框和状态样式。
- 同位置的后置按钮应保持稳定宽度，不能因文案变化挤压输入框。

## 状态与数据变化

列表页面必须显式区分首次加载、已有结果、零条结果、后台刷新、分页加载、初始失败、刷新失败和分页失败。

- 后台刷新必须保留旧结果、旧总数和滚动上下文，成功后再替换第一页。
- 搜索、筛选和排序请求必须取消旧请求；主动取消不得显示错误或断连反馈。
- 分页只追加并按业务唯一标识去重，不得覆盖已有页。
- 零条结果时移除没有意义的表头、空表格和移动空列表，保留工具栏和稳定列表尾部。
- 刷新失败保留上一次成功结果；分页失败只在尾部提供恢复入口。
- 加载反馈遵守 [`async-state-transitions.md`](async-state-transitions.md)，不得为了动画人为延迟请求或数据更新。

## Dialog、Drawer 与浮层

- 列表是主任务、编辑是临时上下文时，桌面优先保持列表全宽并使用 Dialog。
- 同一业务的新建与编辑应复用同一个外壳、表单和操作区，只改变会话模式与标题语义。
- Dialog、Drawer 和 Popover 必须复用现有遮罩、层级、关闭、焦点返回和 motion token。
- 大型表单只允许内容区滚动；标题和底部操作区保持稳定。
- 移动端重内容编辑使用底部面板或全屏面板，不照搬桌面双列布局。
- 属性分组使用标题、间距和分隔线，不连续堆叠灰色卡片。

## 响应式规则

- 项目只维护桌面和移动两种主要体验，`768px` 附近只做布局收缩，不创建第三套业务逻辑。
- 响应式可以改变换行、字段宽度、列表与卡片呈现以及非必要文字显隐，不能改变操作语义和数据状态。
- 固定操作栏必须为安全区和最后一条内容预留空间。
- 长名称、长编号、最大按钮数量和最窄支持宽度必须作为常规验收数据，而不是异常情况。

## 可访问性

- 字段、搜索、筛选和图标按钮必须有可访问名称。
- 请求期间结果区域使用 `aria-busy`，但仍有效的旧结果不能从可访问树中移除。
- 初始加载使用礼貌状态播报，明确错误使用 `alert`；同一次数量变化不得由多个区域重复播报。
- 筛选和结果更新不得抢夺焦点；Dialog 或浮层关闭后焦点返回触发控件。
- 键盘焦点、触控尺寸和 `prefers-reduced-motion` 必须遵守现有视觉与动效规范。

## 例外与规范演进

- 页面偏离本文规则前，必须在所属页面文档记录业务原因、替代方案和量化验收结果。
- “页面特殊”本身不是理由；必须证明现有模式无法表达真实业务语义。
- 新模式只在存在明确复用价值时提升为项目级规则；单页探索先记录在 `implementation-notes/`。
- 当新模式成为正式规则时，必须同步更新本文、共享组件、检查清单、代码地图和受影响页面。
- 具体页面的落地过程和历史结论不得继续堆入本文，应保存在页面文档或 `implementation-notes/`。

## 实施入口与完成条件

进行 UI 修改时必须依次读取：

1. [`visual-style.md`](visual-style.md)：视觉语言和 token。
2. 本文：页面结构和交互模式。
3. [`ui-consistency-checklist.md`](ui-consistency-checklist.md)：状态、视口和量化验收。
4. [`async-state-transitions.md`](async-state-transitions.md)：涉及异步状态时的稳定呈现规则。

实现完成后至少证明：

- 没有无业务理由的新视觉模式或重复组件。
- 宽桌面没有不必要的局部滚动，移动端没有页面级横向溢出。
- 固定区域在局部滚动前后坐标不变，局部内容没有溢出后扩大滚动范围。
- 加载、零结果、刷新失败和分页失败符合稳定骨架规则。
- 真实浏览器三档视口、控制台、`pnpm build` 和 `git diff --check` 均通过。
