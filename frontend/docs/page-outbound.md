# 新建出库页面实施设计

本文定义 `/outbound`“新建出库”工作台的前端实施边界。页面创建的是待审批出库单，不在提交时扣减库存；审批通过后 core 才按指定批次或 FIFO 扣减库存。它复用 `/inbound` 的两步工作台、物品目录、稳定异步状态、草稿保护与响应式规则，但不复制入库来源、价格、模板、图片属性或“直接入库”行为。

## 页面目标

- 让拥有 `stock.outbound.create` 的用户从可用物品中建立多明细出库申请，填写去向和备注，并明确每条明细采用指定批次还是 FIFO。
- 在提交前帮助用户发现数量、批次、库位和草稿完整性问题；最终库存充足性仍由审批事务判断。
- 不伪造实时锁库、可用数量承诺、审批结果或成本金额。创建成功只表示“已提交审核，库存尚未扣减”。
- 桌面、接近 768px 和 390×844 共享同一份草稿、批次选择和提交状态，只调整布局。

通用视觉、字段、Dialog、稳定等待、三段式列表和验收要求以 `visual-style.md`、`ui-design-guidelines.md`、`ui-consistency-checklist.md`、`async-state-transitions.md` 为准。本文件只补充出库业务语义。

## 已有 HTTP 契约

| 接口 | 权限 | 页面用途 |
| --- | --- | --- |
| `GET /api/items/options` | `stock.item.read` 或 `stock.outbound.create` | 服务端分页搜索可选物品；返回名称、SKU、单位、主图。 |
| `GET /api/items/{id}/batches` | `stock.item.read` 或 `stock.outbound.create` | 分页读取当前仍有余额的批次，供“指定批次”模式选择。 |
| `POST /api/outbound` | `stock.outbound.create` | 创建 pending 出库单；请求包含 `destination`、`notes` 和 `items`。 |
| `GET /api/outbound/{id}` | `stock.outbound.read` | 创建成功后的单据读取或后续跳转，不作为提交前校验源。 |

`OutboundItemRequest` 的稳定字段为 `item_id`、大于 0 的 `quantity`、可选 `batch_id` 和可选 `location_id`：

- `batch_id` 为空：审批时在可选库位范围内 FIFO 扣减。
- `batch_id` 不为空：审批时只从该批次扣减；若同时传 `location_id`，批次必须属于该库位。
- `location_id` 为空：FIFO 可跨当前所有库存库位；不能在前端显示成已锁定某库位。

当前 `POST /api/outbound` 只创建 `pending`，没有“直接出库”模式；页面必须只有一个“提交审核”主按钮。审批页拥有通过、拒绝和库存不足错误处理，本页不调用审批接口。

### 首版不能假设的能力

- 物品轻量选择响应不保证返回实时可用数量；不能因目录项可见就显示“库存充足”。
- 批次列表是读取快照；用户选择后到审批前可能被其它操作消耗，审批仍可能返回库存不足。
- 后端未提供预占、预检或批次间拆分请求。首版一个明细只选择“单个指定批次”或“FIFO”，不在前端拆分多个批次。
- 不为本页引入出库模板、价格、客户主数据、运单、附件、折扣或销售结算字段。

## 权限与职责

| 用户能力 | 行为 |
| --- | --- |
| 无 `stock.outbound.create` | 路由守卫离开页面，不加载物品目录。 |
| `stock.outbound.create` | 可搜索物品、查询批次、建立草稿和提交审核。 |
| 另有 `stock.outbound.read` | 创建成功后可显示“查看出库单”跳转，否则只显示提交结果。 |
| 另有 `stock.outbound.approve` | 仍不在本页显示直接出库；可在成功 Notice 提供“前往出库审批”链接。 |

前端权限只用于收敛入口。服务端仍在每次物品、批次和提交请求中实时授权。

## 信息架构

```text
页面标题“新建出库” + 当前步骤/草稿摘要
├─ 步骤 1：选择出库物品
│  ├─ 搜索物品
│  ├─ 触底追加物品目录
│  └─ 加入/移出当前申请
├─ 步骤 2：填写出库单
│  ├─ 去向、备注
│  ├─ 出库明细连续列表
│  └─ 每条“扣减批次与库位”抽屉
└─ 固定操作区：清空草稿 / 上一步 / 提交审核
```

不使用常驻双栏编辑、商品卡片网格、表格内联批次下拉或浏览器原生日期/选择弹层。桌面工作区连续；临时批次选择使用抽屉或 Dialog，移动端使用同一会话的全屏面板。

## 步骤 1：选择出库物品

复用 `useInboundItemCatalog` 的服务端搜索、取消、分页去重和触底模式；若抽取为中性 `useItemOptionCatalog`，不得改变已实现入库行为。

- 每个物品行为“主图 + 名称 + SKU/单位 + 加入按钮”；已选时按钮切换为“移出申请”，不额外堆叠成功色状态文字。
- 搜索使用 `SearchField`，防抖请求，旧请求取消；目录为空、加载失败、继续加载与到底状态固定在列表尾部。
- 选中物品按 `item_id` 去重。移除时若草稿存在批次选择，只清理该行的局部状态，不影响其它明细。
- 顶部摘要显示“n 条明细”“n 个物品”；数量尚未填写时不得显示误导性的总数量或预计金额。
- 只有 `stock.item.manage` 时可沿用入库页面的“新建物品”入口；新建成功后将物品加入当前出库草稿，并重新进入本步选择上下文。

## 步骤 2：填写出库单

### 基础信息

- `destination`：必填，标签为“出库去向”，示例“客户 / 部门 / 项目”。最大长度与 API 一致（128）。
- `notes`：可选，默认折叠为“添加备注”，展开后使用 `FormTextarea`，不把空备注占据主工作区。
- 不显示来源、单价、预计金额、入库模板、有效期编辑、批次号生成或直接入库切换。

### 出库明细主列表

桌面使用与入库明细一致的连续行，不新增宽表列：

1. 物品身份区：主图、名称、SKU、单位、明细编号。
2. 数量区：正数输入，输入后显示“<数量> <单位>”；不能与不同单位合计。
3. 扣减摘要区：`按 FIFO 分配` 或 `批次 <编号> · 库位 <名称>`；必要时显示“尚未选择库位（允许全部库位）”。
4. 操作区：打开“扣减批次与库位”抽屉、移除行。抽屉按钮必须显示当前选择摘要，不能只写“编辑”。

行内完整性仅显示实际阻塞：数量缺失/非法、指定批次已被删除或不属于选择库位、批次候选加载失败。不要常驻显示“已完整”。

移动端每条明细为单列项目：第一行身份与移除，第二行数量，第三行扣减摘要与抽屉入口。触控目标最小 44px；长 SKU 和批次号截断但可在抽屉完整查看。

## 扣减批次与库位抽屉

标题使用任务语义“设置扣减批次与库位”，物品名称、SKU、单位属于上下文，不反转标题层级。抽屉维护单条草稿，点击“应用”才写回主列表；取消丢弃草稿。

### 两种互斥模式

使用明确单选控件，不使用普通 tab：

| 模式 | 文案 | 表单与解释 |
| --- | --- | --- |
| `fifo`（默认） | 按先进先出分配 | 可选选择库位；审批时从该库位或全部库存按 FIFO 扣减。 |
| `specific_batch` | 指定批次 | 先选可用批次，可选库位自动跟随批次并锁定；显示批次号、剩余数量、有效期和库位。 |

- 模式切换不立即删除已选批次；切回指定批次时保留上次候选，直到用户替换或清空。
- 切到 FIFO 后，`batch_id` 不提交；若用户保留库位，提交该 `location_id` 以限制 FIFO 范围。
- 批次候选来自 `GET /api/items/{id}/batches` 的服务端分页；抽屉内使用尾部加载和单独错误重试，不能一次假设所有批次已读取。
- 批次余额仅作说明，不做“可提交”承诺；数量超过快照余额用警告提示“审批时仍会校验”，不替代服务端最终判断。
- 若候选请求 `403`，显示无权读取库存批次；网络失败显示重试；候选为空时 FIFO 仍可选择，但提交结果可能因库存不足被审批拒绝。

## 草稿、校验和提交

沿用入库草稿持久化的版本化模式，但单独定义 `OutboundDraft`，不得复用入库 `submission_mode`、模板字段、图片 IndexedDB 或价格字段。

```ts
interface OutboundDraftLine {
  lineId: string
  item: ItemOptionResponse
  quantity: string
  allocationMode: 'fifo' | 'specific_batch'
  batchId: number | null
  locationId: number | null
}
```

- 草稿保存 destination、notes、行、数量和分配模式；批次/库位恢复后必须重新读取候选或安全降级，不能盲目保证仍有效。
- 路由离开、刷新或关闭浏览器时，存在未提交草稿提示原生离开保护；提交成功或确认清空后删除草稿。
- 点击“提交审核”前验证 destination、至少一条明细、每条正数数量、`specific_batch` 存在批次 ID。校验使用现有红框、自动聚焦和 Notice，不插入可见错误行改变布局。
- 提交前打开确认 Dialog：去向、明细数、各单位数量摘要，并明确“提交后进入待审批，库存不会立即扣减”。操作为“返回检查”“确认提交审核”。
- `POST /api/outbound` 成功：清空草稿，回到步骤 1，Notice 显示单号和待审批语义；有读取权限时提供跳转 `/outbound/orders` 的动作。
- 结构化 API 错误按 `line_index` 映射到行；库存不足不是创建阶段常规错误，若服务端未来提前校验也必须保留其文案，不能改成成功提示。

## 异步与响应式

- 首次物品目录、批次候选和提交均使用 `useStablePendingIndicator` 的 200ms 延迟、350ms 最短展示；不延迟请求本身。
- 物品搜索、批次切换和抽屉关闭取消旧请求，取消不显示错误。
- 已选明细和填写内容在后台刷新目录时不清空；批次候选错误只影响当前抽屉。
- 桌面步骤操作区保持位置稳定；移动端固定底部操作区须为安全区和最后一行预留空间。
- 不创建第三套平板业务逻辑；窄宽度仅改变列数、换行和抽屉呈现。

## 实施顺序与验收

1. 复核 `items/options` 和批次读取权限是否能被仅有出库创建权限的用户使用；如不能，core 必须在不授予物品管理能力的前提下补齐任务读取边界。
2. 建立出库草稿模型、持久化、选品复用与批次候选会话。
3. 实现两步工作台、抽屉、确认提交和结构化错误定位。
4. 验收 pending 创建、FIFO、指定批次、跨库位 FIFO、批次无余额、网络失败、权限变化、草稿恢复、离开保护及混合单位。

完成门槛：`pnpm build`、相关 core 定向测试、`git diff --check` 通过；在 1440×900、约 768px、390×844 的真实浏览器中检查无横向溢出、抽屉焦点恢复和控制台新增错误/警告。

## 明确非目标

- 不在新建页直接审批、拒绝、扣库存、锁库存或修改批次余额。
- 不支持一个明细拆分多个指定批次，除非 core 增加对应原子契约。
- 不把入库价格、模板属性、图片附件、直接入库按钮或入库来源复制到出库工作台。
- 不以当前批次列表或前端数量判断替代审批时库存充足性校验。
