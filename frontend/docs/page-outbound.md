# 新建出库页面

本文记录 `/outbound` 当前单物品串行配置工作台的业务边界、交互状态和验收要求。
页面创建出库草稿并通过 HTTP 提交；它不拥有审批工作台、库存事务或批次扣减算法。

## 页面目标

- 让用户选择一个物品后立即完成该物品的数量和扣减方式。
- 已完成明细留在复核列表中；未完成明细会锁定“添加物品”。
- 物品选择、明细编辑、草稿恢复和提交确认在桌面与移动端共享同一份状态。
- 当前批次余额和预计成本只是读取快照，不承诺审批时库存一定充足。

通用视觉、按钮、图标、Dialog、稳定等待和安全区规则分别以 `visual-style.md`、
`ui-design-guidelines.md`、`ui-consistency-checklist.md`、`async-state-transitions.md` 和
`mobile-interactions.md` 为准。

## 当前信息架构

```text
页面标题 + 草稿摘要
└─ 出库单信息与明细工作区
   ├─ 去向、备注
   ├─ 添加物品 -> ItemSelectionDialog
   │              -> 选择一项后关闭选择层
   │              -> 打开“配置出库明细”Dialog
   └─ 明细复核列表
      ├─ 物品身份
      ├─ 数量、FIFO/指定批次、库位和成本摘要
      └─ 编辑图标 / 移除图标
```

选择弹窗和明细编辑弹窗严格串行：选择层的离场动画完成后才打开编辑层；
“完成并继续添加”也会等待当前编辑层离场后再打开选择层，任意时刻只保留一个业务浮层。

## 物品选择与明细状态

`ItemSelectionDialog` 复用 `SearchField`、服务端分页和触底追加：

| 物品状态 | 目录按钮 | 结果 |
| --- | --- | --- |
| 尚未加入 | 添加并配置 | 创建一条默认草稿并打开明细配置 |
| 已加入且待补充 | 继续配置 | 打开原明细，不创建重复行 |
| 已加入且可提交 | 继续配置 | 仍打开原明细进行复核 |

目录不承担移除语义；移除只在复核列表中提供统一垃圾桶线性图标。选择、继续配置和移除
均属于本地草稿操作，不使用业务成功色 Notice。

明细编辑器关闭、Escape 或 Android 返回时保留当前输入。只有用户明确移除明细或清空草稿，
才会删除对应本地数据。

## 出库明细编辑器

当前编辑器由页面挂载的宽 `ModalDialog` 承载，标题使用任务语义“配置出库明细”，物品名、
SKU 和单位仅作为上下文。编辑内容包括：

1. 本次出库数量（正数）。
2. 扣减方式：按先进先出分配或指定批次。
3. FIFO 模式的可选库位范围。
4. 指定批次模式的分页批次候选、库位、剩余数量、有效期和单位成本。
5. 当前批次快照的预计成本提示。

FIFO/指定批次使用项目统一的线性单选样式，库位限制使用 `SelectControl`；不使用浏览器原生
蓝色下拉或单选外观。

“暂存并关闭”为次级按钮，“完成并继续添加”为主按钮。完成会先校验当前行，失败时保留
编辑层并聚焦数量或第一个阻塞字段。

批次候选通过 `GET /api/items/{id}/batches` 分页加载；读取失败只影响当前编辑层，提供重试，
不会清空其它明细。成本快照可以在数量有效后后台读取，失败时显示“实际出库时重新校验”的
中性说明。

## 复核列表与列宽

桌面列表使用三段式连续行：

```text
物品身份区（弹性较大） | 数量/分配摘要区（弹性） | 编辑、移除操作区（固定）
```

操作区只放两个 34px 项目标准图标按钮，编辑使用线性铅笔，移除使用线性垃圾桶；两者都必须
提供 `title` 和 `aria-label`。桌面宽度充足时不得产生页面或列表横向滚动；参数摘要允许截断，
但操作区不能被压缩。

移动端将每条明细重排为身份、摘要、操作三段，不缩放桌面表格，也不制造页面级横向滚动。
固定底部提交栏消费安全区，并由工作区底部余量保证最后一条明细可滚到操作栏上方。

## 草稿、校验和提交

- 草稿键保持 `winestock.outbound-draft.v1`，不持久化当前打开的 Dialog。
- 恢复草稿后回到复核列表；不会自动打开任意明细。
- 提交前验证去向、至少一条明细、正数数量以及指定批次 ID。
- FIFO 模式清除 `batch_id`；指定批次模式保留批次及其库位约束。
- 提交确认层明确库存不会因普通待审批提交立即扣减的语义（若当前权限策略触发直接生效，须按下节说明）。

当前页面保留既有实现：当账号具有直接审批能力时，创建成功后会继续调用审批接口并显示直接出库结果；
页面文档和 core 创建接口仍描述 pending-only。该差异是待产品决策的既有行为，本次交互整改不改变它。

## 权限与 HTTP 边界

页面只调用现有 HTTP 契约：

- `GET /api/items/options`：物品选择；
- `GET /api/items/{id}/batches`：批次候选与成本快照；
- `GET /api/locations`：FIFO 库位限制；
- `POST /api/outbound`：创建出库单；
- 具备对应能力时调用审批接口完成既有直接生效路径。

前端权限只用于隐藏入口，core 仍对每次读取和写入实时授权。Shell Bridge、运行模式、API 地址和
库存事务不属于本页面。

## 响应式与无障碍验收

至少在以下视口验证：

- 桌面 `1440×900`：操作区固定、摘要列无溢出、`scrollWidth === clientWidth`；
- 断点附近约 `768px`：行重排后长名称和按钮仍可见；
- 移动 `390×844`：Dialog/固定底栏消费安全区，最后一条明细可滚动到栏上方。

还需验证选择层与编辑层不重叠、关闭后焦点返回触发按钮、Escape/Android 返回只关闭最上层、
字段错误不改变布局、控制台无新增 error/warning，以及 `pnpm build` 和 `git diff --check` 通过。
