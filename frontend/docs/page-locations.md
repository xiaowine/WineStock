# 库位管理页面实施设计

本文是 `frontend/` 库位管理页面的实施设计，定义页面职责、信息架构、交互状态、前端模块拆分和验收标准。
它不改变 `core` 的库位业务语义，也不把库位复制成物品属性。

当前实现状态：第一阶段库位主数据页面已经落地，包括真实 `/locations` 路由、库位分组树、分组 CRUD、库位搜索、库位 CRUD、移动端分组 Drawer、权限控制和入库页面统一 DTO。库存位置详情与整批次移库仍等待按库位查询当前批次的后端契约。

## 设计结论

库位是库存批次和出入库流转的位置属性，不属于物品主数据。页面需要同时管理两层对象：

- **库位分组**：用于组织仓库、区域、楼层或库区的层级树，可拥有子分组和直接库位。
- **库位**：真正被入库明细、库存批次和移库请求引用的可用存放位置。

页面的第一阶段目标是完成“库位主数据维护 + 入库可选库位的一致来源”。库存数量和批次操作属于第二阶段，不能把不存在于当前 API 响应中的库存汇总伪造到库位列表中。

当前后端已经提供：

- `GET /api/location-groups/tree`：分组树，节点包含直接子分组和直接库位。
- `POST/PUT/DELETE /api/location-groups`：分组创建、更新、软删除。
- `GET /api/locations`：按分组和搜索词查询库位。
- `POST/PUT/DELETE /api/locations`：库位创建、更新、软删除。
- `POST /api/location-transfers`：整批次移库，首版不支持部分数量移库。

详细契约见 [`core/docs/business-api/locations.md`](../../core/docs/business-api/locations.md)。

## 页面边界

### 页面负责

- 展示库位分组树和库位列表。
- 创建、编辑、移动和软删除库位分组。
- 创建、编辑和软删除库位。
- 选择分组后筛选库位，支持按名称或备注搜索。
- 在后端补齐库存查询契约后，展示库位下的批次并发起整批次移库。
- 根据 `stock.location.read` 和 `stock.location.manage` 控制读取与操作入口。

### 页面不负责

- 不在库位页面编辑物品名称、SKU、分类、单位或物品属性。
- 不把库位保存到物品主数据；入库单明细仍保存实际 `location_id`。
- 不直接修改库存数量；库存变化必须由入库、出库、盘点或移库服务产生流水。
- 不允许前端绕过分组循环、编码唯一、在用库位不可删除等服务端校验。
- 不在没有 API 数据时显示“当前库存数量”“库存价值”或批次数量。

## 路由与导航

### 路由

- 路径：`/locations`
- 路由名：`locations`
- 页面标题：`库位管理`
- 布局：`AppShell`
- 读取权限：`stock.location.read`
- 管理权限：`stock.location.manage`

当前路由已经接入真实 `LocationsPage`，见 [`frontend/docs/routes.md`](routes.md)。后续库存位置详情继续复用现有路由名和权限，不新增第二个库位入口。

### 入口呈现

- 桌面侧栏管理分组显示“库位管理”。
- 移动 Drawer 使用同一导航元数据，不维护第二套名称。
- 没有 `stock.location.read` 时由路由守卫阻止进入；没有 `stock.location.manage` 时保留页面读取能力并隐藏新增、编辑、删除和移库入口。
- `stock.location.manage` 不能替代 `stock.location.read`；服务端仍执行最终授权。

## 页面信息架构

### 桌面布局

页面使用现有列表管理骨架，不新建独立视觉体系：

```text
页面标题：库位管理                         [刷新]
库位分组与库位主数据说明                    [新建分组] [新建库位]
┌──────────────────────────────────────────────────────────┐
│ 库位分组树             │ 库位列表工作区                   │
│                       │ 面包屑 / 当前分组                │
│ 全部库位              │ 搜索名称或备注    [刷新] [新增]  │
│ 默认库区              │ 库位表格                         │
│   默认库位            │ 列表尾部 / 数量                   │
└──────────────────────────────────────────────────────────┘
```

- 左侧树是工作区的一列，不做卡片套卡片；建议宽度 `224px`，沿用应用壳导航密度。
- 右侧列表占满剩余宽度；列表为空时仍保留工具栏和当前分组上下文。
- 页面标题只识别业务范围；搜索、新增、刷新和筛选全部放在列表工具栏。
- “全部库位”是前端虚拟筛选节点，不调用额外 API；选择后请求不带 `group_id`。

### 移动布局

- 移动 Shell 已显示“库位管理”时，页面内部不重复显示同名大标题。
- 分组树转为左侧 Drawer 或页面级 Sheet；关闭后保留当前列表筛选和滚动位置。
- 列表改为连续单列库位项目，不压缩桌面表格，也不产生页面级横向滚动。
- 顶部工具栏保留搜索、分组入口、刷新和新增；次要排序或批量动作进入页面 Sheet。
- 新建和编辑仍使用 Dialog；整批次移库使用底部 Sheet 或全屏面板。

## 分组树设计

### 节点内容

每个树节点显示：

- 分组名称。
- 直接库位数量（由树节点的 `locations.length` 计算）。
- 展开/收起按钮；有子分组或直接库位时才显示可展开状态。
- 当前选中态和键盘焦点态。

树节点不显示库存数量，因为当前 `LocationResponse` 没有库存汇总字段。

### 树交互

- 首次加载自动展开根节点和服务端默认库区，其他节点保持收起。
- 点击节点只改变右侧列表筛选，不触发重复树请求。
- 展开/收起只改变本地 `expandedGroupIds`，不改变当前选中分组。
- 根分组计为第 1 层，最多 10 层；第 10 层隐藏或禁用新建子分组入口。
- 键盘支持 Tab 聚焦、Enter/Space 选择节点、方向键展开/收起和上下移动焦点。
- 树加载期间显示稳定骨架；失败时保留上一次成功树并提供“重试”，不清空右侧列表。
- 分组新增或移动成功后展开目标父级，并选中新分组；删除成功后选择其父级或“全部库位”。

### 分组操作

#### 新建分组 Dialog

字段顺序：

1. `分组名称`：必填，最多 128 个字符；提示同一父分组下不能重名。
2. `上级分组`：可选；默认使用当前选中分组，支持选择“根分组”。
3. `排序`：默认 0；首版可以放在“更多设置”中，不把数值排序误认为拖拽排序。

操作：

- 取消：丢弃草稿，不请求。
- 创建：调用 `POST /api/location-groups`，成功关闭并刷新树。
- 保存期间锁定字段和提交按钮，Dialog 标题与底部操作区保持稳定。

#### 编辑分组

- 可修改名称、上级分组和排序。
- 上级分组选项排除当前节点及其全部子孙，避免提交必然形成的循环。
- 上级分组选项同时排除会使当前分组整个子树超过 10 层的目标位置。
- 服务端返回 `location_group_cycle` 时定位到上级分组字段，不只显示全局错误。
- 服务端返回 `location_group_depth_exceeded` 时定位到上级分组字段并提示最多 10 层。
- 移动分组会影响后续树和库位筛选展示，但不改写历史入库单或库存流水。

#### 删除分组

- 删除前显示确认 Dialog，明确“仍有子分组或有效库位时不能删除”。
- `409 location_group_in_use` 时保留 Dialog 上下文，提示先移动或删除子项。
- 不提供强制删除，不级联删除库位。

## 库位列表设计

### 工具栏

工具栏从左到右：

1. 当前分组面包屑或“全部库位”。
2. 搜索框：搜索库位名称或备注，使用现有 `SearchField`，防抖后提交查询。
3. 结果数量：只切换数字，不推动按钮位置。
4. 刷新按钮：保留旧结果，显示局部刷新状态。
5. 新建库位：仅 `stock.location.manage` 显示。

搜索、切换分组和刷新必须取消旧请求；请求失败时保留旧列表并在工具栏或 Notice 提示失败原因。

### 桌面表格

桌面列表遵循项目三段式目录：左侧固定身份区显示库位名称和所属分组，中间弹性参数区显示备注，右侧固定判断与操作区显示排序、更新时间和管理按钮；三段表头、数据行和横向滚动保持同一列宽与固定边界。

推荐列顺序：

| 列 | 内容 | 规则 |
|---|---|---|
| 库位名称 | `name` | 全局唯一；超长省略，完整内容放 `title` |
| 所属分组 | `group_name` | 在“全部库位”视图显示；当前分组视图可缩减 |
| 备注 | `notes` | 无内容显示占位符，超长省略并保留完整 `title` |
| 排序 | `sort_order` | 默认隐藏或作为次要信息，不放大视觉权重 |
| 更新时间 | `updated_at` | 使用本地化日期时间，必要时显示相对时间 |
| 操作 | 编辑、删除、移库 | 由权限和后端库存能力决定 |

当前 API 只能直接返回上述主数据字段。库存数量、库存价值、批次和当前库位占用需要额外库存查询接口，不能从库位树或物品筛选结果猜测。

### 移动库位项目

每个项目显示：

- 第一行：库位名称。
- 第二行：所属分组、备注和更新时间。
- 右侧：更多操作按钮；按钮必须有 `title` 与 `aria-label`。
- 不把排序值、内部 ID 或空库存摘要放在首屏。

## 库位 Dialog

### 新建/编辑库位

字段顺序：

1. `所属分组`：必填选择框，默认当前分组；不能选择已删除分组。
2. `库位名称`：必填，最多 128 个字符，未删除库位内全局唯一。
3. `备注`：可选，最多 1024 个字符，用于记录位置或使用限制。
4. `排序`：默认 0，作为同组展示顺序。

交互规则：

- 新建和编辑复用同一个 Dialog 组件，只改变模式、标题和初始值。
- `location_name_taken` 映射到名称字段错误。
- `location_group_not_found` 映射到分组字段错误并刷新分组树。
- 成功后关闭 Dialog、刷新当前列表和树节点数量；不重置用户当前搜索条件。
- 删除库位前显示其编码和名称；`location_in_use` 时说明仍有当前库存批次引用，要求先移库或清空库存。
- 删除是软删除，历史入库和出库单仍保留原库位引用。

## 库存与整批次移库

### 当前 API 缺口

`POST /api/location-transfers` 需要 `batch_id`、原库位和目标库位，但当前库位接口没有“按库位列出当前批次”的查询接口。
因此第一阶段不能在库位列表中直接实现可靠的“移库”按钮，也不能通过 `GET /api/items` 的目录筛选拼出批次选择器。

实现库存操作前，建议补充以下只读契约之一：

```text
GET /api/locations/{id}/inventory
```

或：

```text
GET /api/location-inventory?location_id=<id>
```

响应至少包含：

- 库位 ID、编码和名称。
- 物品 ID、名称、SKU、单位。
- 批次 ID、批次号、有效期、剩余数量、单位成本和库存价值。
- 当前库存状态和最近更新时间。

### 库位库存详情面板

补齐查询契约后，点击库位进入右侧详情面板或移动全屏面板：

- 顶部显示库位名称、所属分组、备注和当前批次数量。
- 中部按物品分组展示批次；默认按有效期、入库时间和批次 ID 稳定排序。
- 每个批次显示剩余数量、单位成本、有效期和库存状态。
- 只提供“整批次移库”，明确显示本次将移动全部剩余数量。
- 目标库位不能等于当前库位；目标库位必须来自未删除库位。
- 提交前显示原库位、目标库位、批次和数量确认。
- 成功后刷新源库位和目标库位详情，并显示移库流水成功 Notice。
- 不在前端提供部分数量输入，除非后端新增部分移库契约。

## 前端模块拆分

建议新增以下文件，沿用现有页面和组件所有权：

```text
frontend/src/
  api/locations.ts
  pages/LocationsPage.vue
  pages/LocationsPage.scss
  components/locations/
    LocationGroupTree.vue
    LocationGroupDialog.vue
    LocationDialog.vue
    LocationTransferDialog.vue       # 库存查询契约补齐后加入
    LocationInventoryPanel.vue       # 库存查询契约补齐后加入
  composables/
    useLocationTree.ts
    useLocationList.ts
```

### `api/locations.ts`

集中定义并导出：

- `LocationGroupResponse`
- `LocationGroupTreeNode`
- `LocationResponse`
- `LocationTransferCreateRequest`
- `LocationTransferResponse`
- 分组树、分组 CRUD、库位查询和库位 CRUD 请求函数。

`frontend/src/api/inbound.ts` 不再重复定义 `LocationResponse`，改为从 `api/locations.ts` 导出，入库页面继续只依赖库位查询函数。

### `LocationsPage.vue`

页面负责：

- 会话权限读取。
- 树和列表请求编排。
- 当前分组、展开节点、搜索词和 Dialog 状态。
- 刷新、创建、编辑、删除和错误 Notice。
- 不直接拼接 HTTP URL，不复制表单校验和树递归渲染。

### `useLocationTree.ts`

负责：

- 树加载、请求取消、稳定等待状态和错误恢复。
- `selectedGroupId`、`expandedGroupIds` 和节点查找。
- 创建、移动、删除后局部更新或重新加载树。

### `useLocationList.ts`

负责：

- `group_id`、搜索词和结果列表。
- 搜索防抖、取消旧请求、刷新保留旧结果。
- 空状态、零结果、请求失败和刷新状态。

## 状态与错误矩阵

| 状态 | 页面呈现 | 可执行操作 |
|---|---|---|
| 树初始加载 | 左侧骨架，右侧中性占位 | 不显示误导性空数据 |
| 树加载失败 | 树区域错误 + 重试 | 保留旧列表 |
| 无分组 | 空状态说明 + 新建分组 | 管理员可直接新建根分组 |
| 选中空分组 | 保留工具栏，列表空状态 | 管理员可新建库位 |
| 搜索无结果 | “没有匹配库位” | 清除搜索 |
| 列表刷新 | 保留旧列表，局部弱化 | 仍可浏览和切换分组 |
| 创建/编辑保存 | Dialog 内稳定 busy | 禁止重复提交 |
| 名称冲突 | 字段附近错误 | 保留用户输入 |
| 删除被占用 | 确认层转为说明 | 引导移库或清空库存 |
| 移库失败 | 保留详情面板和批次上下文 | 重试，不清空当前数据 |

遵守 [`async-state-transitions.md`](async-state-transitions.md) 的 `200ms` 延迟显示和 `350ms` 最短展示规则；错误不等待视觉延迟。

## 响应式与可访问性

- 桌面 `1440 × 900`：树、工具栏和列表均可见，页面不出现无意义横向滚动。
- 断点附近：树宽度保持可用，列表压缩名称列和次要列，不压缩操作按钮。
- 移动 `390 × 844`：分组树进入 Drawer/Sheet，库位列表为单列项目，Dialog 转底部面板。
- 树使用 `role="tree"`、`role="treeitem"`、`aria-expanded` 和 `aria-selected`。
- 列表操作按钮必须有可访问名称；删除和移库必须有明确确认语义。
- 搜索输入、树选择和列表刷新不得抢夺焦点；Dialog 关闭后焦点返回触发按钮。
- `aria-busy` 只表示当前区域正在请求，不得因为刷新移除仍可用的旧列表。
- 长编码、长名称、重复分组名和大量子节点必须检查省略、滚动和键盘可达性。

## 实施顺序

### 阶段一：库位主数据页面

已完成：

1. 新增 `api/locations.ts`，统一 Location DTO。
2. 将 `/locations` 从占位页替换为真实 `LocationsPage`。
3. 实现分组树、分组 CRUD、库位列表和库位 CRUD。
4. 将入库页面改为复用新的库位 API 模块。

仍需浏览器联调验证新增库位后入库选择器能够读取同一服务端数据。

### 阶段二：库存位置查看

1. 补充按库位查询当前批次的只读 API。
2. 增加库位库存详情面板和批次列表。
3. 验证物品库存 Dialog、物品目录和库位详情展示同一批次余额。

### 阶段三：整批次移库

1. 增加移库 Dialog 和目标库位选择。
2. 调用 `POST /api/location-transfers`，只支持整批次移动。
3. 刷新源/目标库位和相关物品库存详情。
4. 验证移库流水、权限、原库位确认和并发位置变化错误。

## 完成门槛

- 页面只使用 `stock.location.read` / `stock.location.manage` 对应能力，不把前端隐藏当作授权。
- 分组树、列表、Dialog 和移动端 Sheet 复用已有页面骨架、表单控件、Dialog、Notice 和异步状态模式。
- 不新增第二套库位 DTO；入库页面与库位页面使用同一 `api/locations.ts`。
- 库位删除、分组删除、分组移动和库位名称冲突均有字段或上下文明确的错误呈现。
- 分组创建和整棵子树移动均不得超过 10 层，前端候选限制不能替代后端强校验。
- 当前 API 没有库存汇总时，页面不展示猜测的库存数字；移库功能必须等待批次查询契约。
- 覆盖桌面、断点附近和移动视口的树、列表、Dialog、空状态、错误状态和长文本。
- 验证 `pnpm build`、`git diff --check`、浏览器控制台和页面横向溢出。
