# 新建入库页面

本文记录 `/inbound` 当前单物品串行配置工作台的业务边界、交互状态和视觉验收要求。
页面只创建入库草稿并通过 HTTP 提交，不拥有入库审批工作台或库存事务 API。

## 当前流程

```text
入库单信息与明细
├─ 来源、备注
├─ 选择物品 -> ItemSelectionDialog
│              -> 选择一项后关闭选择层
│              -> 打开“入库物品明细”Dialog
└─ 明细复核列表
   ├─ 物品身份
   ├─ 数量、单价、库位与批次摘要
   └─ 编辑图标 / 移除图标
```

选择层和明细 Dialog 严格串行。选择层离场动画完成后才打开 Dialog；“完成并继续添加”
也会先完成当前 Dialog 的离场，再把焦点交给下一次选择。存在未完成明细时，“选择物品”仍可
点击，但不会打开选择层，而是重新打开第一条未完成明细并通过 Warning Notice 说明原因，避免
用户在多个明细之间来回补录，也避免禁用按钮造成操作无反馈。

## 扫码添加（立创料袋）

“扫码添加”与“选择物品”并排放置，打开通用 `BarcodeScanDialog` 识别立创料袋二维码；
识别、忽略与格式规则见 [`../../docs/implementation-notes/lcsc-bag-scanning.md`](../../docs/implementation-notes/lcsc-bag-scanning.md)。入库域行为：

- 命中（C 号按物品编号精确匹配）：关闭扫码进入该物品明细，袋内数量预填且可改；
  明细保存/暂存/取消后自动重开扫码，直到用户主动关闭扫码 Dialog（串行会话）；
- 重复扫到已在草稿的物品：不新增，Notice 提示并直接打开该行明细；
- 未命中：转入快速新建 Dialog，自动以 C 号执行立创资料查询预填；创建完成回到明细并应用数量；
- 料袋含订单号且整单来源为空时，明细 Dialog 顶部提示条询问是否以「立创 SO…」填入来源：
  「忽略」只挡同一订单号，「本单不再提示」随草稿持久化，来源已填则完全静默；
- 未完成明细存在时，“扫码添加”与“选择物品”一致：先回到未完成明细，完成后自动回到扫码。

## 导入订单（立创订单导出表格）

“导入订单”从入库域的导入入口打开 `LcscOrderImportDialog`，选择立创商城
「订单详情」导出的 `.xls` 文件。表格只取订单编号、商品编号（C 号）、订购数量与商品单价
四个字段，其余信息一律以 C 号经既有立创查询补齐；解析纯逻辑归 `src/lcsc/orderExport.ts`
（node 单测覆盖），SheetJS 仅在该 Dialog 内按需动态加载。

- 预览表逐行给出状态：已匹配（按物品编号精确匹配）、未命中、已在草稿/重复/不发货等跳过原因；
- 未命中行提供行内“新建”，复用 `ItemCreateDialog` 并自动以该 C 号查询预填，创建成功即转为已匹配；
- 未命中/创建失败行带勾选框（默认全选，表头全选/半选联动），支持按类别分批创建：
  勾选一批（如全部电阻）→ 用一个模板创建，再勾另一批（连接器）→ 用另一个模板创建；
- 存在未命中行时操作区（modal-actions）左侧独立提供“创建选中的 N 个物品”（`margin-right: auto` 左置惯例，与右侧“取消/加入明细”决策流分开；N=勾选数，为 0 时禁用）：先弹批量创建选项（属性模板预选全站默认、
  分类默认不指定、计量单位默认“个”，同会话记住上次选择），确认后由
  `components/items/useBatchLcscItemCreation` 串行逐项查立创资料、拉商品图并创建**勾选的**物品
  （商城无受控图片地址或选定图片读取失败时生成带客编的“暂无商品图片”PNG；串行天然限制上游请求频率）；行状态经
  “创建中…”转为已匹配，失败行显示原因并提供
  行内“重试”与“手动新建”，单项失败不阻塞后续；`sku_taken` 视为已存在自动匹配。
  批量执行期间该按钮显示“正在创建 i/N…”并连同导入确认一起禁用；
  关闭 Dialog 中止批量，创建中的行回到未命中。
  设计见 `docs/implementation-notes/lcsc-batch-item-creation-and-erp-backup-import.md`；
- 确认导入把已匹配行批量加入草稿，数量与单价预填，库位留待逐条补齐（沿用未完成明细串行规则）；
- 识别到订单号且整单来源为空时提供勾选，把来源填为「立创 SO…」；来源已填则不出现勾选；
- 匹配查询失败的行计入跳过并可“重试匹配”，不阻塞其余行导入。

## 导入备份（第三方 ERP 备份）

“导入备份”与“导入订单”归入同一个导入入口（仅入库域、需物品管理权限），打开
`ErpBackupImportDialog` 选择
开源「LCSC Android ERP」导出的 `.xlsx` 备份，按备份库存生成一张期初入库草稿。解析纯逻辑归
`src/erp/backupImport.ts`（四表按表头解析并 join，node 单测覆盖），文件读取入口
`src/erp/backupImportFile.ts` 动态加载 SheetJS。设计见
`docs/implementation-notes/erp-backup-import-implementation.md`。

- 预览三段：库位（恢复备份中的全部有效库位，含无库存引用的空库位，并标注已存在/待新建）、
  器件（真 C 码，匹配/待创建，带勾选批量创建，
  复用 `useBatchLcscItemCreation`）、跳过（C0 手工器件灰显不导入，含提示文案）；
- 确认导入执行：缺失库位在首个根分组下新建 → 未匹配器件批量创建 → 按已匹配器件组装期初
  库存行回传装配；同物品跨多库位展开为多条明细，库位已定的行不走预填；
- 一键创建期间按钮使用等待指针；导入条件不满足时，导入按钮保持普通禁止态，不伪装成加载中；
- 装配预填来源「备份导入 <文件名>」、备注（导出版本 + 跳过手工器件数），单价按 0 记；
- best-effort 重复导入防护：已存在同文件名来源的入库单时红字警告（不阻止，用户决定）。

## 库位分层预填与批量设置

新行（手动添加/扫码/订单导入/新建后加入）的库位按三层预填，预填等同手选可随时改
（设计见 `docs/implementation-notes/inbound-location-prefill.md`）：

1. **同编号历史库位**：仅严格同一物品——该物品当前有库存且只分布在一个库位时预填该库位；
   多库位或无库存不猜，不做任何相似物品推断。装配行时异步查 `GET /api/items/{id}/inventory`，
   查询失败静默回落，用户已手选的行不覆盖。
2. **全局默认库位**：库位页星标设置的 `is_default` 库位（无历史时回落）。
3. **待选择**：以上皆无时保持空，由行编辑器或批量设置补齐。

存在"待选择"明细时工作台操作区出现"批量设置库位"：选择一个库位一次应用到全部未选库位的
明细（已设库位的行不覆盖）；恢复的历史草稿行不重新预填。

## 明细编辑器

`InboundLineEditor.vue` 是单条明细的唯一编辑入口，字段顺序为：

1. 数量、单价、入库库位；
2. 批次号、有效期。

来源和备注属于单据级字段，只在工作台填写一次。关闭、Escape 或 Android 返回只关闭当前
编辑器并保留草稿；删除必须通过复核列表的垃圾桶图标完成。完成明细不调用创建接口，页面级
“直接入库/提交审核”才会提交整张单据。

编辑器使用项目通用 `ModalDialog`：桌面为工作区宽 Dialog，移动端沿用通用底部面板；标题固定为
“入库物品明细”，物品身份位于 context，操作位于标准 actions。遮罩、关闭动画、焦点约束与返回
处理均由通用组件负责，不再维护入库专用侧栏。

字段未完成时，复核列表只显示实际阻塞原因，不常驻显示“已配置”标签。

## 复核列表与视觉规则

宽桌面将稳定字段展平为固定六列：

```text
物品 25% | 数量 10% | 单价 / 小计 14% | 库位 16% | 批次 自适应 | 操作 90px
```

操作列只放两个 34px 的项目标准 `icon-button`：线性铅笔和线性垃圾桶；按钮提供 `title`
与 `aria-label`，不会因为摘要长文本而被压缩。数量和库位保持单行，单价/小计与批次最多
两行；缺失或失效状态直接由对应字段使用警告或错误色表达，不在操作列重复显示状态文案。长物品名、
编号和库位名均省略显示，不能撑开页面。

窄桌面使用同一组单元格重排为三行信息网格，移动端再按字段标签纵向排列；两者都沿用项目中性
浅色表面、分隔线、系统字体和克制圆角，不增加重复业务结构，也不产生横向滚动。窄桌面明细区占用
工作区剩余高度并独立纵向滚动，移动端回到页面自然滚动。固定提交栏消费
`--safe-area-bottom`，工作区底部余量保证最后一条明细可滚动到操作栏上方。

桌面与移动端统一使用同一组紧凑操作行：依次为导入图标、扫码图标和末尾弹性宽度的
“选择物品”；导入图标展开“导入订单 / 导入备份”，批量设置库位仅在需要时独占下一行。
移动端由 Shell 显示页面标题，解除草稿工作区外框；操作区和单据头保留分隔关系，明细结果背景
延伸到页面内侧边缘，明细卡保持标准内容缩进。明细行和移动卡均可点击、Enter 或 Space 打开编辑器，
图片预览与编辑/移除按钮阻止冒泡并保持独立动作。

通用视觉、按钮、图标、Dialog、异步稳定等待和安全区规则分别以 `visual-style.md`、
`ui-design-guidelines.md`、`ui-consistency-checklist.md`、`async-state-transitions.md` 和
`mobile-interactions.md` 为准。

## 可复制字段

工作台明细编辑区选中物品的名称与编号经 `v-copyable` 提供点击复制（无常驻图标）；
入库单详情弹窗的可复制字段见 [`page-inbound-orders.md`](page-inbound-orders.md)。
规范见 [`ui-consistency-checklist.md`](ui-consistency-checklist.md)。

## 草稿、校验和权限

- 草稿键为 `winestock.inbound-draft.v6`，旧版本草稿恢复时直接清除；不持久化活动选择层、Dialog 或焦点。
- 恢复草稿后只恢复复核列表；不会自动打开任意明细。
- 入库数量、单价、库位字段由前端提供即时定位，core 仍执行最终校验。
- 页面按现有权限显示直接入库或提交审核；不改变 HTTP 契约、Shell Bridge 或运行模式。
- 选择弹窗中的新建物品复用 `ItemCreateDialog`，创建成功后进入同一条明细配置流程。

## 验收

至少检查 `1440×900`、约 `768px` 和 `390×844`：

- 选择层与明细 Dialog 不重叠，关闭后焦点回到触发按钮或搜索框；
- 桌面列宽无横向溢出，操作按钮保持 34px；
- 移动端导入菜单、固定底栏、Dialog 标题和关闭按钮避让安全区；
- 长名称、长编号、字段错误和提交确认不改变布局；
- Android 返回只关闭最上层活动编辑器，下一次返回才交给路由；
- 控制台无新增 error/warning，`pnpm build` 与 `git diff --check` 通过。
