# 新建入库页面

本文记录 `/inbound` 当前单物品串行配置工作台的业务边界、交互状态和视觉验收要求。
页面只创建入库草稿并通过 HTTP 提交，不拥有入库审批工作台、库存事务或模板管理 API。

## 当前流程

```text
入库单信息与明细
├─ 来源、备注
├─ 添加物品 -> ItemSelectionDialog
│              -> 选择一项后关闭选择层
│              -> 打开“配置入库明细”Drawer
└─ 明细复核列表
   ├─ 物品身份
   ├─ 数量、单价、库位、模板与批次摘要
   └─ 编辑图标 / 移除图标
```

选择层和明细 Drawer 严格串行。选择层离场动画完成后才打开 Drawer；“完成并继续添加”
也会先完成当前 Drawer 的离场，再把焦点交给下一次选择。未完成明细会锁定“添加物品”，
避免用户在多个明细之间来回补录。

## 明细编辑器

`InboundLineEditor.vue` 是单条明细的唯一编辑入口，字段顺序为：

1. 数量、单价、入库库位；
2. 批次号、有效期；
3. 入库模板、模板动态字段和图片属性。

来源和备注属于单据级字段，只在工作台填写一次。关闭、Escape 或 Android 返回只关闭当前
编辑器并保留草稿；删除必须通过复核列表的垃圾桶图标完成。完成明细不调用创建接口，页面级
“直接入库/提交审核”才会提交整张单据。

推荐模板、模板详情和图片草稿继续使用每条明细的请求版本、取消控制器和 IndexedDB 清理规则。
模板失效、候选读取失败或字段未完成时，复核列表只显示实际阻塞原因，不常驻显示“已配置”标签。

## 复核列表与视觉规则

桌面端使用固定四列：

```text
物品身份 30% | 本次入库 23% | 模板与批次 34% | 操作 13%
```

操作列只放两个 34px 的项目标准 `icon-button`：线性铅笔和线性垃圾桶；按钮提供 `title`
与 `aria-label`，不会因为摘要长文本而被压缩。摘要列允许省略，长物品名和 SKU 不能撑开页面。

移动端复核表重排为身份、入库参数、模板/批次和操作四段，沿用项目中性浅色表面、分隔线、
系统字体和克制圆角；页面不产生横向滚动。固定提交栏消费 `--safe-area-bottom`，工作区底部
余量保证最后一条明细可滚动到操作栏上方。

通用视觉、按钮、图标、Dialog、异步稳定等待和安全区规则分别以 `visual-style.md`、
`ui-design-guidelines.md`、`ui-consistency-checklist.md`、`async-state-transitions.md` 和
`mobile-interactions.md` 为准。

## 草稿、校验和权限

- 草稿键保持 `winestock.inbound-draft.v5`；不持久化活动选择层、Drawer 或焦点。
- 恢复草稿后只恢复复核列表；不会自动打开任意明细。
- 入库数量、单价、库位、模板字段由前端提供即时定位，core 仍执行最终校验。
- 页面按现有权限显示直接入库或提交审核；不改变 HTTP 契约、Shell Bridge 或运行模式。
- 选择弹窗中的新建物品复用 `ItemCreateDialog`，创建成功后进入同一条明细配置流程。

## 验收

至少检查 `1440×900`、约 `768px` 和 `390×844`：

- 选择层与明细 Drawer 不重叠，关闭后焦点回到触发按钮或搜索框；
- 桌面列宽无横向溢出，操作按钮保持 34px；
- 移动端固定底栏、Drawer 标题和关闭按钮避让安全区；
- 长名称、长 SKU、模板加载失败、字段错误和提交确认不改变布局；
- Android 返回只关闭最上层活动编辑器，下一次返回才交给路由；
- 控制台无新增 error/warning，`pnpm build` 与 `git diff --check` 通过。
