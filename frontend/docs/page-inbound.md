# 新建入库页面

本文记录 `/inbound` 当前单物品串行配置工作台的业务边界、交互状态和视觉验收要求。
页面只创建入库草稿并通过 HTTP 提交，不拥有入库审批工作台或库存事务 API。

## 当前流程

```text
入库单信息与明细
├─ 来源、备注
├─ 添加物品 -> ItemSelectionDialog
│              -> 选择一项后关闭选择层
│              -> 打开“入库物品明细”Dialog
└─ 明细复核列表
   ├─ 物品身份
   ├─ 数量、单价、库位与批次摘要
   └─ 编辑图标 / 移除图标
```

选择层和明细 Dialog 严格串行。选择层离场动画完成后才打开 Dialog；“完成并继续添加”
也会先完成当前 Dialog 的离场，再把焦点交给下一次选择。存在未完成明细时，“添加物品”仍可
点击，但不会打开选择层，而是重新打开第一条未完成明细并通过 Warning Notice 说明原因，避免
用户在多个明细之间来回补录，也避免禁用按钮造成操作无反馈。

## 扫码添加（立创料袋）

“扫码添加”与“添加物品”并排放置，打开通用 `BarcodeScanDialog` 识别立创料袋二维码；
识别、忽略与格式规则见 [`../../docs/implementation-notes/lcsc-bag-scanning.md`](../../docs/implementation-notes/lcsc-bag-scanning.md)。入库域行为：

- 命中（C 号按物品编号精确匹配）：关闭扫码进入该物品明细，袋内数量预填且可改；
  明细保存/暂存/取消后自动重开扫码，直到用户主动关闭扫码 Dialog（串行会话）；
- 重复扫到已在草稿的物品：不新增，Notice 提示并直接打开该行明细；
- 未命中：转入快速新建 Dialog，自动以 C 号执行立创资料查询预填；创建完成回到明细并应用数量；
- 料袋含订单号且整单来源为空时，明细 Dialog 顶部提示条询问是否以「立创 SO…」填入来源：
  「忽略」只挡同一订单号，「本单不再提示」随草稿持久化，来源已填则完全静默；
- 未完成明细存在时，“扫码添加”与“添加物品”一致：先回到未完成明细，完成后自动回到扫码。

## 导入订单（立创订单导出表格）

“导入订单”与扫码/添加按钮并排（仅入库域），打开 `LcscOrderImportDialog` 选择立创商城
「订单详情」导出的 `.xls` 文件。表格只取订单编号、商品编号（C 号）、订购数量与商品单价
四个字段，其余信息一律以 C 号经既有立创查询补齐；解析纯逻辑归 `src/lcsc/orderExport.ts`
（node 单测覆盖），SheetJS 仅在该 Dialog 内按需动态加载。

- 预览表逐行给出状态：已匹配（按物品编号精确匹配）、未命中、已在草稿/重复/不发货等跳过原因；
- 未命中行提供行内“新建”，复用 `ItemCreateDialog` 并自动以该 C 号查询预填，创建成功即转为已匹配；
- 确认导入把已匹配行批量加入草稿，数量与单价预填，库位留待逐条补齐（沿用未完成明细串行规则）；
- 识别到订单号且整单来源为空时提供勾选，把来源填为「立创 SO…」；来源已填则不出现勾选；
- 匹配查询失败的行计入跳过并可“重试匹配”，不阻塞其余行导入。

## 明细编辑器

`InboundLineEditor.vue` 是单条明细的唯一编辑入口，字段顺序为：

1. 数量、单价、入库库位；
2. 批次号、有效期。

来源和备注属于单据级字段，只在工作台填写一次。关闭、Escape 或 Android 返回只关闭当前
编辑器并保留草稿；删除必须通过复核列表的垃圾桶图标完成。完成明细不调用创建接口，页面级
“直接入库/提交审核”才会提交整张单据。

编辑器使用项目通用 `ModalDialog`：桌面为工作区宽 Dialog，移动端沿用通用底部面板；标题固定为
“入库物品明细”，物品身份位于 context，操作位于标准 actions。遮罩、关闭动画、焦点约束与返回
处理均由通用组件负责，不再维护入库专用侧栏。

字段未完成时，复核列表只显示实际阻塞原因，不常驻显示“已配置”标签。

## 复核列表与视觉规则

宽桌面将稳定字段展平为固定六列：

```text
物品 25% | 数量 10% | 单价 / 小计 14% | 库位 16% | 批次 自适应 | 操作 90px
```

操作列只放两个 34px 的项目标准 `icon-button`：线性铅笔和线性垃圾桶；按钮提供 `title`
与 `aria-label`，不会因为摘要长文本而被压缩。数量和库位保持单行，单价/小计与批次最多
两行；缺失或失效状态直接由对应字段使用警告或错误色表达，不在操作列重复显示状态文案。长物品名、
SKU 和库位名均省略显示，不能撑开页面。

窄桌面使用同一组单元格重排为三行信息网格，移动端再按字段标签纵向排列；两者都沿用项目中性
浅色表面、分隔线、系统字体和克制圆角，不增加重复业务结构，也不产生横向滚动。固定提交栏消费
`--safe-area-bottom`，工作区底部余量保证最后一条明细可滚动到操作栏上方。

通用视觉、按钮、图标、Dialog、异步稳定等待和安全区规则分别以 `visual-style.md`、
`ui-design-guidelines.md`、`ui-consistency-checklist.md`、`async-state-transitions.md` 和
`mobile-interactions.md` 为准。

## 可复制字段

工作台明细编辑区选中物品的名称与编号经 `v-copyable` 提供点击复制（无常驻图标）；
入库单详情弹窗的可复制字段见 [`page-inbound-orders.md`](page-inbound-orders.md)。
规范见 [`ui-consistency-checklist.md`](ui-consistency-checklist.md)。

## 草稿、校验和权限

- 草稿键为 `winestock.inbound-draft.v6`，旧版本草稿恢复时直接清除；不持久化活动选择层、Dialog 或焦点。
- 恢复草稿后只恢复复核列表；不会自动打开任意明细。
- 入库数量、单价、库位字段由前端提供即时定位，core 仍执行最终校验。
- 页面按现有权限显示直接入库或提交审核；不改变 HTTP 契约、Shell Bridge 或运行模式。
- 选择弹窗中的新建物品复用 `ItemCreateDialog`，创建成功后进入同一条明细配置流程。

## 验收

至少检查 `1440×900`、约 `768px` 和 `390×844`：

- 选择层与明细 Dialog 不重叠，关闭后焦点回到触发按钮或搜索框；
- 桌面列宽无横向溢出，操作按钮保持 34px；
- 移动端固定底栏、Dialog 标题和关闭按钮避让安全区；
- 长名称、长 SKU、字段错误和提交确认不改变布局；
- Android 返回只关闭最上层活动编辑器，下一次返回才交给路由；
- 控制台无新增 error/warning，`pnpm build` 与 `git diff --check` 通过。
