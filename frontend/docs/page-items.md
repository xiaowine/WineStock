# 物品管理页面

物品管理页拥有库存目录、新建与详情 Dialog。目录继续通过 WineStock HTTP API 查询；新建物品仍由现有
`ItemEditorDialog`、图片上传和 `POST /api/items` 完成。

## 可复制字段

目录行的物品名称与编号、编辑 Dialog 头部的名称与编号经 `v-copyable` 提供点击复制
（无常驻图标，copy 光标与键盘触发；产品决定保持字段视觉干净）；目录行上点击复制
阻断冒泡，不触发行级打开编辑。规范见
[`ui-consistency-checklist.md`](ui-consistency-checklist.md) 的「复制到剪贴板」。

## 移动物品目录

- 手机端工具栏固定为两行：第一行依次为搜索、刷新和新建，第二行依次为库存筛选、排序、高级筛选和展示设置；字段标题仅供无障碍读取，在不压缩常用选中值的前提下减少目录上方占用。
- 移动卡片头部保留主图、名称、编号、分类和右侧操作的稳定位置；关键属性使用头部下方的独立两列区域，短字段名保持完整，只允许字段值按可用宽度省略。
- 极窄视口下身份辅助信息和关键属性回落单列；桌面三段式目录、筛选状态、分页状态和行级操作语义保持不变。
- 验收覆盖 `390 x 844`、接近 `768px` 的断点和 Android WebView 实机，检查选择框当前值、长名称、长编号、关键属性、操作按钮和页面横向溢出。

## 新建草稿的默认模板

设置了全站默认物品属性模板时，新建物品草稿（物品管理与入库快速新建共用会话）在创建时自动
预选并应用该模板字段，基线指纹同步刷新，预填不计入未保存修改；用户可改选其它模板或
“不使用模板”。规则与设置入口见 [`page-templates.md`](page-templates.md)。

## 主图快捷粘贴

新建/编辑物品 Dialog 打开期间，Ctrl+V 粘贴剪贴板中的图片直接作为物品主图；粘贴文件与本地选择走同一套
校验（PNG/JPEG/WebP、15MB、内容核验）、图片草稿和提交时上传流程，成功与拒绝均通过全局 Notice 反馈。

- 监听由共享 `ItemEditor` 持有，仅在其所在 `.modal-layer` 是最上层时生效；立创查询、放弃确认等嵌套
  Dialog 打开时粘贴不会误改底层主图。
- 焦点在文本控件且剪贴板同时携带文本时（如复制网页图文），保持默认文本粘贴，不拦截。
- 只读详情与保存中不响应粘贴；替换临时已上传主图时立即删除服务端临时文件，与图片字段更换行为一致。
- 粘贴提示文案只在桌面视口显示。

## 立创资料查询

只有具备 `stock.item.manage` 权限、从物品管理打开的 `create` 模式 Dialog 显示“编号填写”和
“扫码填写”两个入口（并排放置，对仗文案表达“两种方式填写同一份立创资料”）。

查询能力按模块拆分：`useLcscLookupRequest` 拥有查询执行与错误文案，`LcscCandidateConfirmPanel`
拥有候选摘要与模板选择内容；手动入口使用带输入表单的 `LcscItemLookupDialog`，扫码与自动路径使用
**无输入表单**的 `LcscLookupFlowDialog`（仅 查询中/候选确认/错误 三态）。

“扫码填写”路径：识别到立创料袋码即取 C 号进入查询流；“不填写”、关闭或错误态“返回扫码”都会
**回到扫码 Dialog 继续**，不会停留在查询界面；“覆盖填写”后留在编辑器。非立创内容在扫码层内提示
已忽略，不关闭扫码。

入库选品中复用的快速新建 Dialog 不显示这两个入口，但入库扫码未命中转入的新建会话会以扫到的
C 号自动打开同一查询流预填（取消后留在编辑器手动填写，见
`docs/implementation-notes/lcsc-bag-scanning.md`）。编辑已有物品不允许通过此能力覆盖资料。

查询流程：

```text
新建物品 Dialog
  -> 编号填写
  -> 输入单个 C + 数字商品编号
  -> GET /api/items/lookups/lcsc/{product_code}
  -> 查询成功后显示命中摘要
     -> 不填写：草稿不变
     -> 选择属性模板（默认第一项）
     -> 覆盖填写：先应用模板、候选资料和参考价格，再异步直连受控图片地址准备商品主图
  -> 返回外层 Dialog继续检查和保存
```

查询使用嵌套 `ModalDialog`，外层新建会话始终保持挂载。关闭、Escape 和 Android 返回只关闭最上层查询 Dialog；
查询中的关闭会中止前端请求，关闭后焦点返回“编号填写”。错误保留商品编号并允许原地重试。

确认覆盖后：

- 商品编号覆盖 SKU；
- 非空候选名称和描述覆盖基础字段；
- 确认态默认选择模板列表第一项，也允许改选其它模板或“不使用模板”；
- 先应用所选模板，再把候选资料覆盖到同名模板字段；模板缺少的字段创建物品私有自定义属性；
- 制造商型号、制造商、封装、数据手册和其它参数分别映射到“型号”“品牌”“封装”“数据手册”“参数”；
- 同名属性直接覆盖，缺失属性创建物品私有自定义属性；
- 空候选值不清空当前字段；
- 有效 `default_price` 覆盖参考单价；价格为空时保留当前值；
- 使用 Core 响应中经过白名单校验的 `image_url`，从 `alimg.szlcsc.com` 直接读取图片 Blob；请求不携带
  WineStock token、Cookie 或自定义头，前端复核格式、大小和文件签名后转换为普通待上传图片草稿并覆盖主图；
- 图片请求只在用户确认覆盖后发起；图片缺失或读取失败时保留当前主图，并使用非阻断提示；已经完成的资料、
  模板属性和价格回填不得回滚；
- 分类、单位和补货点保持不变；
- 不更新草稿 baseline，不自动保存，外层关闭继续触发现有未保存确认；
- 最终创建仍执行现有主图、SKU、模板与属性校验。

modal-actions 中「编号填写」「扫码填写」作为左侧次要操作紧贴成组（组内 8px 间距，组尾吃掉剩余空间），「取消」「保存物品」保持右侧；移动端必须检查四个按钮的实际宽度和安全区。
查询 Dialog 使用组件自有 SCSS，并在 `1440×900`、断点附近和 `390×844` 验证嵌套层级、横向溢出、长文本、
焦点、控制台和 Android 返回。
