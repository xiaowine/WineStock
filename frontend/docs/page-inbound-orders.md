# 入库单页面实施设计

本文定义 `/inbound/orders`“入库单”页面的实施方案。它负责查询、筛选和查看已创建的入库单；新建入库仍属于 [`/inbound`](../src/pages/StockDraftPage.vue) 工作台，审批或拒绝仍属于 `/approvals/inbound`。页面不复制新建草稿、审批写入或库存调整逻辑。

当前状态：已实现服务端分页协议下的触底追加、关键词/状态/日期筛选、按需详情和审批路由跳转；core 已补齐状态筛选契约。物品名称投影仍是后续扩展。

通用视觉、三段式列表、响应式、异步反馈和验收规则以 `visual-style.md`、`ui-design-guidelines.md`、`ui-consistency-checklist.md` 和 `async-state-transitions.md` 为准。本文只定义入库单业务信息、功能边界和具体页面结构。

## 页面目标

- 让拥有 `stock.inbound.read` 的用户快速定位某张入库单，并区分待审批、已入库和已拒绝的业务结果。
- 在列表保留足够的身份、状态、来源、明细和金额信息；详情展示每条明细、库位、批次与审批时间。
- 让审批能力保持在审批路由，不在入库单查询页悄悄执行“通过”或“拒绝”。
- 首次和筛选变更只加载第 1 页；列表尾部哨兵按需追加后续页，详情独立按需请求，避免列表预载所有属性和图片。

## 已有 HTTP 契约

### 可直接使用

| 接口                             | 权限                 | 页面用途                                                                                    |
| -------------------------------- | -------------------- | ------------------------------------------------------------------------------------------- |
| `GET /api/inbound`               | `stock.inbound.read` | 服务端分页列表；当前支持 `page`、`page_size`、`item_id`、`date_from`、`date_to`、`search`。 |
| `GET /api/inbound/filter-values` | `stock.inbound.read` | 获取历史中可出现的基础字段筛选值，供高级筛选候选展示与后续扩展。                            |
| `GET /api/inbound/{id}`          | `stock.inbound.read` | 按需读取单据完整明细、创建/审批/拒绝元数据。                                                |

`InboundResponse` 现有 `id`、`source`、`status`、`notes`、创建/审批/拒绝用户 ID 与时间，以及 `items`。每条明细提供物品 ID、数量、单价、库位 ID/名称、批次号和有效期。列表与详情使用同一响应结构，但页面不得假设创建响应独有的 `submission_mode` 一定存在。

### 已补齐的 core 状态筛选契约

`GET /api/inbound` 支持 `status` 查询参数，前端不能在已经分页的结果上本地筛选状态：

```text
GET /api/inbound?...&status=pending|approved|rejected
```

- `status` 为空表示全部；单值筛选即可，首版不需要多选或逗号语法。
- service 校验只接受三个稳定枚举值；非法值返回现有 `400 invalid_request`。
- repository 把状态条件同时放入列表查询和总数查询，分页响应的 `total`、`total_pages` 必须与结果一致。
- `GET /api/inbound/filter-values` 不替代状态筛选；状态是稳定工作流字段，前端直接用固定中文标签，不等待历史数据生成候选项。

不在本页首版增加创建人、审批人、库位的服务端筛选。关键词搜索已覆盖单据、明细和关联物品；更复杂的字段筛选应在 core 明确参数和索引后另行设计，不能把筛选值接口的返回结果当成前端本地筛选源。

## 权限与职责

| 用户能力                     | 页面行为                                                                                                         |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 无 `stock.inbound.read`      | 路由守卫返回总览，页面不请求 API。                                                                               |
| `stock.inbound.read`         | 可查看列表、筛选、触底追加和详情。                                                                               |
| 另有 `stock.inbound.create`  | 顶部可显示“新建入库”主按钮，跳转 `/inbound`；没有创建权限时完全不渲染。                                          |
| 另有 `stock.inbound.approve` | 状态为 `pending` 时在详情中显示“前往入库审批”，跳转 `/approvals/inbound`；不在本页直接调用 approve/reject 接口。 |

前端权限只收敛入口，服务端继续实时授权。详情读取或跳转后出现 `403` 时，保留列表上下文、关闭不可用动作并给出 Notice。

## 页面信息架构

```text
页面标题“入库单” + 说明
├─ 工具栏：关键词搜索、筛选 Dialog 入口、刷新、新建入库
├─ 已应用条件摘要：结果总数、清除筛选
├─ 主列表：桌面三段式行 / 移动单列条目
└─ 入库单详情 Dialog：单据摘要、审批轨迹、入库明细
```

页面不使用常驻双栏详情。列表需要在桌面和移动端维持稳定宽度；点击行或“查看详情”后才打开 `ModalDialog`。Dialog 打开期间保留列表、搜索词、已应用筛选和当前页。

## 工具栏与筛选设计

### 关键词搜索

- 使用现有 `SearchField`，提示词为“搜索单号、来源、物品或批次”。
- 输入草稿防抖后应用到服务端 `search`，变化时回到第 1 页；不在前端仅过滤当前页。
- 清空搜索恢复原条件与第一页，主动取消旧请求不显示错误。

### 状态筛选

状态选择位于“筛选入库单”Dialog：`全部`、`待审批`、`已入库`、`已拒绝`。选项使用文字，不只依赖颜色区分状态。

| 状态       | 标签   | 视觉语义               | 行为                               |
| ---------- | ------ | ---------------------- | ---------------------------------- |
| `pending`  | 待审批 | 低饱和警告色           | 库存尚未增加；详情可显示审批入口。 |
| `approved` | 已入库 | 低饱和成功色           | 已写入批次和库存流水。             |
| `rejected` | 已拒绝 | 中性弱化或低饱和危险色 | 不增加库存，也不能再次审批。       |

点击“应用筛选”才请求新的服务端页，并更新 URL query，例如 `#/inbound/orders?status=pending`。页面初始化解析 query；浏览器前进/后退恢复同一筛选与页码，非法 query 降级为默认值并 replace 为合法 URL。

### 日期范围与高级筛选

- 工具栏只保留关键词搜索、结果数、筛选图标和刷新图标。状态和“创建时间”范围在“筛选入库单”Dialog 中以草稿编辑，时间字段复用项目 `DateTimeField`；点击“应用筛选”后将本地时间转换为 ISO UTC，写入 `status`、`date_from` 与 `date_to` URL query 并重新读取服务端结果。
- 筛选图标右上角显示已启用的状态和日期条件数；Dialog 的“重置”仅清空草稿，仍须点击“应用筛选”才影响列表。
- 开始晚于结束时在应用前提示字段错误，不发送请求。
- 首版 Dialog 仅承载状态和日期；关键词仍在工具栏。
- 空状态说明提供“清除筛选”入口，一次复位状态、日期、关键词和页码，并替换 URL query。

### 刷新与新建

- 刷新保留列表、滚动位置和筛选条件，只让刷新图标进入稳定等待状态；不清空为骨架屏。
- 新建按钮只在 `stock.inbound.create` 时显示，使用主题色图标按钮，跳转 `/inbound`。它不打开本页 Dialog，也不在返回时伪造新记录；入库工作台创建成功后由其成功逻辑或返回时刷新处理。

## 列表设计

### 桌面（1440 × 900）

列表沿用身份、业务信息、判断与操作三段式，不使用传统密集表格的所有字段列。

1. 身份段：主信息 `入库单 #<id>`；次行显示来源，缺失时显示“未记录来源”；再显示创建时间。
2. 业务信息段：`n 条明细`、`总数量`、`预计金额`，以及最多两个物品名称摘要。总数量只在所有明细单位相同才合计并展示单位；单位混合时显示“按明细分别计量”，禁止伪造合计。
3. 判断与操作段：状态标签、审批/拒绝时间摘要和查看图标。`pending` 不显示虚假的“已入库时间”；`approved` 只显示审批时间；`rejected` 只显示拒绝时间。

金额按明细 `quantity × unit_price` 求和，显示为“入库金额”，不能称为实时库存价值。物品名称过多时显示“物品 A、物品 B 等 n 项”，完整内容在详情中展示。

行点击打开详情；键盘焦点、Enter 和 Space 与查看按钮等价。若行内存在审批跳转按钮，必须阻止事件冒泡，不能让一次点击同时打开详情。

### 移动（390 × 844）

- 单据编号、状态标签和操作菜单位于第一行。
- 来源、创建时间位于第二行；长来源允许两行截断并用详情查看全文。
- 明细数、数量/单位和金额以自然换行的紧凑元信息组呈现。
- 状态时间单独一行，不挤压状态标签和主操作；不使用横向滚动容器。
- 点击卡片打开详情；危险或审批类跳转保留独立可达按钮，不能让整张卡片承担写操作。

### 列表状态

- 初次加载：没有旧数据时使用稳定加载占位；超过 200ms 才出现，出现后至少展示 350ms。
- 后台刷新：保留原行和滚动上下文，刷新按钮显示等待；响应到达后以新的第 1 页替换列表。
- 触底追加：列表尾部进入可见区域时请求下一服务端页，按单据 ID 去重追加；加载、失败重试和“已加载全部”均固定显示在尾部，不显示“上一页/下一页”。
- 空数据：区分“尚无入库单”与“没有符合条件的入库单”；仅前者可给有创建权限的用户显示“新建入库”。
- 请求失败：无缓存时显示页面内错误和重试；有缓存时保留内容并以 Notice 报告刷新失败。
- 删除或审批导致的外部状态改变：本页不乐观修改未知记录；手动刷新或路由返回时重新读取当前页。

## 详情 Dialog

详情使用宽屏 `ModalDialog`，移动端占满可用视口。打开时先展示列表行的稳定身份上下文，同时按需请求 `GET /api/inbound/{id}`；不能用列表响应猜测审批元数据。

### 顶部上下文

- 标题：`入库单 #<id>`。
- context 区：状态标签、来源、创建时间。
- 右侧/底部操作：关闭；有创建权限时“新建入库”；具备审批权限且状态为 `pending` 时“前往入库审批”。
- 不提供编辑、删除、复制、重新提交、直接审批或拒绝按钮；当前 API 与业务规则均未定义这些行为在本页执行。

### 单据摘要

使用键值区，而不是禁用表单：来源、备注、创建时间、创建人 ID、状态、审批/拒绝时间与对应用户 ID。若用户信息接口不提供可安全解析的姓名，本页显示稳定的“用户 #<id>”，不发起 N+1 用户查询。

`approved` 显示“已于 <时间> 入库”；`pending` 显示“等待审批，库存尚未增加”；`rejected` 显示“已拒绝，未增加库存”。这三种说明只在状态区显示一次。

### 明细区

每条明细为连续条目，不使用嵌套卡片：

- 标题：`明细 n`、物品 ID（若后端尚未返回物品名称，显示 `物品 #<id>`，并把名称增强列为后续 API 扩展，而不是前端额外请求）。
- 主数据：数量、物品单位、单价、行金额、库位名称、批次号、有效期。

混合单位不在顶部伪合计；每条明细必须保留其实际单位。日期、金额和数量复用入库工作台已有格式化函数，避免同一业务在两个页面出现不同精度或货币符号。

### 详情异步与错误

- 打开 Dialog 后立即请求详情；等待期间保留标题和 context 区，内容区使用局部稳定加载状态。
- `404`：提示单据不存在或已不可读取，关闭 Dialog 后刷新当前列表。
- `403`：提示权限已变化，关闭 Dialog，保留列表筛选上下文。
- 网络失败：保留 Dialog、显示重试入口和原行摘要；不清空列表或改变 URL。
- 重复打开不同单据时取消前一个 `AbortController`；只允许最新响应写入当前 Dialog。

## 可复制字段

详情 Dialog 头部的整单来源、物品行的名称与编号经 `v-copyable` 提供点击复制
（无常驻图标）；规范见 [`ui-consistency-checklist.md`](ui-consistency-checklist.md)。

## 建议前端模块划分

```text
frontend/src/api/inboundOrders.ts
  - 入库单分页、详情、筛选值 DTO 与请求；不管理页面状态。
frontend/src/pages/InboundOrdersPage.vue
frontend/src/pages/InboundOrdersPage.scss
  - 路由页面、URL query、筛选、触底追加、列表刷新和详情会话编排。
frontend/src/pages/inbound-orders/model.ts
  - 查询草稿/URL 转换、状态标签、金额数量汇总、列表摘要派生；不请求 API。
frontend/src/components/inbound/InboundOrderList.vue
  - 桌面/移动列表呈现与行事件；不请求 API。
frontend/src/components/inbound/InboundOrderDetailDialog.vue
  - 详情按需加载、只读明细和审批跳转；不拥有列表筛选。
frontend/src/components/inbound/InboundOrderFiltersDialog.vue
  - 窄屏/高级日期筛选草稿；不直接写 URL 或请求 API。
```

若现有 `frontend/src/api/inbound.ts` 已成为入库共享边界，可扩展该文件而不是创建重复 client；最终以“创建草稿 API”和“查询订单 API”职责是否仍清晰为准。不要为本页引入状态管理库或第三方表格/日期库。

## 实施顺序

1. core 状态服务端筛选、OpenAPI、业务 API 文档和回归测试已完成。
2. 前端 DTO、查询 URL 模型、状态标签、列表、详情和路由替换已完成。
3. 后续补充物品名称批量投影，并执行浏览器多视口实测。

## 验收清单

- 服务端状态、关键词、物品和日期筛选的 `total`、页码与列表一致；切换筛选不保留旧页码。
- `pending`、`approved`、`rejected` 三种状态均有正确的库存语义与时间字段，不互相混用。
- 只有审批权限用户能看到“前往入库审批”，且它不在本页执行审批写操作。
- 详情中的多明细、混合单位、无批次号和无有效期均可读。
- 在 `1440 × 900`、约 `768px` 与 `390 × 844` 检查无横向溢出、实际元素尺寸、Dialog 焦点恢复与控制台新增错误/警告。
- 覆盖初始加载、后台刷新、触底追加/失败重试/已加载全部、空数据、筛选无结果、详情加载/404/403/网络失败、权限变化与浏览器前进后退。
- `pnpm build`、相关 core 定向测试、`git diff --check` 通过；实施完成后更新 `frontend/docs/routes.md`、`frontend/docs/api-client.md`、`core/docs/business-api/inbound.md` 和对应代码地图。

## 明确非目标

- 不在本页创建、编辑、删除或复制入库单。
- 不把“直接入库/提交审核”模式切换复制到历史单据页面。
- 不在本页直接执行审批、拒绝、库存调整或批次移动。
- 不以本地筛选、已加载页或筛选值候选伪造服务端查询能力。
- 不为显示物品名称、用户名称而逐行追加请求；需要时通过批量投影扩展 core 契约。
