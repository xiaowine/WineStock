# 分类与模板页面实施设计

本文定义 `/templates`“分类与模板”页面的前端实施方案，覆盖物品分类和物品属性模板两个独立业务域。页面必须基于真实 API 和权限实现，不把两类数据抽象成含义模糊的统一模板；分类与物品属性模板使用服务端提供的当前有效物品使用数量。

当前状态：页面、完整 API client、分类 CRUD、物品属性模板查看/创建/编辑/复制/删除、字段编辑模型和目标视口响应式样式已经实现；后续扩展仍必须遵守本文边界。

通用视觉、三段式列表、异步状态和响应式规则继续以 [`visual-style.md`](visual-style.md)、[`ui-design-guidelines.md`](ui-design-guidelines.md)、[`ui-consistency-checklist.md`](ui-consistency-checklist.md) 与 [`async-state-transitions.md`](async-state-transitions.md) 为准；本文只补充本页面的业务结构和验收标准。

## 页面目标

- 在一个稳定工作区内管理物品分类和物品属性模板。
- 允许管理者完成创建、编辑、复制、排序和删除，同时让只读用户获得完整的结构查看能力。
- 复用项目现有页面骨架、工具栏、三段式列表、`ModalDialog`、表单控件、Notice 和稳定刷新规则。
- 在桌面、断点附近和移动端保持同一业务状态，不因布局切换重建页面或丢失编辑草稿。

## 非目标

- 不在本页编辑具体物品、库存、入库单或实际属性值。
- 不把分类与模板建立强制绑定；当前 API 没有此关系。
- 不提供服务端分页、服务端搜索、批量删除、导入导出或版本历史；当前 API 不支持这些能力。
- 不从分页物品列表推导使用次数、受影响物品数或删除前影响分析；只展示分类和物品属性模板响应提供的数量。
- 不在首版引入拖拽依赖；字段顺序使用明确的上移、下移按钮调整。

## 权限边界

| 能力                         | 权限                    | 前端行为                                       |
| ---------------------------- | ----------------------- | ---------------------------------------------- |
| 进入页面并读取两类列表和详情 | `stock.template.read`   | 路由守卫校验；读取失败按页面错误状态处理       |
| 创建、编辑、复制和删除       | `stock.template.manage` | 无权限时不渲染新增、编辑、复制、删除和保存入口 |

前端权限只用于收敛入口，所有写请求仍由 core 实时鉴权。会话期间权限被撤销后，已打开的编辑 Dialog 应关闭或切换为只读；写请求返回 `403` 时显示 Notice 并刷新当前业务域。

## API 与数据契约

### 物品分类

- 列表与创建：`GET /api/item-categories`、`POST /api/item-categories`
- 详情、更新与删除：`GET/PUT/DELETE /api/item-categories/{id}`
- 字段：`id`、`name`、`description`、`sort_order`、`item_usage_count`、`created_at`、`updated_at`
- 名称裁剪首尾空白后长度为 1 至 128；说明存在时长度为 1 至 1024；排序值是大于等于零的整数。
- 名称冲突返回 `409 category_name_taken`，应映射到名称字段。
- 删除是软删除。已有物品可能继续保留分类 ID，但物品列表无法再解析出活动分类名称；页面不得宣称删除会自动重分类。

### 物品属性模板

- 列表与创建：`GET /api/item-attribute-templates`、`POST /api/item-attribute-templates`
- 详情、更新与删除：`GET/PUT/DELETE /api/item-attribute-templates/{id}`
- 复制：`POST /api/item-attribute-templates/{id}/copy`
- 字段：`id`、`name`、`description`、`item_usage_count`、`fields`、`created_at`、`updated_at`
- 删除会解除现有物品的模板关联，并删除由该模板定义的物品属性值，是不可由前端恢复的高风险操作。

### 模板字段

物品属性模板要求 1 至 64 个字段，字段数组顺序就是保存后的展示顺序。

| 属性            | 规则                                                                     |
| --------------- | ------------------------------------------------------------------------ |
| `definition_id` | 编辑已有字段时原样提交；新增字段省略或传空，不能在前端重新生成           |
| `field_name`    | 1 至 64 字符；同一模板内忽略大小写唯一                                   |
| `field_type`    | `text`、`number`、`select`、`date`、`file`、`url`、`boolean`             |
| `required`      | 是否要求实际录入值                                                       |
| `searchable`    | 是否参与后续筛选值聚合                                                   |
| `options`       | 仅 `select` 使用；1 至 128 项，去空白后忽略大小写唯一，每项最多 128 字符 |
| `default_value` | 最多 256 字符；必须符合当前字段类型；`file` 禁止默认值                   |

默认值校验必须与服务端一致：数字必须有限，布尔值只能是 `true` 或 `false`，URL 只能使用 HTTP/HTTPS，日期必须是实际存在的 `YYYY-MM-DD` 日期，选择默认值必须属于候选项。

物品属性模板字段额外包含：

- `catalog_visible`：每套模板最多三个字段；编辑区持续显示 `目录字段：已选择 n / 3`。
- `unit.mode = none`：无单位。
- `unit.mode = fixed`：固定单位长度 1 至 32，实际录入只读展示该单位。
- `unit.mode = select`：1 至 32 个候选单位，忽略大小写唯一，每项长度 1 至 32。

## 信息架构

页面使用一个连续工作区，不为两类数据分别建立路由。整体自上而下分为：

1. 页面标题区：标题“分类与模板”和简短说明“维护物品归类与长期属性结构”。
2. 业务域切换：`物品分类`、`物品属性模板` 两个分段按钮或页签。
3. 当前域工具栏：本地搜索、结果数量、刷新和权限控制的主题色新增图标按钮。
4. 当前域主体：桌面三段式列表，窄屏切换为纵向条目。
5. 创建、查看、编辑、复制和删除 Dialog。

业务域切换只替换工作区内容，不改变路由。每个业务域分别保留搜索词、已加载数据和滚动位置；切回已加载业务域时先展示缓存，再按需后台刷新，避免反复空白闪烁。

## 业务域切换

- 两个入口必须同时带文字，不使用只有图标的切换方式。
- 当前项使用主题色文字、浅主题背景和清晰选中指示，不依赖颜色作为唯一状态。
- 切换后页面标题不变，工具栏占位和列表起点保持稳定。
- 首次进入默认选择“物品分类”；后续可在当前页面生命周期内记住最后选择，不写入持久存储。
- 键盘可用左右方向键切换，具备正确的 `tablist`、`tab`、`tabpanel` 关系。

## 工具栏设计

- 搜索框使用 `SearchField`，占据可伸缩空间；提示词随当前域变化，例如“搜索分类名称或说明”。
- 搜索只作用于已完整加载的本地列表，按名称和说明进行不区分大小写的包含匹配；模板字段名不进入首版搜索范围。
- 数量显示为当前筛选结果，例如 `12 个分类`、`5 个物品模板`；加载期间保留上次数量，刷新不跳成零。
- 刷新使用稳定图标按钮，位于新增按钮紧邻位置；不得被放在搜索框与数量之间。
- 新增使用主题色圆角图标按钮，图标为加号，按当前域提供 `aria-label` 和 tooltip，例如“新建物品属性模板”。
- 无管理权限时新增入口完全不渲染，刷新仍可用。
- 窄屏时搜索独占第一行，数量、刷新和新增靠近排列在第二行；不得让数量远离操作按钮或产生横向滚动。

## 列表通用规则

列表沿用项目三段式信息结构：身份、业务信息、判断与操作。桌面使用对齐的表格化行，但不追求传统密集数据表；移动端转为无横向滚动的卡片式条目。

- 初次加载：只在无可展示数据时显示稳定加载骨架或占位。
- 后台刷新：保留现有列表和滚动位置，只让刷新按钮显示等待状态。
- 空列表：分别显示“还没有分类/模板”，有管理权限时提供与工具栏一致的新增入口。
- 搜索无结果：显示“没有符合条件的结果”和清除搜索按钮，不误报为空数据。
- 加载失败：无缓存时显示页面内错误和重试；有缓存时保留内容并用 Notice 提示刷新失败。
- 行操作期间只锁定对应行或 Dialog，不能让整页失去浏览能力。
- 默认排序遵循服务端返回顺序；分类若需明确前端排序，则按 `sort_order` 升序、名称本地化比较、ID 升序稳定排列。模板首版不提供用户排序控件。

## 物品分类列表

### 桌面三段式

1. 身份段：分类名称为主信息，次行显示 `分类 #<id>`。
2. 信息段：说明文本，缺失时显示弱化的“暂无说明”；最多展示两行并允许从查看/编辑 Dialog 阅读全文。
3. 判断与操作段：同一紧凑区域显示 `已用于 n 个物品 · 排序 <sort_order> · 更新 HH:mm`，随后是编辑和删除图标按钮；零使用数显示“暂未被物品使用”。

更新时间只显示小时与分钟，不拆成两列；完整日期时间通过 `title` 或可访问描述提供。参数名使用弱化颜色，参数值使用正文或强调色，避免“排序”“更新时间”和数值混成同一视觉层级。

### 移动条目

- 第一行：名称和操作菜单。
- 第二行：两行以内说明。
- 第三行：`排序 <值> · 更新 <HH:mm>`；宽度不足时先压缩说明区域，不能隐藏更新时间。
- 编辑和删除可收敛到操作 Dialog，但删除必须保持危险操作样式。

## 物品属性模板列表

### 桌面三段式

1. 身份段：模板名称、`物品模板 #<id>` 和一行说明摘要。
2. 信息段：使用不同颜色区分标签与值，展示 `字段 n`、`必填 n`、`可筛选 n`、`目录 n/3` 和 `已用于 n 个物品`。
3. 判断与操作段：显示更新时间，并提供查看/编辑、复制和删除操作。

### 移动条目

- 名称和状态置顶，说明最多两行。
- 指标以可换行的紧凑键值组呈现，不使用四个等宽列。
- 普通操作进入移动操作 Dialog；高频查看入口可保留为行点击，不能让删除成为整行点击行为。

## 分类编辑 Dialog

分类使用标准尺寸 `ModalDialog`，创建和编辑复用同一表单：

- 名称：必填，最大 128 字符，提交前裁剪首尾空白。
- 说明：可选，最大 1024 字符；空字符串提交为 `null` 或按 API 约定省略。
- 排序：必填，非负整数，默认值为当前最大排序值加一；无法计算时为零。
- 底部操作：取消、主题色“创建”或“保存”。

编辑打开时可直接使用列表完整响应；如果列表契约不能保证详情完整，再请求详情。提交成功后以响应替换对应记录，保留当前搜索和滚动位置。

## 模板编辑工作区

物品属性模板使用宽屏 `ModalDialog`；移动端占满可用视口。它不是简单的三字段表单，而是可以维护完整字段结构的编辑工作区。

### 顶部基础信息

- 模板名称：必填，1 至 128 字符。
- 模板说明：可选，最多 1024 字符。

### 字段工具条

- 左侧显示“字段结构”和 `n / 64`。
- 同时显示“目录字段：已选择 n / 3”。
- 右侧为“添加字段”按钮；达到 64 个时禁用并说明原因。
- 字段至少保留一个。只剩一个字段时删除按钮禁用并说明“模板至少需要一个字段”。

### 字段条目

每个字段使用可折叠编辑卡片，标题行包含顺序号、字段名称或“未命名字段”、类型、必填状态以及上移、下移、删除操作。展开区包含：

- 字段名称和字段类型。
- 必填、可筛选开关。
- 默认值编辑器。
- `select` 候选项编辑器。
- 目录展示开关和单位规则。

首个字段禁用上移，末个字段禁用下移。上移、下移后焦点留在被移动字段的对应按钮，并通过可访问状态说明新位置。删除字段必须在字段存在已填写内容时确认；未填写的新空字段可直接移除。

### 类型相关编辑器

- `text`：默认值使用单行文本。
- `number`：默认值使用允许小数的文本/数字输入，保存前验证有限数值，不依赖浏览器静默纠正。
- `select`：展示候选项列表，支持添加、删除和上下移动；默认值从候选中选择。
- `date`：使用符合项目风格的日期控件，不调用浏览器原生日期弹层；保存格式为 `YYYY-MM-DD`。
- `file`：隐藏并清空默认值，显示“图片字段不支持默认文件”。
- `url`：普通输入框并校验 HTTP/HTTPS。
- `boolean`：默认值使用“未设置 / 是 / 否”选择，映射为 `null / true / false` 字符串契约。

字段类型改变时，如果现有默认值、候选项或单位配置与新类型不兼容，先显示确认提示，明确将被清除的内容；用户取消时恢复原类型。不能在 `watch` 中静默丢失数据。

### 选择候选与单位候选

- 每项使用文本输入、上移、下移和删除操作，不以逗号分隔的大文本代替结构化编辑。
- 添加后自动聚焦新项；重复或空白错误定位到具体项。
- `select` 至少保留一个候选项；单位 `select` 同样至少保留一个候选单位。
- 切回“无单位”前确认清除已有单位内容。

### 目录展示字段

- 每个字段提供 `catalog_visible` 开关。
- 已选择三个后，其他未选字段的开关禁用并显示“目录最多展示 3 个字段”。
- 已选字段仍可关闭；顺序由模板字段顺序决定，不另建一套目录顺序。
- 本页修改的是模板默认目录字段，物品页面的目录字段维护入口不应被误认为模板结构编辑器。

### 保存与离开

- 保存前执行完整客户端校验，并滚动聚焦首个错误；Notice 只概括第一个原因，不插入导致布局跳动的可见错误行。
- 请求提交整个有序字段数组；编辑已有字段时保留 `definition_id`。
- 保存期间锁定关闭、保存和会改变请求内容的操作，但编辑区视觉位置保持不变。
- 保存成功后关闭或切换到干净查看态，以响应数据更新列表。
- 有未保存修改时，关闭按钮、Escape、遮罩点击和移动端返回动作都进入离开确认。

## 查看模式

只读用户和管理用户都可以打开模板详情。详情复用模板工作区结构，但所有控件转为只读呈现，不显示伪装成禁用表单的大面积灰色输入框：

- 基础信息使用键值信息区。
- 字段按顺序展示名称、类型、必填、可筛选、默认值、候选项、单位和目录展示状态。
- 管理用户可从详情头部进入编辑；只读用户不显示该操作。

## 复制流程

- 复制操作只适用于物品属性模板，不适用于分类。
- 小型 Dialog 显示来源模板名称，只要求输入新的唯一名称。
- 默认建议名称为 `<原名称> 副本`，但用户必须确认或修改。
- 名称冲突 `409 template_name_taken` 映射到名称字段。
- 成功后把复制结果插入当前列表，显示成功 Notice，并直接打开新模板的编辑工作区供用户检查。
- 复制必须保留字段顺序、候选项、默认值、单位规则和目录展示状态。

## 删除确认

两类删除不得共用一段泛化文案：

### 删除分类

明确说明：分类将从活动分类列表移除；已有物品可能继续保存该分类 ID，但不会自动改到其他分类，后续需要重新归类。确认框展示服务端列表响应的当前有效使用数，并说明这是打开确认框时的快照；删除成功 Notice 使用删除响应的 `affected_active_item_count`。

### 删除物品属性模板

使用高风险确认样式，明确说明：

- 已有物品与该模板的关联会被解除。
- 由该模板字段定义的物品属性值会被删除。
- 此操作无法从当前界面恢复。

确认框展示服务端列表响应的当前有效使用数；删除成功 Notice 使用删除事务内返回的 `affected_active_item_count`，不能沿用打开确认框时的旧值。

确认按钮使用“删除模板及属性”，不能只写含义过轻的“确定”。可要求再次输入模板名称，以降低误触风险。

## 异步与错误处理

- 两个业务域分别维护 `idle/loading/ready/refreshing/error`，不能用一个全页布尔值让切换互相阻塞。
- 首次进入当前域才发起列表请求。
- 同一业务域重复刷新应复用或取消旧请求，迟到响应不能覆盖较新的提交结果。
- 创建、更新、复制和删除成功后优先使用响应局部更新；需要验证服务端最终状态时再后台刷新，不先清空列表。
- `400 invalid_request` 和字段错误映射到具体控件；`409` 映射名称冲突；`403` 说明权限变化；`404` 说明记录已被其他用户删除并刷新列表；网络错误保留编辑草稿。
- 切换业务域不关闭正在编辑的 Dialog；Dialog 打开时背景域切换不可操作。

## 响应式设计

### `1440 × 900`

- 工作区使用页面允许的全宽内容，业务域切换、工具栏和列表对齐。
- 模板列表完整呈现三段信息，操作图标保持在行尾。
- 模板编辑 Dialog 使用宽工作区，基础信息与字段结构可见，不让正文形成窄长单列。
- 字段卡片可把基础属性和类型配置分为两列，但阅读顺序必须保持从上到下。

### `1024 × 768` 及断点附近

- 工具栏允许搜索框缩短或换行，数量、刷新、新增保持为相邻操作组。
- 三段式列表适当收窄身份段，信息键值组自然换行；更新时间不得被 `overflow: hidden` 吃掉。
- 模板编辑器改为单列字段配置，底部操作固定在 Dialog 可视区域内，正文独立滚动。
- 在断点前后各检查一次，确认不出现桌面列仍存在但内容已不可读的中间状态。

### `390 × 844`

- 页面无横向滚动；业务域切换允许等宽两项或整组横向滚动，但当前项和文字必须完整可见。
- 搜索独占一行；结果数量靠近刷新、新增按钮。
- 列表使用移动条目，键值信息换行，更新时间始终可见。
- 模板编辑器占满可用视口，标题栏和保存区保持可达，字段正文独立滚动并适配安全区。
- 候选项操作按钮保留至少 44px 触控目标，不把上移、下移、删除压成难以触达的密集图标。
- 键盘弹出后当前输入和错误仍能滚动到可见区域。

## 可访问性

- 所有纯图标按钮提供准确的 `aria-label` 和 tooltip，禁用时可读出原因。
- 分段切换、字段折叠、开关、候选项列表和确认 Dialog 使用对应语义与键盘交互。
- 标签名与参数值除颜色外，还通过字重、间距或结构区分。
- 危险操作不只依赖红色，必须有明确标题、后果文本和动作名称。
- 保存错误聚焦首个字段；字段重排和删除后把焦点放回可预测位置。
- 动画遵守项目 motion token 和 `prefers-reduced-motion`，不为字段重排添加大幅位移动画。

## 前端模块建议

建议按业务所有权拆分，避免把所有逻辑堆入页面：

```text
frontend/src/
├─ api/
│  ├─ itemCategories.ts
│  ├─ itemAttributeTemplates.ts
│  └─ templateFields.ts
├─ components/templates/
│  ├─ TemplateDomainTabs.vue
│  ├─ TemplateListToolbar.vue
│  ├─ CategoryDialog.vue
│  ├─ TemplateEditorDialog.vue
│  ├─ TemplateFieldEditor.vue
│  ├─ TemplateOptionEditor.vue
│  ├─ TemplateCopyDialog.vue
│  └─ TemplateDeleteDialog.vue
└─ pages/
   ├─ TemplatesPage.vue
   ├─ TemplatesPage.scss
   └─ templates/
      ├─ model.ts
      ├─ validation.ts
      └─ presentation.ts
```

- `TemplatesPage.vue`：业务域状态、请求编排、权限入口和列表局部更新。
- API 文件：补齐两类资源的完整 CRUD、复制请求 DTO 和响应类型，不制造统一模板接口。
- `model.ts`：编辑草稿、字段顺序、类型切换和请求构造。
- `validation.ts`：长度、唯一性、默认值、候选项、单位和目录字段上限校验。
- `presentation.ts`：字段类型中文标签、时间、指标和 API 错误文案。
- 组件只接收数据并发出事件，不直接请求 API；复杂编辑状态由页面或专用模型持有。

## 建议实施顺序

1. 补齐分类与物品属性模板 API client、请求 DTO 和错误类型。
2. 建立双业务域页面骨架、权限入口、本地搜索和稳定异步状态。
3. 完成分类列表、表单和删除流程。
4. 完成物品属性模板列表、详情、复制和差异化删除确认。
5. 完成模板字段编辑模型、类型相关控件、排序和完整校验。
6. 完成响应式样式、键盘/焦点、真实接口和多视口验证。
7. 替换 `/templates` 的 `PlaceholderPage.vue`，同步路由文档与代码地图。

## 验收标准

### 功能

- 两个业务域均读取真实列表，切换后保留各自搜索、内容和滚动位置。
- `stock.template.read` 可查看全部结构；无 `stock.template.manage` 时看不到任何写入口。
- 分类可创建、编辑、排序和删除，名称冲突定位到名称字段。
- 物品属性模板可创建、查看、编辑、复制和删除；复制后自动打开新模板。
- 模板始终包含 1 至 64 个字段，已有字段保存时保留 `definition_id` 和顺序。
- 七种字段类型的默认值、候选项和类型切换均符合 API 规则。
- 物品模板单位规则正确，目录展示字段不超过三个。
- 两类删除确认准确描述各自后果，不显示虚构影响数量。

### 界面

- 列表符合身份、信息、判断与操作三段式；参数名和值有清晰视觉差异。
- 刷新和新增按钮相邻，新增为主题色高频操作图标按钮。
- 后台刷新保留内容和滚动位置，不闪空态、不跳到顶部。
- `1440 × 900`、`1024 × 768`、`390 × 844` 均无意外横向滚动、遮挡或不可达操作。
- 窄屏下数量靠近筛选/操作区域，更新时间完整可见。
- 模板编辑器在桌面为宽工作区、移动端为全屏工作区，底部保存和当前错误始终可达。

### 状态与质量

- 初次加载、后台刷新、空数据、搜索无结果、无缓存错误、有缓存刷新失败均有不同且稳定的呈现。
- 未保存草稿在关闭、Escape、遮罩和移动返回时都受到保护。
- API 迟到响应不会覆盖更新后的列表或新保存数据。
- 纯图标按钮、业务域切换、字段重排和危险确认均可通过键盘完成并具有可读名称。
- 浏览器控制台无 Vue 警告、未处理 Promise、重复 key、横向溢出或焦点陷阱错误。

## 实施验证清单

- 使用真实 core 服务分别验证只读和管理权限账号。
- 对两类资源执行创建、更新、重复名称、删除、并发删除后的 `404` 和权限变化后的 `403`。
- 创建覆盖七种字段类型的模板，验证默认值、候选、单位、目录字段上限和字段重排。
- 删除被物品引用的物品属性模板，确认警告文案与服务端实际破坏性行为一致。
- 在 `1440 × 900`、`1024 × 768`、`390 × 844` 截图审核默认、长名称、长说明、满 64 字段、错误和加载状态。
- 在断点上下各检查一次真实尺寸、滚动宿主、Dialog 内滚动、触控目标、键盘焦点和控制台。
