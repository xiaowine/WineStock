# 业务界面一致性检查清单

本文定义 WineStock 业务页面的 UI/UX 一致性要求。
它适用于多步骤工作流、列表、表格、表单、抽屉、Dialog 和提交确认，不限定具体业务领域。

## 核心原则

### 相同语义使用相同表达

- 同一工作流内，相同层级的标题、字段、输入框、按钮和状态必须复用同一结构与样式。
- 同一页面在侧栏、移动 Header 和页面主标题中使用完全相同的名称；名称由路由目录单点声明，其它位置读取路由元数据，不维护独立文案。
- 页面名称按职责使用稳定格式：总览使用“业务范围 + 总览”，资源维护使用“资源 + 管理”，创建工作台使用“新建 + 业务”，单据与审批使用“业务 + 单”或“业务 + 审批”；不为凑齐字数增加无意义词语。
- 不以“看起来接近”作为验收标准；宽度、高度、间距、颜色和坐标应实际测量。
- 输入框起点相同不代表已经对齐，还必须比较实际宽度、列间距和后置按钮占用空间。
- 只有业务含义不同，视觉表达才允许不同。

### 业务差异不等于视觉割裂

- 浏览步骤可以是只读列表，编辑步骤可以是表格或表单，但两者仍需共享页面框架、物品身份区、密度和控件语言。
- 桌面业务工具优先使用连续列表、表格和分隔线，不在相邻步骤间切换为另一套卡片后台模板。
- 移动端可以使用卡片承载字段，但卡片头部、图片、标题、辅助信息和操作位置应保持一致。

### 只展示有用信息

- 只保留字段名称、当前状态、明确命令和执行操作前必须知道的后果。
- 控件状态已经表达的含义，不再增加重复文字。
- 用户通过一次操作即可理解的规则，不写成功能说明或操作教程。
- 不在用户尚未填写数据时展示容易被误解的推导值，例如未确认单价前的预计金额。

## 多步骤工作流

### 固定页面骨架

同一流程的每个步骤应共享：

- 页面标题和步骤指示器位置。
- 步骤面板边界和标题栏高度。
- 上一步、下一步按钮的容器、尺寸、样式和文案格式。
- 工具栏的背景、边框、内边距和字段起点。

步骤间切换时，导航按钮不应因计数、摘要或提示文字而移动。
动态摘要应放在不会改变主要操作位置的区域，移动端可以直接隐藏非必要摘要。

步骤切换使用稳定尺寸的舞台容器和完整 Vue `Transition`：前进时旧步骤向左退出、新步骤从右进入，返回时方向相反；退出使用快速 motion token，进入使用标准 motion token，并采用 `out-in` 避免两个步骤同时可操作。

### 对称导航

- 使用对称文案，例如“上一步：选择物品”和“下一步：填写单据”。
- 两个按钮应使用相同按钮等级，不混用主按钮和次级按钮。
- 按钮宽高和相对坐标应一致。
- 真正改变业务状态的提交操作才使用主按钮。

## 表单与工具栏

### 页面标题与列表工具栏

- 页面标题区只负责识别当前业务页面和提供必要的页面级上下文，不承载只作用于某个列表或目录的操作。
- 刷新、新建等列表级命令放在对应列表工具栏内，避免一个操作留在列表中、另一个操作漂在页面大标题旁。
- 同级且高频的熟悉操作可以统一为图标按钮；按钮尺寸、边框、背景、颜色、图标线宽和间距必须一致，并提供 `title` 与 `aria-label`。
- 桌面和移动端复用同一组工具栏结构与操作语义，只通过响应式布局调整位置，不维护两套按钮或两套事件逻辑。
- 空状态只说明当前没有数据，不重复展示工具栏已经提供的“新建”命令；搜索无结果时可以保留“清除搜索”这类只属于当前状态的恢复操作。
- 刷新会使当前编辑上下文失效时，干净草稿应关闭编辑器、清除选中并刷新目录；存在未保存修改时必须先确认，不能静默丢弃草稿。
- 工具栏中的动态数量和加载状态不得挤压或移动右侧操作组；对应按钮在桌面、窄桌面和移动端都应保持稳定坐标与尺寸。
- 业务流程需要补建基础资料时，复用基础资料编辑器和保存会话，不嵌套完整管理页面。
- 流程内新建成功后直接消费服务端返回对象完成当前业务动作，不要求用户刷新分页目录后再次查找。
- 共享编辑器必须自己拥有字段、响应式布局和操作区样式，页面样式只能负责编辑器在本页面中的位置与进出场。

### 字段结构

同层级字段统一使用：

```text
字段标题
输入控件
```

不要让一个页面只使用 placeholder，另一个页面使用可见字段标题。
placeholder 只提供输入示例，不能替代字段名称。

### 输入框和操作按钮

- 对应工具栏使用相同的网格列定义。
- 输入框宽度、高度、内边距和焦点状态一致。
- 同位置按钮使用固定宽度，避免文字长度改变输入框宽度。
- 默认按钮的背景、边框、文字色、字号和字重必须一致。
- 可选扩展字段展开后独占下一整行，不挤压主输入框。
- 对应页面应使用相同的字段标题结构，不能一处只有 placeholder、另一处有可见标题。
- 不允许仅统一输入框高度，却保留不同列间距导致实际宽度不同。

推荐结构：

```text
minmax(0, 1fr)  固定宽度操作按钮
可选扩展字段跨越全部列
```

## 列表、表格和物品身份区

### 桌面端

- 浏览型数据优先使用连续列表，编辑型数据使用表格。
- 两者复用相同的物品身份结构：主图、名称、SKU、单位。
- 主图尺寸、行高、文字层级和左右内边距保持一致。
- 列表表头与表格表头使用相同背景、字号和分隔线。
- 列表尾部的加载、错误和到底状态必须跨越全部列。

### 移动端

- 列表项和编辑项复用同一种卡片头部。
- 物品主图、名称、辅助信息和右侧操作保持相同位置。
- 编辑页面只是在相同卡片头部下增加字段，不另建一套身份布局。
- 卡片圆角不超过 `8px`，避免消费级大圆角和过度留白。

### 选中状态

- 选中属于交互状态，使用项目主强调色，不使用成功绿色。
- 可以使用浅强调背景和左侧细强调条。
- 图标按钮背景应与所在选中容器协调，避免出现突兀的白色嵌块。
- 成功色只表示业务成功，不用于普通选择。

## 图标和操作

- 熟悉的加入、移除、关闭等操作优先使用图标按钮。
- 图标统一使用单色线性语言、圆端点和相同线宽。
- 图标按钮必须提供 `aria-label` 和悬浮提示。
- 同一控件的两个状态应使用成对图标，例如加号与减号。
- 明确命令或高风险操作继续使用文字按钮，不强行图标化。
- 控件本身已经完成确认时，不再增加重复确认按钮。例如颜色选择完成后可直接生成纯色图片。

## 互斥输入模式

- 同一字段存在多个互斥来源时，使用分段控件、单选项或锚定选择浮层等明确的单选结构。
- 每次只展示当前操作需要的控件，不在主表单中同时铺开多套来源操作。
- 模式切换不应立即销毁已有值；用户完成新选择后再替换当前值。
- 删除当前值后保留用户选择的输入模式，避免操作上下文突然跳回默认模式。
- 两种模式应转换为同一种稳定草稿或请求结构，后续上传和提交逻辑不分叉。
- 共用字段组件必须自己拥有预览、错误态、模式选择和操作按钮样式，不能依赖某个业务页面的 SCSS。

图片字段推荐结构：

```text
未选择：选择图片 -> 本地图片 | 纯色图片
已选择：可点击的图片预览（更换） + 删除图标
```

图片来源可以收敛到从触发控件打开的锚定浮层：选择本地图片时直接打开文件选择器，选择纯色图片时只显示项目自有的 HSV/HEX 颜色控件，避免不同 WebView 的原生颜色选择器产生不一致体验。颜色变更后直接生成图片，不再显示额外的“生成”按钮。浮层关闭后焦点返回触发控件，已选择状态仍需保留直接更换入口，不能要求用户先删除再重新选择。

## 状态反馈

### Notice

- 成对操作必须成对反馈，例如加入和移除都显示 Notice。
- 草稿选择不属于业务成功，使用信息型 Notice，不使用成功型 Notice。
- 只有服务端提交完成、库存确实变化等结果才使用成功提示。
- 字段校验优先使用字段高亮、错误提示和自动聚焦，不重复增加常驻状态标签。

### 加载和分页

- 初始加载、空状态、分页加载、分页错误和到底状态应有稳定位置。
- 分页尾部状态不能占用普通数据单元格或随着列数漂移。
- 异步提示遵循 `async-state-transitions.md` 的防闪烁规则。

## 抽屉、Dialog 和浮层

- 当列表浏览是页面主任务、编辑只是临时上下文时，桌面端应让列表保持全宽，并通过 Dialog 完成新建或编辑；不要为了尚未发生的编辑长期预留空白列。
- 同一业务的新建与编辑应复用同一个 Dialog 外壳、表单组件和操作区，只改变草稿与标题语义。
- Dialog 必须复用项目通用遮罩、标题栏、关闭按钮、内容滚动区、底部操作区和 motion token，不另写一套近似弹窗。
- 大型表单 Dialog 仍由 Dialog 内容区单独滚动，页面目录和 Dialog 标题、操作区不得随表单内容滚动。
- Dialog 关闭后清除只属于本次编辑的列表选中态，并把焦点返回打开它的列表项或工具栏按钮。

- 抽屉打开和关闭必须使用完整的 Vue `Transition`，关闭时不能立即卸载。
- 遮罩与面板使用同一 motion token。
- 桌面抽屉从来源方向小幅进入并原路退出。
- 移动端全屏面板从下方进入并退出。
- Escape、遮罩、关闭图标和完成按钮应产生一致的关闭结果。
- 关闭后焦点返回触发按钮。
- 抽屉主标题描述当前任务，物品名称、SKU 和单位属于辅助上下文，不能反转标题层级。
- 抽屉内字段继续遵循“标题在上、控件在下”的表单结构，模板选择器也不例外。
- 属性分组优先使用标题、间距和分隔线，不在抽屉中堆叠灰色卡片。
- 桌面抽屉宽度应保留足够的原页面上下文，不因少量短字段占据大部分工作区。
- 移动端全屏抽屉保持单列字段和底部主操作，不照搬桌面双列布局。

## 响应式要求

- 桌面和移动端共享业务状态与操作语义，不维护两套业务逻辑。
- 移动 Shell 已显示路由标题时，页面内部不重复展示同名大标题。
- 常驻双栏编辑可以保留当前列表选中项；Dialog、抽屉或移动全屏编辑关闭后应清除仅用于临时编辑上下文的选中态，避免用户误以为目录仍处于选择模式。
- 移动端底部提交栏必须预留安全区和内容底部空间。
- 固定操作栏不能遮挡最后一条数据或字段。
- 每个目标视口都要检查横向溢出和长文本截断。

## 业务逻辑与 UI

- UI 约束必须和当前业务规则一致，不能仅因为后端支持某种请求就开放对应操作。
- 更新接口区分“字段缺失”和显式 `null` 时，前端只发送真正变化的字段；需要清空的可空字段显式发送 `null`，不能每次把完整快照重新提交。
- 模板字段的必填、类型和候选项必须来自服务端模板定义；必填字段在提交前由表单阻止，模板选项使用受控选择器，不能把后端枚举规则退化成任意文本输入。
- 模板已经拥有字段名称和类型时，编辑表单只显示字段名称对应的值控件及必要单位，不再重复展示可编辑的“属性名称”和“类型”；只有自定义属性使用完整结构。
- 单位控件同样由模板规则决定：`none` 不展示，`fixed` 作为值控件后缀只读展示，`select` 使用受控选择器，只有 `custom` 使用自由输入；不要给每个模板属性机械添加单位输入框。
- 恢复旧草稿时，应重新应用当前 UI 约束，例如按业务唯一键去重。
- 混合计量单位不能合并成带错误单位的总数量。
- 高风险操作需要确认对话框，普通可逆选择不增加确认步骤。

## 验收方法

### 必查视口

- 桌面：`1440 × 900`。
- 窄桌面或平板：接近 `768px` 断点的桌面宽度。
- 移动：`390 × 844`。

### 必查状态

- 空数据、初始加载、加载失败、分页加载、分页失败和已加载全部。
- 未选择、已选择、加入、移除和清空。
- 字段完整、字段错误和服务端结构化错误。
- 抽屉或 Dialog 的打开、关闭动画和焦点恢复。
- 普通提交、直接生效操作和确认对话框。
- 长名称、长 SKU、混合单位和多条数据。

### 量化检查

不要只依赖截图目测。使用浏览器读取 `getBoundingClientRect()`，比较对应元素：

- `x`、`y`。
- `width`、`height`。
- 工具栏高度和内边距。
- 输入框与按钮的实际宽度。
- 计算后的背景、边框、文字色、字号和字重。
- 抽屉或 Dialog 的 `clientWidth` 与 `scrollWidth`，确认内部控件没有撑开面板。
- 互斥模式切换后，非当前模式控件是否已从 DOM 中移除。

同一层级控件的预期差值应为 `0`。

### 完成门槛

- `pnpm build` 通过。
- `git diff --check` 通过。
- 浏览器控制台无新增错误、警告或页面自身审计问题。
- 桌面和移动端没有横向溢出。
- 代码注释为中文，且没有过时的试验页说明。

## 常见反例

- 一个步骤使用卡片网格，下一步骤突然使用另一套表格视觉。
- 两个字段起点相同，但实际输入框宽度、列间距或按钮样式不同。
- 两个后置按钮高度相同，但宽度、边框、文字色或悬浮状态不同。
- 动态计数放在导航按钮旁，导致两个步骤的按钮位置变化。
- 按钮已经表达选中状态，旁边仍重复显示“已加入”。
- 未填写价格时展示预计金额。
- 选择项使用成功绿色，混淆交互状态和业务成功。
- 只实现抽屉进入动画，关闭时直接移除 DOM。
- 列表页面默认保留一个空编辑列，导致主要浏览区域长期被无效压缩。
- 同一业务的新建使用 Dialog、编辑使用页面内嵌表单，造成关闭行为和操作区不一致。
- 抽屉用物品名作为主标题，却把当前编辑任务放在弱化小字中。
- 抽屉里的模板选择器使用横向标题，其它字段却使用纵向标题。
- 属性区、字段区和图片预览连续套用边框与灰色背景，形成卡片套卡片。
- 文件选择、颜色选择和生成按钮同时出现，却没有明确的互斥来源状态。
- 颜色控件已经完成选择后，仍要求点击额外的“生成”按钮。
- 共用组件的关键样式写在单一业务页面中，导致其它页面使用时控件没有样式。
- 只检查构建结果，不检查真实浏览器坐标、溢出和控制台。

## 入库工作台落地摘要

本轮入库工作台改造形成了以下可复用结论：

- 两个步骤共享相同页面骨架、步骤导航和工具栏结构。
- “上一步”和“下一步”按钮使用相同尺寸、样式和固定位置。
- 搜索物品与入库来源统一为可见字段标题、等宽输入框和固定宽度后置按钮。
- 桌面物品选择从卡片网格改为与入库明细一致的连续列表。
- 移动端选择项和编辑项共享同一种物品身份卡片头部。
- 选中状态使用项目酒红强调色，不再使用成功绿色。
- 加入和移除使用成对图标和成对信息型 Notice，不增加重复状态文字。
- 未确认数量和价格前不展示误导性的汇总值。
- 明细校验通过提交时的字段高亮、Notice 和自动聚焦反馈，不常驻展示“完整/待补充”。
- 批次与属性抽屉使用任务标题为主、物品身份为辅的标题层级。
- 模板方案、批次号和有效期使用相同的纵向字段结构。
- 抽屉内属性区域使用分隔线分组，删除嵌套卡片背景。
- 桌面抽屉收窄以保留表格上下文，移动端继续使用单列全屏面板。
- 图片字段使用单一选择入口打开“本地图片/纯色图片”锚定浮层，颜色变化后立即生成纯色图；选中后图片本身承担放大查看入口，更换继续使用相邻的明确操作区域，删除使用独立图标，三种操作不能互相抢占点击语义。
- 图片字段的预览、错误态和按钮样式由共用组件自己维护。
- 所有关键一致性问题均通过浏览器坐标、计算样式、溢出和控制台检查验证。

## 物品目录工具栏落地摘要

本轮物品管理页面调整补充了以下可复用结论：

- 页面大标题只保留“物品”及必要上下文，不再放置只作用于物品目录的创建入口。
- 刷新与新建统一进入物品目录工具栏，并使用同尺寸、同边框、同背景和同线性图标语言的图标按钮。
- 桌面、窄桌面和移动端复用同一组刷新/新建控件，避免移动端单独维护文字按钮。
- 空目录不再重复显示“新建物品”；搜索无结果仍保留“清除搜索”，因为它只用于恢复当前筛选状态。
- 刷新目录会同步关闭干净编辑器并清除选中；存在未保存修改时先显示放弃确认。
- 验收实际比较了按钮 `x`、`y`、`width`、`height`、间距和计算样式，并检查三档视口横向溢出与浏览器控制台。

## 物品编辑 Dialog 落地摘要

- 桌面物品页默认让目录占满工作区，不再显示窄目录、空编辑列或常驻双栏。
- 点击目录项和点击新建使用同一个 `ItemEditorDialog`，共享字段、校验、图片、属性和底部操作区。
- `ItemEditorDialog` 组合通用 `ModalDialog`，复用项目现有遮罩、关闭动画、Escape、焦点进入和焦点返回行为。
- 移动端继续使用同一 Dialog 和同一业务状态，仅由通用 Dialog 的响应式样式切换为底部面板，不维护独立编辑页面。
- Dialog 打开期间保留背景目录和分页结果；保存后的目录刷新继续保留现有内容，只显示稳定的局部刷新反馈。
- 新建或编辑保存成功后关闭 Dialog 并返回目录，与其它管理 Dialog 的完成行为保持一致。
- 编辑请求按 OpenAPI 部分更新语义只发送变化字段；未修改属性时不触发属性整体替换，未更换主图时不重复提交主图 ID。
- 属性模板的必填标记和 select 候选项直接使用服务端模板元数据，必填值缺失时由表单定位对应控件，不再提交后只显示笼统的请求无效。
- 模板属性只呈现模板字段名和受类型约束的值控件，不显示冗余的属性名称、属性类型或逐项删除按钮；自定义属性仍可编辑名称、类型和值。
- 打开已有物品时必须把当前模板中未持久化的空字段补入编辑草稿，不能要求用户切换一次模板才能看到完整字段；补齐后的编辑草稿和基线草稿保持一致，不能因此产生虚假的未保存状态。
- 物品编辑 Dialog 的模板属性与自定义属性使用独立分组；添加入口只属于自定义属性，不能让用户误以为模板字段可以逐项增删。
- 表单输入不因 Dialog 剩余宽度而机械拉满：基础资料、模板属性和自定义属性必须使用同一列系统，桌面统一三列；常规手机使用两列，较宽移动端或平板使用三列，只有极窄视口才回落单列；长描述保持整行，主图作为特殊字段独立于普通输入列。
- 模板属性的视觉结构直接复用基础资料表单：标签高度、控件高度和行列间距一致，字段容器不增加逐项内边距、底边框、卡片背景或重复分隔线；模板与自定义属性只在分组边界使用一次分隔。
- 关闭 Dialog 后清空草稿和目录选中态；存在未保存修改时先显示统一放弃确认。
