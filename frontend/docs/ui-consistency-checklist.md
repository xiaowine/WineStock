# 业务界面一致性检查清单

本文定义 WineStock 业务页面的 UI/UX 一致性要求。
它适用于多步骤工作流、列表、表格、表单、抽屉、Dialog 和提交确认，不限定具体业务领域。

本文的主要职责是实施约束和量化验收。
新增或重构页面应先按 [`ui-design-guidelines.md`](ui-design-guidelines.md) 选择页面结构与交互模式，再使用本文检查业务状态、响应式尺寸、动效边界和浏览器实际结果。
文末落地摘要记录已有页面经验，不得覆盖 `ui-design-guidelines.md` 中的项目级规则。

## 核心原则

### 相同语义使用相同表达

- 同一工作流内，相同层级的标题、字段、输入框、按钮和状态必须复用同一结构与样式。
- 同一页面在侧栏、移动 Header 和页面主标题中使用完全相同的名称；名称由路由目录单点声明，其它位置读取路由元数据，不维护独立文案。
- 页面名称按职责使用稳定格式：总览使用“业务范围 + 总览”，资源维护使用“资源 + 管理”，创建工作台使用“新建 + 业务”，单据与审批使用“业务 + 单”或“业务 + 审批”；不为凑齐字数增加无意义词语。
- 不以“看起来接近”作为验收标准；宽度、高度、间距、颜色和坐标应实际测量。
- 输入框起点相同不代表已经对齐，还必须比较实际宽度、列间距和后置按钮占用空间。
- 只有业务含义不同，视觉表达才允许不同。

### 业务差异不等于视觉割裂

- 浏览步骤可以是只读列表，编辑步骤可以是表格或表单，但两者仍需共享页面框架、物品身份区、密度和控件语言。
- 桌面业务工具优先使用连续列表、表格和分隔线，不在相邻步骤间切换为另一套卡片后台模板。
- 移动端可以使用卡片承载字段，但卡片头部、图片、标题、辅助信息和操作位置应保持一致。

### 只展示有用信息

- 只保留字段名称、当前状态、明确命令和执行操作前必须知道的后果。
- 控件状态已经表达的含义，不再增加重复文字。
- 用户通过一次操作即可理解的规则，不写成功能说明或操作教程。
- 不在用户尚未填写数据时展示容易被误解的推导值，例如未确认单价前的预计金额。

### 稳定骨架与最小变化

- 页面状态变化必须优先保留已经建立的页面骨架，只更新真正发生变化的控件、数字、数据行或局部反馈。
- 不得因为搜索、筛选、排序、刷新或结果数量变化而替换整套页面结构、切换视觉体系或增加无业务必要的中间状态面板。
- 动画的作用范围必须与状态变化范围一致：工作流步骤可以切换完整舞台，异步刷新只反馈局部等待，数字变化只动画数字文字。
- 列表页面的完整强制规则见“列表页面稳定性与最小变化规则”；后续新增或重构列表、目录、管理页时必须逐项执行。

### 共享组件、控件与浮层

- 相同业务语义必须使用同一个共享组件。输入框、选择框、搜索框、密码框、Dialog、图标按钮和图片字段不得在业务页面中重复实现近似版本。
- 共享控件必须覆盖默认、悬浮、焦点、展开、选中、禁用、错误、加载和移动端状态；只统一静态边框和颜色不算完成复用。
- 页面样式只负责控件的网格位置、可用宽度、业务密度和响应式重排。边框、背景、圆角、文字内边距、图标、焦点环、错误态、禁用态和开关动画由共享组件拥有。
- 普通业务组件不得直接使用原生 `<select>`。标准表单选择使用 `FormSelect`，已有字段外壳、工具栏、表格和复合控件使用底层 `SelectControl`。
- 项目选择框保留 `combobox`、`listbox`、`option` 等无障碍语义以及方向键、Enter、Space、Escape、Tab 和焦点返回能力，但关闭和展开外观统一由项目组件渲染，不使用浏览器或 WebView 原生下拉菜单。
- 选中项通过 `aria-selected`、选中背景、强调文字和字重表达，不在选项尾部放置占用内容宽度的勾选图标；弹出选项沿用触发框的实际字号和行高，文字单行占满按钮的全部可用宽度，超出后省略，不由浏览器自动换行撑高选项。
- 选择框浮层默认与触发框实际宽度相同；最长选项无法完整显示时，浮层只扩展到内容需要的最小宽度，并受 `320px` 与视口安全边界限制。触发框宽度和相邻字段列宽不得因此改变，达到浮层上限后才截断长选项。
- 锚定浮层必须根据可用视口空间决定向上或向下展开，并限制最大高度；在桌面、移动端和 Dialog 内都不得超出视口或产生页面级横向滚动。
- Dialog、抽屉或滚动容器内的选择列表、菜单和 Popover 使用 `Teleport` 进入统一浮层层级，高于 Dialog、低于全局 Notice，不得被父级 `overflow` 裁剪。
- 浮层内按 Escape 只关闭当前浮层并把焦点还给触发控件，不得继续冒泡并关闭所属 Dialog 或抽屉。
- 自定义选择控件必须保留业务绑定值的原始类型。数字、布尔值、`null` 和 `undefined` 不得在选择后被隐式转换为显示文案或普通字符串。
- 桌面和移动端复用同一控件与业务状态，只通过网格和宽度规则调整排布。常见移动宽度下应优先压缩短控件以保留同一行操作；极窄屏确实无法容纳时才回退换行。

### SCSS 结构与能力验收

- 新增或重构的 `.scss` 文件使用 `@use` 管理依赖，不新增 `@import`，也不依赖未声明的 Sass 变量或 mixin。
- BEM 元素、修饰符、状态伪类和直接子元素使用 `&` 嵌套；跨组件上下文、Teleport 宿主和无父子语义的选择器才允许显式平铺。
- 通用断点、触控媒体条件、焦点环、SVG 图标和减少动效规则复用 `foundation/_mixins.scss`，不重复散落固定断点媒体查询。
- 运行时视觉 token 使用 CSS 自定义属性；Sass 变量、map、`@each` 和占位选择器只用于编译期结构或确实重复的规则族。
- 嵌套表达组件关系而不是任意 DOM 深度；新增选择器不得形成超过三层的深链，也不能为了使用嵌套改变原有 specificity 或跨组件所有权。
- 共享控件的边框、焦点、错误、禁用和动效仍由共享层拥有，业务页面只补布局、密度和响应式重排。

提交前逐项确认：

- [ ] 变更文件的依赖通过 `@use` 明确声明。
- [ ] 可嵌套的 BEM 元素、修饰符和状态没有继续重复完整选择器。
- [ ] 没有新增重复断点、图标骨架或运行时 token；必要抽象已复用共享 mixin。
- [ ] `rg` 检查没有新增 `@import`、未声明变量或超过三层的深链选择器。
- [ ] `pnpm build` 通过，且编译没有 Sass warning。
- [ ] `git diff --check` 通过，中文职责注释和样式所有权说明仍然准确。
- [ ] 桌面 `1440 × 900`、接近 `768px` 断点和移动 `390 × 844` 的真实尺寸、横向溢出、状态和控制台结果已复核。

## 多步骤工作流

### 固定页面骨架

同一流程的每个步骤应共享：

- 页面标题和步骤指示器位置。
- 步骤面板边界和标题栏高度。
- 上一步、下一步按钮的容器、尺寸、样式和文案格式。
- 工具栏的背景、边框、内边距和字段起点。

步骤间切换时，导航按钮不应因计数、摘要或提示文字而移动。
动态摘要应放在不会改变主要操作位置的区域，移动端可以直接隐藏非必要摘要。

步骤切换使用稳定尺寸的舞台容器和完整 Vue `Transition`：前进时旧步骤向左退出、新步骤从右进入，返回时方向相反；退出使用快速 motion token，进入使用标准 motion token，并采用 `out-in` 避免两个步骤同时可操作。

### 对称导航

- 使用对称文案，例如“上一步：选择物品”和“下一步：填写单据”。
- 两个按钮应使用相同按钮等级，不混用主按钮和次级按钮。
- 按钮宽高和相对坐标应一致。
- 真正改变业务状态的提交操作才使用主按钮。

## 表单与工具栏

### 页面标题与列表工具栏

- 页面标题区只负责识别当前业务页面和提供必要的页面级上下文，不承载只作用于某个列表或目录的操作。
- 刷新、新建等列表级命令放在对应列表工具栏内，避免一个操作留在列表中、另一个操作漂在页面大标题旁。
- 同级且高频的熟悉操作可以统一为图标按钮；按钮尺寸、边框、背景、颜色、图标线宽和间距必须一致，并提供 `title` 与 `aria-label`。
- 桌面和移动端复用同一组工具栏结构与操作语义，只通过响应式布局调整位置，不维护两套按钮或两套事件逻辑。
- 空状态只说明当前没有数据，不重复展示工具栏已经提供的“新建”命令；搜索无结果时可以保留“清除搜索”这类只属于当前状态的恢复操作。列表页面的零条结果呈现与例外边界以“列表页面稳定性与最小变化规则”为准。
- 刷新会使当前编辑上下文失效时，干净草稿应关闭编辑器、清除选中并刷新目录；存在未保存修改时必须先确认，不能静默丢弃草稿。
- 工具栏中的动态数量和加载状态不得挤压或移动右侧操作组；对应按钮在桌面、窄桌面和移动端都应保持稳定坐标与尺寸。
- 业务流程需要补建基础资料时，复用基础资料编辑器和保存会话，不嵌套完整管理页面。
- 流程内新建成功后直接消费服务端返回对象完成当前业务动作，不要求用户刷新分页目录后再次查找。
- 共享编辑器必须自己拥有字段、响应式布局和操作区样式，页面样式只能负责编辑器在本页面中的位置与进出场。
- Dialog 内通过 `Teleport` 挂载到页面根部的 Popover 必须使用高于 Dialog、低于全局 Notice 的统一层级 token，不能因脱离 Dialog DOM 后落到遮罩或面板下方。

### 字段结构

同层级字段统一使用：

```text
字段标题
输入控件
```

不要让一个页面只使用 placeholder，另一个页面使用可见字段标题。
placeholder 只提供输入示例，不能替代字段名称。

- 普通输入、选择和多行文本优先复用通用字段组件，由组件统一标题、必填标记、提示、红框错误状态、不占布局的无障碍错误说明、`aria-invalid` 和首错定位注册。
- 同一表单网格中的输入框和选择框必须占满相同网格列；实际 `x`、`width` 和高度应一致，不能为短选项单独限制选择框宽度，造成与下一字段之间出现额外空白。
- 图片、颜色、单位等复杂控件放入通用字段外壳，不复制字段标题和错误结构。
- 组件只负责错误如何呈现和定位；必填、跨字段、重复性、模板约束及服务端错误映射仍由所属业务模型或提交会话负责。

### 输入框和操作按钮

- 对应工具栏使用相同的网格列定义。
- 输入框宽度、高度、内边距和焦点状态一致。
- 同行选择框与输入框使用相同列宽和控件高度；选项内容多少不得改变控件外部宽度或字段间距。
- 同位置按钮使用固定宽度，避免文字长度改变输入框宽度。
- 默认按钮的背景、边框、文字色、字号和字重必须一致。
- 可选扩展字段展开后独占下一整行，不挤压主输入框。
- 对应页面应使用相同的字段标题结构，不能一处只有 placeholder、另一处有可见标题。
- 不允许仅统一输入框高度，却保留不同列间距导致实际宽度不同。

推荐结构：

```text
minmax(0, 1fr)  固定宽度操作按钮
可选扩展字段跨越全部列
```

## 列表页面稳定性与最小变化规则

本节是 WineStock 后续列表、目录、表格管理页的强制设计约束。
适用于物品、用户、库位、分类与模板、单据、审批、审计记录等以浏览、搜索、筛选、分页和管理集合数据为主的页面。
除非页面文档明确记录业务原因和替代验收方案，否则不得偏离本节规则。

本节使用以下规范关键词：

- “必须”“不得”是验收阻断项；实现不满足时不能以视觉接近、单页特例或开发成本为由通过评审。
- “应”“优先”是默认实现；偏离时必须证明现有组件或模式无法满足业务语义，并按本节例外流程记录。
- “可以”“允许”只表示在列出的前提下可选，不代表可以绕过其它强制条款。
- 页面专属文档只能补充业务约束，不能静默放宽本节规则；确需放宽时必须同时更新本清单中的例外或适用范围。

### 页面骨架与职责

标准列表页面按以下职责组织：

```text
页面标题与必要上下文
列表工具栏：搜索、筛选、排序、数量、刷新、新建
结果区域：桌面表格或连续列表 / 移动列表
列表尾部：分页加载、分页失败、继续加载、已加载数量
临时操作：Dialog、抽屉或移动操作面板
```

- 页面标题区只识别业务页面，不承载仅作用于当前列表的刷新、新建、筛选和排序命令。
- 工具栏、结果区域和列表尾部必须保持稳定顺序；搜索、筛选、排序和刷新不得把它们替换成另一套页面结构。
- 页面负责请求、筛选、分页和业务操作编排；搜索框、选择框、图标按钮、字段和 Dialog 外壳必须优先复用现有共享组件。
- 桌面与移动端共享同一份业务状态、请求和事件；只允许改变布局和数据呈现方式，不允许维护两套筛选条件、加载状态或操作结果。
- 新增列表页面前必须先检查现有工具栏、选择控件、搜索控件、加载尾部和管理 Dialog，不得为相同语义复制局部实现。

### 控件选择与统一表达

- 具有字段含义的筛选条件使用选择框、搜索框、日期控件等字段控件；不能因为候选项较少就临时改成 tab。
- tab 只用于切换相对稳定的内容页或工作区；分段控件只用于高频互斥模式，不用于普通数据字段筛选。
- 项目已有同类选择控件时必须复用其高度、箭头、边框、焦点和禁用状态，不能直接新增一套近似原生 `select` 样式。
- 熟悉且高频的刷新、新建、设置等命令使用统一线性图标按钮；文字按钮保留给需要明确命令名称、提交后果或风险等级的操作。
- 图标按钮必须提供 `title` 和 `aria-label`，并保持同一尺寸、线宽、边框、背景、悬浮和禁用状态。
- 同一工具栏中的搜索、筛选和排序控件必须按字段底边对齐；数量、刷新和新建组成稳定操作组，不得因动态文字改变坐标。

### 状态模型

列表页面必须显式区分以下状态，不得只依赖 `items.length` 推断所有语义：

- `首次加载`：尚未获得任何可用结果。
- `已有结果`：当前查询返回一条或多条数据。
- `零条结果`：当前查询成功，但数据总数为 `0`。
- `后台刷新`：已经存在可用结果或已完成首次查询，正在重新查询第一页。
- `分页加载`：保留已加载结果，正在追加下一页。
- `初始失败`：首次查询失败，没有可安全展示的旧结果。
- `刷新失败`：重新查询失败，但仍有上一次成功结果可保留。
- `分页失败`：下一页失败，已加载页仍然有效。

实现至少应拥有等价于以下状态的数据来源：

```text
items / total / page / totalPages
loading / loadingMore
hasLoadedOnce
loadError / loadMoreError
activeSearch / activeFilters / activeSort
```

不得通过清空 `items` 来表示后台刷新，也不得把请求是否 pending 与是否显示等待反馈绑定为同一个状态。

### 各状态的固定呈现

| 业务状态 | 必须保留 | 结果区域 | 列表尾部 | 禁止行为 |
| --- | --- | --- | --- | --- |
| 首次加载 | 页面标题、工具栏边界或稳定占位 | 显示固定位置的加载状态 | 可暂不显示 | 短暂显示“0 条”或空状态后再跳到数据 |
| 已有结果 | 完整页面骨架 | 渲染桌面数据结构和移动列表 | 显示继续加载或已加载数量 | 额外显示重复的“有数据”状态面板 |
| 查询成功且零条结果 | 页面标题、工具栏、结果容器、列表尾部 | 隐藏没有数据意义的表格、表头和移动空列表 | 显示“已加载全部 0 个…” | 保留空表头、创建第二套空状态页面或重复新建入口 |
| 后台刷新 | 当前工具栏、旧结果、滚动上下文 | 继续展示上一次成功结果 | 保留原分页提示，成功后更新 | 请求开始即清空列表或切换全屏加载 |
| 分页加载 | 已加载结果 | 保持原行不变 | 在固定尾部显示加载状态 | 用新加载状态覆盖已有列表 |
| 初始失败 | 页面标题、工具栏或稳定错误容器 | 不展示伪造旧数据 | 提供明确重试入口 | 把错误显示成空数据 |
| 刷新失败 | 上一次成功结果 | 保留旧结果 | 恢复原尾部状态并使用 Notice 报错 | 隐藏旧结果或显示“0 条” |
| 分页失败 | 已加载结果 | 保持原行不变 | 在尾部提供重试 | 清空已加载页或回到第一页 |

专门空状态只在以下情况允许使用：

- 该业务集合从未建立，且用户需要理解如何开始。
- 当前状态需要一个列表尾部无法承载的恢复操作或关键解释。
- 安全、权限或业务前置条件使普通列表结构不再成立。

即使允许专门空状态，也不得重复工具栏已有的“新建”命令；搜索或筛选零结果默认不属于需要专门空状态的情况。

### 请求与数据替换规则

- 搜索、筛选、排序和手动刷新必须请求第一页；成功后用新第一页整体替换旧结果并重建分页状态。
- 请求进行期间必须保留旧结果、旧总数和旧分页状态，直到新请求成功；失败时继续使用旧状态。
- 新的搜索、筛选或排序请求必须取消旧请求，旧请求的主动取消不显示错误、Notice 或断连状态。
- 分页请求只允许追加并按业务唯一标识去重，不能覆盖第一页，也不能与第一页刷新并发修改同一列表。
- 筛选、刷新、创建、删除或状态更新成功后需要重建分页时，仍然遵守“请求期间保留、成功后替换”的规则。
- 服务端拥有筛选、排序和总数时，前端不得从当前已加载页自行推导总数、筛选计数或分页结论。

### 数量、尾部状态与文字变化

- 工具栏数量是当前查询结果的紧凑摘要；列表尾部负责分页进度、失败恢复和“已加载全部”结论，二者职责不得混用。
- 动态数量必须预留稳定宽度并使用等宽数字，数量位数变化不能挤压刷新、新建或其它操作。
- 数量变化允许使用带 `key` 的短促文字过渡：旧文字向上淡出，新文字从下方淡入；不得因此动画整个工具栏、表格或页面。
- 数量文字使用快速 motion token；不得为等待动画人为延迟请求或延迟数据更新。
- 同一列表的数量与分页状态只保留一个承担动态播报的 `aria-live` 区域；顶部摘要和底部状态不能同时播报同一次数量变化，全局 Notice 不受此限制。
- 零条结果必须让顶部摘要与底部结论同时使用服务端成功响应的 `0`，不能保留旧数量或显示临时推导值。

### 加载反馈与动画边界

动画必须服从以下层级：

1. 工作流步骤、Dialog、抽屉和真正的内容页切换可以使用完整进入与离开动画。
2. 列表搜索、筛选、排序和刷新只使用局部等待反馈，不对结果区域做整块 `out-in` 切换。
3. 数量、状态标签和按钮 pending 等小范围变化只动画对应元素。

- 后台刷新复用 `useStablePendingIndicator` 或等价稳定呈现层，默认延迟显示 `200ms`、最短展示 `350ms`。
- 快速完成的请求不显示刷新动画；一旦刷新反馈出现，必须满足最短展示时间，避免闪光。
- 稳定刷新反馈可以弱化旧列表、改变刷新图标状态或显示紧凑文字，但不能阻断浏览和滚动。
- 请求状态必须即时更新，禁止通过 `setTimeout`、固定等待或延迟响应来配合动画。
- 所有过渡使用项目 motion token；`prefers-reduced-motion` 只压缩视觉动画，不跳过状态正确性、延迟显示和最短展示规则。
- 普通结果数量变化、非空与零条结果切换不得增加整表淡入淡出、页面滑动或专门空状态切换动画。

### 零条结果规则

- 查询成功且总数为 `0` 时，桌面表格、表头、固定列和移动列表必须从 DOM 中移除。
- 页面继续保留工具栏、筛选条件、刷新入口、创建入口和固定列表尾部。
- 列表尾部显示“已加载全部 0 个…”；不得同时显示“没有符合条件的数据”、空表头和 `0` 数量三套重复信息。
- 如果零结果由筛选产生，用户通过当前筛选控件即可恢复，不额外增加重复的“调整筛选”说明。
- 如果产品确实需要“清除搜索”或“重置筛选”快捷操作，该操作属于尾部或工具栏的状态恢复命令，不得演变成另一套空状态页面。
- 桌面与移动端使用同一零结果语义；不能桌面隐藏表格、移动端却保留空卡片容器。

### 响应式与布局稳定性

- 桌面、接近 `768px` 断点和移动端必须使用相同筛选值、总数和分页状态。
- 响应式只允许改变工具栏换行、字段宽度、表格与卡片呈现、文字提示显隐，不允许改变操作语义。
- 移动端筛选控件应保持触控尺寸，单个字段不应无理由靠右悬空；工具栏换行后仍需保持字段标题与控件关系。
- 零条结果隐藏桌面表格和移动列表后，列表尾部不得因负边距、固定宽度或空容器产生横向溢出。
- 数量动画期间工具栏高度、操作组坐标和列表尾部高度不得变化。

### 可访问性

- 搜索、筛选和图标按钮必须拥有可访问名称；选择框使用真实字段标题或正确关联的隐藏标签。
- 结果区域在请求期间使用 `aria-busy`，但不能把仍可浏览的旧结果从可访问树中移除。
- 首次加载使用礼貌状态播报，明确错误使用 `alert`；主动取消请求不播报失败。
- 列表尾部是分页和最终数量的默认动态播报区域；同一次更新不得由顶部数量再次重复播报。
- 数量过渡完成后 DOM 中只能保留当前数字，不能为动画长期保留两个可读副本。
- 筛选更新不得抢夺焦点；结果更新后焦点保留在当前筛选控件、操作按钮或原有浏览上下文。

### 实施与验收门槛

每个新增或修改的列表页面必须验证：

- 首次加载快速完成和慢速完成。
- 一条或多条结果。
- 搜索或筛选返回零条结果。
- 零条结果恢复为有数据。
- 后台刷新成功和失败。
- 分页加载、分页失败、重试和已加载全部。
- 连续快速修改筛选时旧请求被取消且没有错误提示。
- 数量从非零变为零、零变为非零和位数变化时，操作组位置不移动。
- 桌面表格与移动列表在零条结果时均不在 DOM 中，列表尾部仍可见。
- `1440 × 900`、接近 `768px` 和 `390 × 844` 下没有横向溢出、遮挡或不可达控件。
- 浏览器控制台无新增 error、warning 或 issue。
- `pnpm build` 与 `git diff --check` 通过。

验收不得只看最终截图。必须在请求过程中读取 DOM、`getBoundingClientRect()`、计算样式、`clientWidth`、`scrollWidth`、过渡类和 `aria-busy`，证明页面遵守“稳定骨架、保留旧结果、最小动画、零结果无空结构”的规则。

### 例外与变更流程

- 多步骤选择器、审批工作台、实时监控舞台等不属于普通列表查询的页面，可以使用更完整的状态切换，但必须遵守其领域文档和 motion 规则。
- 列表尾部不足以解释安全限制、权限前置条件或首次建库流程时，可以使用专门状态面板；必须说明为什么现有工具栏和尾部无法表达。
- 新的交互模式只有在至少两个页面存在相同需求时才应提取为共享模式；单页特例先记录在所属页面文档。
- 任何偏离本节的实现都必须在对应页面文档中记录原因、替代行为和验收结果，不能以“这个页面特殊”为默认理由。
- 如果后续产品决策修改本规则，必须同步更新本清单、相关共享组件、页面文档和已有反例，不能只修改单个页面。

## 列表、表格和物品身份区

- 动态模板属性不应各自生成横向表头；使用稳定的“关键属性”复合单元格，各属性纵向排列，单项内部使用“属性名：属性值”的横向结构。
- 同时承担识别与判断的业务列表可以固定左侧身份和右侧决策信息，中间辅助信息允许横向滚动。
- 固定列必须拥有不透明背景、明确边界和稳定宽度，滚动时不得与中间文字叠加。
- 移动端应重组相同信息语义，不得直接缩放桌面表格或制造页面级横向滚动。
- 窄屏筛选条可以横向滑动，但应隐藏原生滚动条并保持触控可达。

### 桌面端

- 浏览型数据优先使用连续列表，编辑型数据使用表格。
- 两者复用相同的物品身份结构：主图、名称、编号、单位。
- 主图尺寸、行高、文字层级和左右内边距保持一致。
- 列表表头与表格表头使用相同背景、字号和分隔线。
- 列表尾部的加载、错误和到底状态必须跨越全部列。

### 移动端

- 列表项和编辑项复用同一种卡片头部。
- 物品主图、名称、辅助信息和右侧操作保持相同位置。
- 编辑页面只是在相同卡片头部下增加字段，不另建一套身份布局。
- 卡片圆角不超过 `8px`，避免消费级大圆角和过度留白。

### 选中状态

- 选中属于交互状态，使用项目主强调色，不使用成功绿色。
- 可以使用浅强调背景和左侧细强调条。
- 图标按钮背景应与所在选中容器协调，避免出现突兀的白色嵌块。
- 成功色只表示业务成功，不用于普通选择。

## 图标和操作

- 熟悉的加入、移除、关闭等操作优先使用图标按钮。
- 图标统一使用单色线性语言、圆端点和相同线宽。
- 图标按钮必须提供 `aria-label` 和悬浮提示。
- 同一控件的两个状态应使用成对图标，例如加号与减号。
- 明确命令或高风险操作继续使用文字按钮，不强行图标化。
- 控件本身已经完成确认时，不再增加重复确认按钮。例如颜色选择完成后可直接生成纯色图片。

## 互斥输入模式

- 同一字段存在多个互斥来源时，使用分段控件、单选项或锚定选择浮层等明确的单选结构。
- 本节只适用于图片来源、录入方式等高频输入模式，不适用于状态、分类等普通列表筛选字段；列表筛选的控件选择以“列表页面稳定性与最小变化规则”为准。
- 每次只展示当前操作需要的控件，不在主表单中同时铺开多套来源操作。
- 模式切换不应立即销毁已有值；用户完成新选择后再替换当前值。
- 删除当前值后保留用户选择的输入模式，避免操作上下文突然跳回默认模式。
- 两种模式应转换为同一种稳定草稿或请求结构，后续上传和提交逻辑不分叉。
- 共用字段组件必须自己拥有预览、错误态、模式选择和操作按钮样式，不能依赖某个业务页面的 SCSS。

图片字段推荐结构：

```text
未选择：选择图片 -> 本地图片 | 纯色图片
已选择：可点击的图片预览（更换） + 删除图标
```

图片来源可以收敛到从触发控件打开的锚定浮层：选择本地图片时直接打开文件选择器，选择纯色图片时只显示项目自有的 HSV/HEX 颜色控件，避免不同 WebView 的原生颜色选择器产生不一致体验。颜色变更后直接生成图片，不再显示额外的“生成”按钮。浮层关闭后焦点返回触发控件，已选择状态仍需保留直接更换入口，不能要求用户先删除再重新选择。

## 状态反馈

### Notice

- 成对操作必须成对反馈，例如加入和移除都显示 Notice。
- 草稿选择不属于业务成功，使用信息型 Notice，不使用成功型 Notice。
- 只有服务端提交完成、库存确实变化等结果才使用成功提示。
- 字段校验统一使用不改变布局的红框、自动聚焦和提交 Notice；具体错误说明保留在无障碍树中，不在字段下方插入可见错误行或重复增加常驻状态标签。
- 业务表单统一使用 `novalidate` 禁用浏览器原生约束气泡；`required`、`min` 和 `pattern` 只保留字段语义，提交边界必须使用项目自己的字段错误或 Notice，不依赖不同浏览器的原生提示文案与外观。

### 加载和分页

- 初始加载、空状态、分页加载、分页错误和到底状态应有稳定位置。
- 分页尾部状态不能占用普通数据单元格或随着列数漂移。
- 异步提示遵循 `async-state-transitions.md` 的防闪烁规则。
- 列表页面还必须遵守“列表页面稳定性与最小变化规则”中的旧结果保留、零条结果、数量动画和验收门槛。

## 抽屉、Dialog 和浮层

- 当列表浏览是页面主任务、编辑只是临时上下文时，桌面端应让列表保持全宽，并通过 Dialog 完成新建或编辑；不要为了尚未发生的编辑长期预留空白列。
- 同一业务的新建与编辑应复用同一个 Dialog 外壳、表单组件和操作区，只改变草稿与标题语义。
- Dialog 必须复用项目通用遮罩、标题栏、关闭按钮、内容滚动区、底部操作区和 motion token，不另写一套近似弹窗。
- 大型表单 Dialog 仍由 Dialog 内容区单独滚动，页面目录和 Dialog 标题、操作区不得随表单内容滚动。
- Dialog 关闭后清除只属于本次编辑的列表选中态，并把焦点返回打开它的列表项或工具栏按钮。

- 抽屉打开和关闭必须使用完整的 Vue `Transition`，关闭时不能立即卸载。
- 遮罩与面板使用同一 motion token。
- 桌面抽屉从来源方向小幅进入并原路退出。
- 移动端全屏面板从下方进入并退出。
- Escape、遮罩、关闭图标和完成按钮应产生一致的关闭结果。
- 关闭后焦点返回触发按钮。
- 抽屉主标题描述当前任务，物品名称、编号和单位属于辅助上下文，不能反转标题层级。
- 抽屉内字段继续遵循“标题在上、控件在下”的表单结构，模板选择器也不例外。
- 属性分组优先使用标题、间距和分隔线，不在抽屉中堆叠灰色卡片。
- 桌面抽屉宽度应保留足够的原页面上下文，不因少量短字段占据大部分工作区。
- 移动端全屏抽屉保持单列字段和底部主操作，不照搬桌面双列布局。

## 响应式要求

- 桌面和移动端共享业务状态与操作语义，不维护两套业务逻辑。
- 移动 Shell 已显示路由标题时，页面内部不重复展示同名大标题。
- 常驻双栏编辑可以保留当前列表选中项；Dialog、抽屉或移动全屏编辑关闭后应清除仅用于临时编辑上下文的选中态，避免用户误以为目录仍处于选择模式。
- 移动端底部提交栏必须预留安全区和内容底部空间。
- 固定操作栏不能遮挡最后一条数据或字段。
- 每个目标视口都要检查横向溢出和长文本截断。

## 业务逻辑与 UI

- UI 约束必须和当前业务规则一致，不能仅因为后端支持某种请求就开放对应操作。
- 更新接口区分“字段缺失”和显式 `null` 时，前端只发送真正变化的字段；需要清空的可空字段显式发送 `null`，不能每次把完整快照重新提交。
- 模板字段的必填、类型和候选项必须来自服务端模板定义；必填字段在提交前由表单阻止，模板选项使用受控选择器，不能把后端枚举规则退化成任意文本输入。
- 模板已经拥有字段名称和类型时，编辑表单只显示字段名称对应的值控件及必要单位，不再重复展示可编辑的“属性名称”和“类型”；只有自定义属性使用完整结构。
- 单位控件由定义规则决定：数字自定义属性在主表单只显示固定高度的单位摘要与设置入口，none/fixed/select 配置和候选项增删放入独立 Dialog；录入时 fixed 作为只读后缀，select 的实际单位选择器与属性值同行，候选数量不能改变属性网格高度。
- 恢复旧草稿时，应重新应用当前 UI 约束，例如按业务唯一键去重。
- 混合计量单位不能合并成带错误单位的总数量。
- 高风险操作需要确认对话框，普通可逆选择不增加确认步骤。

## 验收方法

### 必查视口

- 桌面：`1440 × 900`。
- 窄桌面或平板：接近 `768px` 断点的桌面宽度。
- 移动：`390 × 844`。

### 必查状态

- 空数据、初始加载、加载失败、分页加载、分页失败和已加载全部。
- 未选择、已选择、加入、移除和清空。
- 字段完整、字段错误和服务端结构化错误。
- 抽屉或 Dialog 的打开、关闭动画和焦点恢复。
- 普通提交、直接生效操作和确认对话框。
- 长名称、长编号、混合单位和多条数据。

### 量化检查

不要只依赖截图目测。使用浏览器读取 `getBoundingClientRect()`，比较对应元素：

- `x`、`y`。
- `width`、`height`。
- 工具栏高度和内边距。
- 输入框与按钮的实际宽度。
- 同一网格内输入框与选择框的 `x`、`width` 和高度差值。
- 选择框触发器与展开浮层的实际宽度差值，默认必须为 `0`。
- 浮层的 `top`、`right`、`bottom`、`left` 是否均位于当前可视视口内。
- 计算后的背景、边框、文字色、字号和字重。
- 抽屉或 Dialog 的 `clientWidth` 与 `scrollWidth`，确认内部控件没有撑开面板。
- 互斥模式切换后，非当前模式控件是否已从 DOM 中移除。

同一层级控件的预期差值应为 `0`。

### 完成门槛

- `pnpm build` 通过。
- `git diff --check` 通过。
- 浏览器控制台无新增错误、警告或页面自身审计问题。
- 桌面和移动端没有横向溢出。
- 代码注释为中文，且没有过时的试验页说明。

## 常见反例

- 一个步骤使用卡片网格，下一步骤突然使用另一套表格视觉。
- 两个字段起点相同，但实际输入框宽度、列间距或按钮样式不同。
- 两个后置按钮高度相同，但宽度、边框、文字色或悬浮状态不同。
- 动态计数放在导航按钮旁，导致两个步骤的按钮位置变化。
- 按钮已经表达选中状态，旁边仍重复显示“已加入”。
- 未填写价格时展示预计金额。
- 选择项使用成功绿色，混淆交互状态和业务成功。
- 只实现抽屉进入动画，关闭时直接移除 DOM。
- 列表页面默认保留一个空编辑列，导致主要浏览区域长期被无效压缩。
- 同一业务的新建使用 Dialog、编辑使用页面内嵌表单，造成关闭行为和操作区不一致。
- 抽屉用物品名作为主标题，却把当前编辑任务放在弱化小字中。
- 抽屉里的模板选择器使用横向标题，其它字段却使用纵向标题。
- 属性区、字段区和图片预览连续套用边框与灰色背景，形成卡片套卡片。
- 文件选择、颜色选择和生成按钮同时出现，却没有明确的互斥来源状态。
- 颜色控件已经完成选择后，仍要求点击额外的“生成”按钮。
- 共用组件的关键样式写在单一业务页面中，导致其它页面使用时控件没有样式。
- 选择框关闭状态使用项目样式，点击后却弹出浏览器或 WebView 原生菜单。
- 因选项文字较短而把选择框限制为固定窄宽度，破坏同一表单网格的列宽。
- 选择浮层设置独立最小宽度，导致它比触发框更宽或挤出移动视口。
- 在 Dialog 的选择列表中按 Escape 时同时关闭了选择列表和整个 Dialog。
- 只检查构建结果，不检查真实浏览器坐标、溢出和控制台。

## 入库工作台落地摘要

本轮入库工作台改造形成了以下可复用结论：

- 两个步骤共享相同页面骨架、步骤导航和工具栏结构。
- “上一步”和“下一步”按钮使用相同尺寸、样式和固定位置。
- 搜索物品与入库来源统一为可见字段标题、等宽输入框和固定宽度后置按钮。
- 桌面物品选择从卡片网格改为与入库明细一致的连续列表。
- 移动端选择项和编辑项共享同一种物品身份卡片头部。
- 选中状态使用项目酒红强调色，不再使用成功绿色。
- 加入和移除使用成对图标和成对信息型 Notice，不增加重复状态文字。
- 未确认数量和价格前不展示误导性的汇总值。
- 明细校验通过提交时的字段高亮、Notice 和自动聚焦反馈，不常驻展示“完整/待补充”。
- 批次与属性抽屉使用任务标题为主、物品身份为辅的标题层级。
- 模板方案、批次号和有效期使用相同的纵向字段结构。
- 抽屉内属性区域使用分隔线分组，删除嵌套卡片背景。
- 桌面抽屉收窄以保留表格上下文，移动端继续使用单列全屏面板。
- 图片字段使用单一选择入口打开“本地图片/纯色图片”锚定浮层，颜色变化后立即生成纯色图；选中后图片本身承担放大查看入口，更换继续使用相邻的明确操作区域，删除使用独立图标，三种操作不能互相抢占点击语义。
- 图片字段的预览、错误态和按钮样式由共用组件自己维护。
- 所有关键一致性问题均通过浏览器坐标、计算样式、溢出和控制台检查验证。

## 物品目录工具栏落地摘要

本轮物品管理页面调整补充了以下可复用结论：

- 页面大标题只保留“物品”及必要上下文，不再放置只作用于物品目录的创建入口。
- 刷新与新建统一进入物品目录工具栏，并使用同尺寸、同边框、同背景和同线性图标语言的图标按钮。
- 桌面、窄桌面和移动端复用同一组刷新/新建控件，避免移动端单独维护文字按钮。
- 空目录不再重复显示“新建物品”；搜索无结果仍保留“清除搜索”，因为它只用于恢复当前筛选状态。
- 刷新目录会同步关闭干净编辑器并清除选中；存在未保存修改时先显示放弃确认。
- 验收实际比较了按钮 `x`、`y`、`width`、`height`、间距和计算样式，并检查三档视口横向溢出与浏览器控制台。

## 物品目录高级筛选落地摘要

- 分类、属性模板和动态属性筛选统一进入一个高级筛选 Dialog，关键词、库存状态和排序继续在工具栏即时生效。
- Dialog 必须区分已应用条件与当前草稿；取消直接丢弃草稿，清除全部只清理草稿，应用后才重建第一页目录请求。
- 同一字段多值使用 OR，不同字段以及搜索、分类、模板和库存状态之间使用 AND；前端不得只筛选当前已加载页。
- 动态字段使用多选项并展示服务端命中数量；默认最多展示八项，其余折叠，避免高基数字段无限推高 Dialog。
- 服务端暂时不再返回的已选值仍应保留并标记不可用，不能在用户确认前静默删除筛选条件。
- 工具栏入口用固定尺寸图标按钮和按字段计数的紧凑徽标，数量变化不能推动刷新、展示设置和新建按钮。
- 筛选值加载失败只影响 Dialog，并提供重试；目录旧结果继续可浏览。
- 桌面、窄桌面和移动端复用同一筛选状态与 Dialog；内容区独立滚动，页面不得产生横向溢出。

## 物品编辑 Dialog 落地摘要

- 已有物品可使用资料/库存双页工作区；新建会话虽然复用同一编辑器，但不得挂载库存导航、库存状态或库存请求。
- Dialog 会话模式在打开时固定，创建响应获得 ID 后应关闭当前新建会话，不能原地切换为已有物品工作区。
- 多页导航占用空间后必须保留原表单有效宽度；宽桌面使用局部工作区宽度，空间不足时导航先切到顶部。

- 桌面物品页默认让目录占满工作区，不再显示窄目录、空编辑列或常驻双栏。
- 点击目录项和点击新建使用同一个 `ItemEditorDialog`，共享字段、校验、图片、属性和底部操作区。
- `ItemEditorDialog` 组合通用 `ModalDialog`，复用项目现有遮罩、关闭动画、Escape、焦点进入和焦点返回行为。
- 移动端继续使用同一 Dialog 和同一业务状态，仅由通用 Dialog 的响应式样式切换为底部面板，不维护独立编辑页面。
- Dialog 打开期间保留背景目录和分页结果；保存后的目录刷新继续保留现有内容，只显示稳定的局部刷新反馈。
- 新建或编辑保存成功后关闭 Dialog 并返回目录，与其它管理 Dialog 的完成行为保持一致。
- 编辑请求按 OpenAPI 部分更新语义只发送变化字段；未修改属性时不触发属性整体替换，未更换主图时不重复提交主图 ID。
- 属性模板的必填标记和 select 候选项直接使用服务端模板元数据，必填值缺失时由表单定位对应控件，不再提交后只显示笼统的请求无效。
- 模板属性只呈现模板字段名和受类型约束的值控件，不显示冗余的属性名称、属性类型或逐项删除按钮；自定义属性仍可编辑名称、类型和值。
- 打开已有物品时必须把当前模板中未持久化的空字段补入编辑草稿，不能要求用户切换一次模板才能看到完整字段；补齐后的编辑草稿和基线草稿保持一致，不能因此产生虚假的未保存状态。
- 物品编辑 Dialog 的模板属性与自定义属性使用独立分组；添加入口只属于自定义属性，不能让用户误以为模板字段可以逐项增删。
- 表单输入不因 Dialog 剩余宽度而机械拉满：基础资料、模板属性和自定义属性必须使用同一列系统，桌面统一三列；常规手机使用两列，较宽移动端或平板使用三列，只有极窄视口才回落单列；长描述保持整行，主图作为特殊字段独立于普通输入列。
- 模板属性的视觉结构直接复用基础资料表单：标签高度、控件高度和行列间距一致，字段容器不增加逐项内边距、底边框、卡片背景或重复分隔线；模板与自定义属性只在分组边界使用一次分隔。
- 关闭 Dialog 后清空草稿和目录选中态；存在未保存修改时先显示统一放弃确认。
