# 替代关系页面实施设计

本文是 `frontend/` 替代关系页面的实施设计，定义全局替代关系治理页面的职责、信息架构、接口边界、编辑流程、响应式行为、模块拆分和验收标准。
它不把替代关系复制成物品主数据，也不改变 `core` 已有的自引用、重复关系、重复优先级和循环关系校验。

当前实现状态：真实列表和星链关系网络已经落地。`/#/substitutes` 使用全局关系接口，按主物品分组展示已有关系，并提供本地搜索、稳定刷新、权限控制、主物品选择和共享单物品编辑 Dialog；物品详情 Dialog 与独立页面复用同一套候选搜索、优先级调整、1024 字备注、移除和整体保存逻辑。全局库存状态筛选仍等待后端批量摘要契约。

星链式全局关系网络的设计与验收基线见 [`implementation-notes/substitute-network-visualization.md`](implementation-notes/substitute-network-visualization.md)。当前实现复用页面已加载的全量关系，不重复请求接口；提供确定性力导向布局、有向箭头、优先级、稳定节点颜色、名称/SKU 层级标签、搜索定位、直接关系、缩放平移、节点拖动和悬浮详情。关系网络用于理解多级链路和共同依赖，不替代当前列表与编辑器。

## 设计结论

独立页面与物品 Dialog 不冲突，职责应明确分层：

- **物品 Dialog：上下文内快速维护**。用户已经打开某个物品时，只维护这个主物品的替代列表，适合补充或调整少量关系。
- **替代关系页面：全局关系治理**。用户从全局视角查看所有“主物品 → 替代物品”关系，按库存状态定位风险，并进入指定主物品的编辑 Dialog。
- 两处共享同一个替代关系草稿模型、候选搜索、优先级归一化、备注长度和保存错误映射；页面不复制一套双向编辑器。
- 关系方向必须始终明确显示为 `主物品 A → 替代物品 B`。替代关系是有方向的，不能用无方向的“关联物品”文案，也不能把 A→B 推断成 B→A。

独立页面第一阶段采用“工具栏 + 按主物品分组的连续三段式列表 + 详情 Dialog”：

```text
替代关系
维护缺货时的替代顺序与可用性

搜索关系   [全部状态]  12 个主物品 / 24 条关系   [刷新] [新增关系]
┌──────────────────────────────────────────────────────────────┐
│ 主物品身份             │ 关系摘要                    │ 判断与操作 │
│ 物品名称 / SKU / ID    │ 2 个替代项 · 首选：物品 B    │ 可用替代  查看 │
│                        │ 1 个可用 · 优先级 1→2       │            │
├──────────────────────────────────────────────────────────────┤
│ 主物品 C → 替代物品 D …（按主物品分组连续展开）                 │
└──────────────────────────────────────────────────────────────┘
```

不在主列表上提供“清空全部关系”或逐条直接删除；高风险编辑统一进入 Dialog，并使用整体替换语义保存。

## 当前接口与数据边界

### 已有接口

| 方法     | 路径                                              | 页面用途                                   | 权限                       |
| -------- | ------------------------------------------------- | ------------------------------------------ | -------------------------- |
| `GET`    | `/api/substitutes`                                | 查询全部已有关系，用于主列表               | `stock.substitute.read`    |
| `GET`    | `/api/substitutes/{item_id}`                      | 查询指定主物品的完整替代详情               | `stock.substitute.read`    |
| `PUT`    | `/api/substitutes/{item_id}`                      | 整体替换指定主物品的完整关系               | `stock.substitute.manage`  |
| `DELETE` | `/api/substitutes/{item_id}/{substitute_item_id}` | 删除单条关系，保留给未来快速解绑或兼容场景 | `stock.substitute.manage`  |
| `GET`    | `/api/items/options`                              | 新增关系时搜索候选物品                     | 通常需要 `stock.item.read` |

`GET /api/substitutes` 返回的全局关系字段为：

- 主物品：`item_id`、`item_name`、`item_sku`。
- 替代物品：`substitute_item_id`、`substitute_item_name`、`substitute_item_sku`。
- 关系信息：`quantity`、`priority`、`notes`、`created_at`、`created_by_user_id`。

全局响应不包含替代物品图片、分类、单位、再订货点和库存状态；这些字段只在指定物品接口返回。因此主列表只能使用全局响应真实字段，不能把详情接口字段拼接成“全局实时状态”。点击查看或编辑后，再加载 `/api/substitutes/{item_id}` 获取完整详情。

当前全局接口没有分页、关键词、状态或排序参数。第一阶段必须：

- 一次加载全量关系后在前端按主物品分组和本地过滤。
- 不显示服务端不存在的分页控件，也不声称结果数量是“全部物品数量”。
- 不伪造“没有替代关系的物品”统计；接口只返回已经存在的关系。
- 关系数量显示为“`N` 个主物品 / `M` 条关系”，其中主物品数量由已返回关系去重计算。

### 服务端校验与错误映射

保存请求的 `substitutes` 是完整列表，空数组表示清空。服务端校验：

- 主物品不能替代自己。
- 同一主物品下不能重复替代物品。
- 同一主物品下优先级不能重复。
- 关系图不能形成循环。
- `priority` 从 1 开始；备注最大长度为 1024，非空备注不能只包含空白。

后端验证失败统一映射为 `invalid_request` 时，页面应保留 Dialog 草稿，优先根据字段详情定位候选或备注，无法定位时在保存按钮附近显示稳定错误并调用错误 Notice。前端的 `maxlength`、优先级归一化和禁用自引用只能改善体验，不能替代后端授权与校验。

## 页面边界

### 页面负责

- 查询并按主物品分组展示已有替代关系。
- 按主物品名称、SKU、替代物品名称、SKU和备注进行本地关键词过滤。
- 按关系可用性派生筛选：全部、存在可用替代、首选替代缺货、全部替代缺货。
- 提供刷新、清除筛选、查看指定主物品关系和新建关系入口。
- 复用物品 Dialog 的替代关系编辑能力，维护候选、优先级和备注。
- 展示加载、空结果、刷新失败、权限变化和保存失败状态。
- 在桌面、窄桌面和移动视口保持相同方向、排序和保存语义。

### 页面不负责

- 不把关系改成双向关系，不在保存时自动创建反向关系。
- 不编辑主物品名称、SKU、分类、单位或库存；这些操作回到物品管理。
- 不从全局接口推断未配置替代关系的物品，也不展示伪造的“覆盖率”。
- 不直接修改库存数量、批次或再订货点。
- 不在列表上直接执行不可逆的清空或批量删除。
- 不把前端隐藏按钮当作授权边界；服务端仍必须执行 `stock.substitute.read/manage`。

## 路由与权限

- 路径：`/substitutes`
- 页面标题：`替代关系`
- 布局：`AppShell`
- 进入权限：`stock.substitute.read`
- 管理权限：`stock.substitute.manage`

权限规则：

- 没有读取权限时，导航不显示入口，直接访问由路由守卫返回总览。
- 只有读取权限时，仍显示全局列表和详情，但隐藏新增、编辑、优先级、备注和移除入口；详情中的关系信息变为只读。
- 管理角色若要新增关系，需要同时能够调用 `/api/items/options`。首选方案是为管理角色配置 `stock.item.read`；若权限模型不允许，应由后端提供专用候选接口或明确的权限例外，不能只在前端绕过权限。
- 收到 `401/403` 时保留当前筛选和旧列表，显示权限或会话错误；不能静默清空页面。

## 页面信息架构

### 桌面三段式列表

列表按 `item_id` 分组，每个主物品占一个连续项目，不让同一主物品的每条关系重复一整行。

#### 左侧身份区：主物品

显示：

- 主物品名称，超长单行省略并保留 `title`。
- `SKU：...`。
- `物品 ID：#...`，作为次要上下文，不放大视觉权重。
- 关系方向提示：`主物品 → 替代物品`。

身份区固定最小宽度，不能被中间摘要挤压；点击名称或查看按钮打开详情 Dialog。

#### 中间信息区：替代关系摘要

显示：

- 替代项总数。
- 首选替代物品名称和优先级；没有关系时不创建空分组。
- 全局接口可计算的数量摘要，例如“`2` 个替代项，首选优先级 `1`”。
- 备注摘要：存在备注时显示“有兼容性说明”，不在列表展开完整文本。

由于全局接口缺少库存状态，第一阶段不能在这里显示“可用替代数量”“首选缺货”等实时判断；这些筛选和判断只有在详情接口返回状态后才可使用。若产品必须在全局列表按库存状态筛选，应先扩展全局 API 响应或增加批量摘要接口。

#### 右侧判断与操作区

显示：

- 关系数量标签。
- `查看关系` 图标按钮；管理用户可使用相同入口进入编辑 Dialog。
- 不显示未经接口支持的库存状态标签。

右侧区域固定宽度，按钮和数量不能被中间长名称推到下一行。主列表不放逐条删除按钮，避免用户误把局部解绑当作普通列表操作。

### 本地搜索与筛选

工具栏顺序：

1. `搜索关系`：匹配主物品名称/SKU、替代物品名称/SKU和备注。
2. 结果数量：显示“`N` 个主物品 / `M` 条关系”，数字变化不推动按钮位置。
3. `刷新`：中性图标按钮，保留当前搜索和筛选。
4. `新增关系`：主题色加号图标按钮，仅同时具备替代关系管理和物品读取权限时显示；按钮使用 `title` 和 `aria-label`，不依赖文字才能理解。

第一阶段不渲染没有真实筛选能力的“状态筛选”控件。全局接口补充批量库存摘要后，再增加存在可用替代、首选缺货和全部缺货等选项。

搜索输入使用现有 `SearchField`，采用防抖并取消旧的本地计算或请求任务。没有结果时保留搜索和清除入口，显示“没有匹配的替代关系”。

### 新增关系流程

新增不是直接创建一条孤立关系，而是先选择主物品，再进入同一个编辑 Dialog：

1. 点击主题色 `+` 图标按钮。
2. 打开“选择主物品”步骤，使用 `/api/items/options` 搜索名称或 SKU。
3. 选中主物品后加载 `/api/substitutes/{item_id}`；已有关系作为当前草稿。
4. 在“添加替代物品”区域搜索候选并加入草稿；候选列表排除主物品自身和已选项。
5. 调整优先级、填写兼容性备注，保存完整列表。
6. 保存成功后关闭 Dialog，刷新全局列表并保留当前搜索上下文。

如果选择的主物品尚未配置替代关系，Dialog 显示明确空状态“该物品暂无替代关系”，而不是把它误显示为全局列表中的一条空关系。

## 关系详情与编辑 Dialog

### 复用原则

独立页面点击“查看关系”后，复用 `ItemSubstitutesPanel.vue` 当前的业务模型和 `ModalDialog` 外壳：

- 同一份 `SubstituteDraft` 字段：替代物品 ID、名称、SKU、分类、图片、单位、库存、再订货点、库存状态、优先级和备注。
- 同一套候选搜索、加入/移除、优先级上移/下移、备注草稿和整体 `PUT` 保存。
- 同一套稳定加载指示、请求取消、Notice和错误映射。
- 页面层只负责传入主物品 ID、权限和关闭后的列表刷新，不在页面层复制替代关系算法。

### 编辑语义

- Dialog 打开后先加载服务端基线；加载期间不显示可编辑空表单。
- 所有修改先写入本地草稿，`dirty` 只由替代物品 ID、优先级和备注组成。
- 优先级移动后立即归一化为 `1…N`，避免提交重复或空档优先级。
- 保存时一次性调用 `PUT /api/substitutes/{item_id}`；正常编辑不直接调用 `DELETE`，以免本地草稿和优先级顺序失去一致性。
- 独立详情 Dialog 的保存按钮固定放在 `modal-actions`，与取消操作同层；共享面板继续拥有保存逻辑，通过组件公开方法响应外层按钮，物品详情内嵌场景仍保留原入口。
- 保存错误固定显示在 `modal-actions` 上方的 notice 区，不因关系内容滚动离开视口；主物品上下文、候选搜索与关系列表共享同一内容滚动区。
- 保存前可显示简短差异摘要：新增项、移除项、顺序变化和备注变化；不要求用户再次确认普通保存。
- 关闭存在未保存修改的 Dialog 时，使用统一“放弃修改”确认；取消关闭则保留草稿。
- 保存成功后以服务端响应重建基线，显示“替代关系已保存”，再刷新主列表。
- 空列表保存表示清空当前主物品关系；这是高风险操作，保存前必须在差异摘要中明确显示“将清空全部替代关系”，但不在主列表提供单独清空按钮。

### 备注长度

后端允许最多 1024 个字符。独立页面与物品 Dialog 已统一使用 `maxlength="1024"`、剩余字数提示和提交前 trim；备注为空时提交 `null`，只包含空白时按服务端规则归一为空值。

### 只读详情

没有管理权限时保留：

- 主物品上下文。
- 替代物品图片、名称、SKU、分类、单位、库存量、库存状态、再订货点和备注。
- 优先级顺序。

隐藏：

- 添加候选物品。
- 上移、下移、移除。
- 保存按钮和新增关系入口。

## 状态与反馈

页面和 Dialog 遵循 `async-state-transitions.md`：

| 状态         | 页面表现                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------- |
| 首次加载     | 200ms 后才显示稳定的列表加载提示，期间不闪烁空状态                                       |
| 加载成功     | 按主物品分组显示；保留工具栏和数量                                                       |
| 空数据       | 显示“暂无已配置的替代关系”，管理用户提供主题色新增入口；只读用户显示说明，不伪造物品统计 |
| 本地无匹配   | 保留搜索值，显示“没有匹配的替代关系”和清除搜索按钮                                       |
| 刷新中       | 保留旧列表，仅弱化内容并驱动刷新图标；不跳回顶部、不清空列表                             |
| 刷新失败     | 保留旧列表，工具栏或 Notice 显示错误并提供重试                                           |
| 权限失效     | 保留旧结果和筛选，显示权限变化错误；重新加载后按服务端结果更新                           |
| 编辑加载失败 | Dialog 保留主物品上下文，显示错误和重试，不挂载空编辑器                                  |
| 保存中       | 锁定候选、排序和备注控件，按钮显示“保存中…”                                              |
| 保存失败     | 保留草稿和焦点，显示字段或全局错误，不关闭 Dialog                                        |

库存状态只在指定物品详情响应存在时显示：`库存正常`、`待补货`、`缺货`、`需配置`。状态色只用于小标签，不能给整行铺强色背景，也不能用“可用替代数量”替代服务端真实数据。

## 响应式设计

### `1440 × 900`

- 页面使用完整三段式关系组列表。
- 工具栏搜索、结果数量、刷新和主题色新增按钮位于同一工作区行。
- 左侧身份区和右侧操作区保持固定最小宽度，中间摘要自适应。
- 详情 Dialog 使用桌面宽度，关系编辑列表内部滚动，标题栏和底部操作区固定。

### `1024 × 768` 或接近断点

- 保留三段语义，但允许中间摘要两行显示。
- 搜索独占第一行，数量、刷新和新增按钮靠近排列；不能压缩成不可点击的小按钮。
- 操作区不被长名称挤出容器；必要时将摘要次要字段隐藏，而不是裁剪操作按钮。
- 详情 Dialog 仍使用单个滚动内容区，候选列表和已配置关系不产生页面级横向滚动。

### `390 × 844`

- 页面内部不重复 AppShell 已显示的“替代关系”大标题。
- 工具栏重组成：搜索独占一行；结果数量、筛选、刷新、新增组成紧凑操作组。
- 关系组重组成单列项目：主物品身份在顶部，`主物品 → 替代物品`摘要和操作按钮在下方；不使用横向表格。
- 新增与编辑 Dialog 使用移动全屏或底部面板，标题栏和底部主操作固定，内容独立纵向滚动。
- 长名称、SKU和备注使用省略或换行策略；禁止页面级横向滚动。
- 移动端触控目标至少保持项目通用尺寸，图标按钮必须提供可读 `aria-label` 和 `title`。

浏览器 MCP 实测结果（2026-07-15）：

- `1440 × 900` 已展示 4 个主物品、9 条有向关系；三段式表头、关系组、刷新和主题色新增按钮均完整显示。
- `1024 × 768` 的搜索框独占一行，结果数量、刷新和新增操作位于相邻命令行；页面、工作区和关系组均满足 `scrollWidth === clientWidth`。
- `390 × 844` 使用单列关系项目，工具栏和 4 个关系组没有页面级横向滚动；`body` 为 `390/390`，工作区和关系项目分别为 `366/366`。
- 移动详情 Dialog 为底部工作面板，`clientWidth = scrollWidth = 390`；内部关系面板为 `354/354`，关系项目为 `325/325`。
- 手动刷新前后列表 `scrollTop` 均保持 `180`，新增数据不会导致当前列表瞬移。
- 主物品选择、候选排除、优先级移动、1024 字备注计数、未保存关闭确认和清空全部二次确认均已通过真实交互检查。
- 三次测试关系整体保存分别调用 `PUT /api/substitutes/6`、`/1` 和 `/4`，响应均为 `200`；保存后全局 `GET /api/substitutes` 自动刷新。
- 回环草稿调用整体保存后由服务端返回 `400`，Dialog 保留候选草稿并显示“请求参数无效”，随后可放弃且不会写入关系。
- 正常加载、搜索、刷新、打开和关闭流程无新增控制台错误；故意提交回环关系时仅出现与预期 `400` 请求对应的资源错误。

## 前端模块拆分

当前实现使用以下模块，保持页面编排与业务组件分离：

```text
frontend/src/pages/SubstitutesPage.vue
frontend/src/pages/SubstitutesPage.scss
frontend/src/pages/substitutes/model.ts
frontend/src/pages/substitutes/networkModel.ts
frontend/src/pages/substitutes/presentation.ts
frontend/src/components/substitutes/SubstituteRelationGroup.vue
frontend/src/components/substitutes/SubstituteEditorDialog.vue
frontend/src/components/substitutes/SubstituteNetworkDialog.vue
frontend/src/components/substitutes/SubstituteNetworkCanvas.vue
frontend/src/components/substitutes/SubstituteNetworkNodeDetail.vue
frontend/src/composables/useSubstituteNetworkLayout.ts
frontend/src/api/substitutes.ts
```

职责边界：

- `SubstitutesPage.vue`：路由筛选、全局列表请求、分组、刷新、权限、网络与编辑器返回编排；不直接修改草稿字段或计算布局。
- `model.ts`：全局关系分组、关键词匹配、摘要派生和编辑目标类型；纯函数可单测。
- `networkModel.ts`：全局关系转稳定节点/边、邻接表、搜索、直接关系和规模降级；不管理 Vue 或 DOM 状态。
- `presentation.ts`：关系数量和错误文案格式化；不发请求。
- `SubstituteRelationGroup.vue`：三段式关系组和移动单列项目；只发出查看/编辑事件。
- `SubstituteEditorDialog.vue`：复用或提取 `ItemSubstitutesPanel` 的编辑会话；拥有 dirty、保存和关闭确认。
- `SubstituteNetworkDialog.vue`：网络搜索、观察范围、画布控制、悬浮详情和编辑切换编排。
- `SubstituteNetworkCanvas.vue`：SVG 节点与有向边、缩放平移、节点拖动、键盘导航和视口状态。
- `SubstituteNetworkNodeDetail.vue`：悬浮节点摘要、上下游文字详情和维护关系入口；不改变画布尺寸。
- `useSubstituteNetworkLayout.ts`：无第三方依赖的确定性力导向布局、位置缓存和停止机制。
- `SubstituteEditorDialog.vue` 内的主物品选择区负责分页接口第一页的精确搜索；单物品候选搜索继续由共享 `ItemSubstitutesPanel.vue` 负责，自引用和已选项不会出现在候选结果中。
- `api/substitutes.ts`：补充全局关系响应 DTO 和全局查询函数；不在 API client 内实现本地过滤。

如果提取编辑器，应先把 `ItemSubstitutesPanel.vue` 改为组合共享组件，再让物品 Dialog 和独立页面共同使用；不要复制文件后分别修 bug。
