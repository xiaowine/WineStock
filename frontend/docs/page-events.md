# 审计日志页面实施设计

本文是 `frontend/` 审计日志页面的实施设计，定义页面职责、筛选模型、列表与详情信息架构、响应式行为、前端模块拆分和验收标准。
它不改变 `core` 的审计写入范围，也不把审计日志扩展成服务器运行日志、登录日志或任意文本检索系统。

当前实现状态：第一阶段真实只读页面已经落地，包括服务端筛选、显式分页、稳定刷新、三段式桌面列表、移动日志项目、历史 JSON 详情和原始 JSON 回退。后端继续使用 `GET /api/events` 提供数据。

## 设计结论

审计日志用于回答以下问题：

- 谁在什么时间执行了什么业务操作。
- 操作影响了哪一种业务实体和哪一条记录。
- 服务端记录了哪些关键字段、前后快照或业务摘要。
- 同一实体或同一操作人最近还执行过哪些相关操作。

页面采用“稳定筛选工具栏 + 三段式审计列表 + 只读详情 Dialog”的结构：

- 列表负责快速定位时间、操作人、业务对象和动作。
- 详情 Dialog 负责展示结构化变更、原始 JSON 和相关筛选入口。
- 筛选、分页和刷新全部使用服务端结果，不在前端下载全量日志后自行过滤。
- 审计记录不可编辑、不可删除，也不提供任何会改变业务状态的操作。

## 当前接口与数据边界

### 已有接口

```text
GET /api/events
```

查询参数：

| 参数 | 类型 | 当前语义 |
| --- | --- | --- |
| `page` | integer | 页码，从 1 开始，默认 1 |
| `page_size` | integer | 每页数量，默认 50，最大 200 |
| `entity_type` | string | 实体类型精确匹配 |
| `entity_id` | integer | 实体 ID 精确匹配 |
| `action` | string | 动作精确匹配 |
| `user_id` | integer | 操作人用户 ID 精确匹配 |
| `date_from` | datetime string | UTC 操作时间下限，包含边界 |
| `date_to` | datetime string | UTC 操作时间上限，包含边界 |

响应使用 `PaginatedResponse<EventLogResponse>`：

| 字段 | 类型 | 页面用途 |
| --- | --- | --- |
| `id` | integer | 稳定列表 key、事件编号和复制值 |
| `timestamp` | string | 操作时间；列表显示本地时间，详情保留原始 UTC |
| `user_id` | integer/null | 操作人筛选；为空时表示无法关联当前用户记录 |
| `username` | string/null | 操作人显示名；为空时回退用户 ID 或“系统/未知操作人” |
| `entity_type` | string | 实体类型字典映射和筛选 |
| `entity_id` | integer/null | 目标实体编号和相关事件筛选 |
| `action` | string | 动作字典映射、状态色和筛选 |
| `details` | JSON value | 摘要、结构化变更和原始详情展示 |

后端固定按 `timestamp DESC, id DESC` 排序。前端不得增加一个没有服务端支持的排序控件，也不得把当前页重新排序后称为全局排序。

### 当前实体类型

前端已知字典至少覆盖：

| 原始值 | 中文标签 |
| --- | --- |
| `item` | 物品 |
| `item_category` | 物品分类 |
| `item_attribute_template` | 物品属性模板 |
| `inbound_template` | 入库模板 |
| `user` | 用户 |
| `inbound` | 入库单 |
| `outbound` | 出库单 |
| `location_group` | 库位分组 |
| `location` | 库位 |
| `location_transfer` | 移库记录 |
| `substitute` | 替代关系 |

字典只负责友好显示，不构成封闭枚举。遇到历史值或未来新增值时：

- 列表显示原始 `entity_type`，不能归类为“未知”后丢失原值。
- 详情显示“未识别实体类型”说明和原始值。
- 自定义实体类型筛选允许提交原始字符串。

### 当前动作类型

| 原始值 | 中文标签 | 建议视觉语义 |
| --- | --- | --- |
| `created` | 创建 | 正向但低饱和 |
| `updated` | 更新 | 中性强调 |
| `deleted` | 删除 | 危险色弱背景 |
| `approved` | 审批通过 | 正向 |
| `rejected` | 驳回 | 警示或危险 |
| `linked` | 建立关联 | 正向 |
| `unlinked` | 解除关联 | 警示 |
| `moved` | 移动 | 中性强调 |

动作色只用于紧凑标签和详情标题的小范围强调，不给整行铺强色背景。审计页面表达的是已经发生的事实，不应把历史删除或驳回渲染成持续告警。

### 当前接口缺口

第一阶段不得伪造以下能力：

- 没有关键词、用户名、实体名称或详情 JSON 的全文搜索。
- 没有可用实体类型、动作和操作人的服务端筛选值接口。
- 没有单条事件详情接口；列表响应已经包含完整 `details`。
- 没有导出 CSV、Excel、PDF 或归档接口。
- 没有 IP、设备、客户端、请求 ID、会话 ID或接口耗时字段。
- 没有按业务对象名称查询或从审计记录恢复被删除对象的接口。
- 没有审计记录删除、编辑和备注能力。

页面不得显示不可用的搜索框、导出按钮、IP 列或“查看请求”入口。后续补充能力时必须先扩展 `core` 契约和文档。

## 页面边界

### 页面负责

- 查询并分页展示当前用户有权读取的审计事件。
- 按实体类型、实体 ID、动作、操作人 ID和时间范围筛选。
- 把已知实体、动作和详情字段映射为可读中文。
- 展示历史详情 JSON 中的已知结构，并完整保留未知字段。
- 从事件行快速筛选同一操作人、同一实体或同类动作。
- 提供手动刷新、分页失败重试和筛选清除。
- 在桌面、断点附近和移动端保持相同数据与筛选语义。

### 页面不负责

- 不修改、删除、重放或撤销审计事件。
- 不根据审计详情直接修改物品、单据、用户或库位。
- 不把缺少 `username` 解释为一定由系统执行；外键置空、历史用户删除和旧数据都可能产生空值。
- 不把实体 ID 当作当前对象必然仍存在的证明。
- 不根据当前业务对象反向覆盖历史快照。
- 不在浏览器中缓存全量审计日志。
- 不把前端隐藏导航当作授权边界。

## 路由与权限

- 路径：`/events`
- 路由名：`events`
- 页面标题：`审计日志`
- 布局：`AppShell`
- 进入权限：`audit.read`
- 后端接口权限：`audit.read`

`frontend/src/router/index.ts` 已懒加载 `EventsPage.vue`，并保留现有路由名、导航顺序和 `getAppRouteMeta('events')`。

权限规则：

- 没有 `audit.read` 时导航不显示入口，直接访问由路由守卫返回总览。
- 页面不依赖 `user.read`。操作人筛选使用事件自身的 `user_id` 和可选的数字输入，不为了显示用户名额外请求用户管理接口。
- 服务端返回 `403` 时显示权限已变化的错误 Notice，并保留当前筛选上下文；前端不能自行假设权限仍然有效。

## 页面信息架构

### 宽桌面布局

页面沿用连续列表工作区，不创建统计卡片或嵌套卡片：

```text
审计日志
追踪用户与库存业务产生的关键操作

┌──────────────────────────────────────────────────────────────┐
│ 实体类型  动作  开始时间  结束时间     [更多筛选]  67 条 [刷新] │
│ [物品] [更新] [2026-07-01 00:00] [2026-07-15 23:59]          │
├───────────────┬─────────────────────────────┬────────────────┤
│ 时间与操作人   │ 对象与变更摘要               │ 动作与详情      │
├───────────────┼─────────────────────────────┼────────────────┤
│ 07/15 13:10   │ 物品 #8                     │ 更新       [>] │
│ admin · #1    │ 名称、分类等 3 项发生变化      │ 事件 #67        │
├───────────────┴─────────────────────────────┴────────────────┤
│ [上一页]                    第 1 / 4 页                 [下一页] │
└──────────────────────────────────────────────────────────────┘
```

- 页面标题区只识别业务范围，不放筛选、刷新或导出按钮。
- 工具栏、列表和分页尾部属于同一个连续工作区。
- 列表采用项目三段式结构：固定身份区、弹性信息区、固定判断与操作区。
- 详情使用通用 `ModalDialog`，不为第一阶段新增另一套页面级 Drawer。

### 断点附近布局

- 工具栏从一行调整为两行：实体与动作保持第一行，时间范围占第二行。
- 结果数量、刷新和更多筛选保持同一操作组，不被时间字段推动。
- 列表身份区和操作区保持固定，中间摘要允许压缩并单行省略。
- 当可用宽度不足以保持桌面三段式最小列宽时，直接切换移动项目，不压缩成不可读窄表格。

### 移动布局

- 移动 Shell 已显示“审计日志”时，页面内部不重复大标题。
- 顶部工具栏显示当前筛选摘要、结果数量、筛选按钮和刷新按钮。
- 详细筛选进入页面级 Dialog 或底部 Sheet，使用同一份草稿状态和提交逻辑。
- 日志列表使用连续单列项目，不产生页面级横向滚动。
- 详情 Dialog 使用移动全屏形态，标题和关闭操作固定，详情内容独立纵向滚动。

## 筛选工具栏设计

### 常用筛选

桌面常驻字段顺序：

1. `实体类型`：`SelectControl`，默认“全部实体”。
2. `动作`：`SelectControl`，默认“全部动作”。
3. `开始时间`：本地 `datetime-local`，精确到秒。
4. `结束时间`：本地 `datetime-local`，精确到秒。
5. `更多筛选`：图标按钮，打开实体 ID、操作人 ID、每页数量和自定义类型设置。
6. `结果数量`：显示服务端 `total`。
7. `刷新`：中性图标按钮，保留当前筛选和页码。

审计日志没有创建操作，因此工具栏不使用主题色加号按钮。

### 更多筛选

更多筛选 Dialog 字段：

- `实体 ID`：正整数，可空。
- `操作人用户 ID`：正整数，可空。
- `实体类型原始值`：选择“自定义类型”时显示，最多 64 个字符，不允许空白值。
- `动作原始值`：选择“自定义动作”时显示，最多 64 个字符。
- `每页数量`：25、50、100、200，默认 50。

操作：

- `取消`：丢弃筛选草稿。
- `重置`：清除更多筛选草稿，不立即请求。
- `应用筛选`：提交完整筛选集合并回到第 1 页。

### 时间范围

- 输入按用户本地时区展示，提交前转换为 UTC ISO 字符串。
- 详情同时显示本地时间和原始 UTC，避免跨时区追溯歧义。
- `date_from` 大于 `date_to` 时不发送请求，定位到时间字段并显示 Notice。
- 清除任一边界后只提交另一边界，不自动补成当天开始或结束。
- 不提供“今天”“最近 7 天”等预设，除非项目后续形成跨页面统一日期范围控件。

### 快速筛选

事件行和详情提供不改变数据的快捷入口：

- 点击操作人上下文中的筛选按钮：设置 `user_id`，回到第 1 页。
- 点击实体上下文中的“查看相关事件”：同时设置 `entity_type` 和 `entity_id`。
- 点击动作标签旁的筛选按钮：设置 `action`。
- 活跃筛选显示为紧凑筛选摘要，可单项清除。

整行点击仍用于打开详情，不把多个筛选语义都绑定到整行。

### URL 查询状态

建议把可分享且不敏感的状态同步到 hash 路由 query：

```text
/#/events?entity_type=item&action=updated&user_id=1&page=2&page_size=50
```

- 页面初始化从 query 解析合法值；非法页码和负数 ID 回退默认值并 replace 当前 URL。
- 筛选变化 reset 到第 1 页并 replace，显式上一页/下一页使用 push，允许浏览器返回恢复页码。
- 时间值使用 UTC ISO 字符串；不把详情 JSON 或用户名写入 URL。

## 审计列表设计

### 桌面三段式列表

#### 左侧身份区：时间与操作人

显示：

- 主行：本地日期时间，建议 `YYYY/MM/DD HH:mm:ss`。
- 次行：`username`；为空时显示 `用户 #<user_id>`，两者都为空时显示“系统/未知操作人”。
- 辅助：用户 ID 只作为次要信息，不放大视觉权重。

规则：

- 时间不使用“刚刚”“几分钟前”替代精确时间。
- 完整 UTC 时间放入 `title` 或详情，不在列表重复两列时间。
- 操作人名称超长时单行省略，完整值保留 `title`。

#### 中间信息区：对象与变更摘要

显示：

- 主行：中文实体类型 + `#entity_id`；ID 为空时显示“无实体编号”。
- 次行：根据 `details` 生成的一行摘要。
- 未识别类型保留原始代码，例如 `custom_event #42`。

摘要示例：

- 物品创建：`创建“纯色主图测试物品”，单位 个`。
- 物品更新：`分类、模板等 2 项发生变化`。
- 用户权限更新：`新增 1 项权限，移除 0 项权限`。
- 入库审批：`审批 3 条明细`。
- 库位移动：`上级分组或排序发生变化`。
- 整批次移库：`批次 #12 从库位 #3 移至 #8，数量 5`。
- 未识别详情：`包含 6 个详情字段` 或 `暂无结构化详情`。

摘要生成必须是纯展示函数，不修改 `details`，不能因某个历史字段缺失而抛出渲染错误。

#### 右侧判断与操作区：动作与详情

显示：

- 动作标签：中文动作；未知动作显示原始代码。
- 事件编号：`事件 #id`。
- 详情图标按钮：打开只读详情 Dialog，提供 `title` 和 `aria-label`。

本区固定宽度，动作文案、事件 ID 和按钮不得被中间摘要挤压。

### 移动日志项目

每个项目显示：

- 第一行：本地时间和动作标签。
- 第二行：实体中文名与 ID。
- 第三行：操作人。
- 第四行：最多两行摘要。
- 右上角或底部：明确的详情图标按钮。

移动项目不直接展示格式化 JSON、权限数组或完整前后快照。复杂详情统一进入 Dialog。

### 动作标签与颜色

- `created`、`approved`、`linked`：使用低饱和正向色。
- `updated`、`moved`：使用主色浅背景或中性强调。
- `deleted`、`rejected`：使用危险色浅背景。
- `unlinked`：使用警示色浅背景。
- 未知动作：使用中性标签并显示原始值。

颜色不能成为唯一信息；中文动作文字始终可见。

## 详情 Dialog 设计

### 标题与固定上下文

Dialog 标题使用：

```text
更新物品
```

固定上下文区显示：

- 事件编号。
- 本地操作时间和原始 UTC。
- 操作人名称与用户 ID。
- 实体类型原始值、中文值和实体 ID。
- 动作原始值和中文值。

固定上下文与滚动详情分离；长 JSON 不能把标题和关闭按钮推离视口。

### 已知详情展示

详情解析优先级：

1. 已知实体 + 已知动作的语义化展示。
2. 通用 `previous` / `new` / `changed_fields` 差异展示。
3. 通用对象键值展示。
4. 数组、标量或空值的通用展示。
5. 始终可展开的原始 JSON。

#### 通用前后差异

当 `details` 包含 `previous` 和 `new` 时显示差异表：

| 字段 | 修改前 | 修改后 |
| --- | --- | --- |
| 名称 | 默认库位 | 成品库位 |
| 上级分组 | `#1` | `#8` |
| 排序 | 0 | 10 |

- 优先使用 `changed_fields` 确定展示字段和顺序。
- 缺少 `changed_fields` 时比较前后对象的键集合。
- `null` 显示“未设置”，缺失字段显示“无记录”，不能把两者混为同一语义。
- 对象和数组不强行转成逗号字符串，复杂值使用可展开区域。

#### 权限变化

用户权限事件包含 `previous_permissions` 和 `new_permissions` 时：

- 计算并显示“新增权限”和“移除权限”两个列表。
- 未变化权限默认折叠，仅在原始 JSON 中保留。
- 权限代码保持原值，可同时使用项目权限说明映射；未知权限不能隐藏。

#### 删除事件

删除事件常包含 `previous` 快照：

- 标题明确“删除前快照”。
- 不使用当前实体查询结果覆盖快照。
- 不显示“恢复”按钮。

#### 单据和移库事件

- 入库/出库创建：显示来源或去向、明细数量。
- 审批/驳回：显示明细数量或服务端原因代码。
- 移库：显示批次、物品、原库位、目标库位和数量。
- 替代关系：显示旧列表、新列表、实际新增和移除的物品 ID。

这些字段都来自 `details`；缺失时降级到通用展示，不能请求其它接口后伪装成历史快照。

### 原始 JSON

- 默认折叠，标题显示“原始详情”。
- 使用等宽字体、保留缩进和换行，容器内部允许横向滚动。
- 提供“复制 JSON”按钮，复制服务端已经返回的完整 `details`。
- `details` 为 `null`、数组、字符串、数字或布尔值时也必须正常显示。
- 序列化失败时显示稳定错误说明，不能导致整个 Dialog 崩溃。

### 详情操作

Dialog 底部只保留：

- `关闭`：关闭 Dialog 并把焦点返回原详情按钮。
- `查看相关事件`：实体类型和实体 ID 都存在时显示，应用筛选并关闭 Dialog。

不提供保存、删除、撤销或编辑按钮。

## 分页与刷新

### 分页选择

审计日志第一阶段使用显式分页，不使用自动无限滚动：

- 日志按时间倒序持续增长，offset 分页在后台新增记录时可能发生页边界移动。
- 显式页码让用户知道当前查看范围，也便于 URL 恢复和返回。
- 默认每页 50 条；允许 25、50、100、200。

分页尾部：

- 左侧：上一页。
- 中间：`第 2 / 6 页 · 共 276 条`。
- 右侧：下一页。
- 首页禁用上一页，末页禁用下一页。
- `total_pages = 0` 时显示“暂无审计事件”，不显示“第 1 / 0 页”。

### 手动刷新

- 刷新保留筛选、页码、滚动上下文和旧列表。
- 使用 `200ms` 延迟显示和 `350ms` 最短展示的稳定刷新状态。
- 刷新成功后替换当前页并显示“审计日志已刷新”。
- 当前页因总页数减少而越界时，请求最后一个有效页；无数据时回到第 1 页状态。
- 刷新失败保留旧结果，在工具栏和 Notice 提示错误。
- 第一阶段不自动轮询，避免用户阅读详情时列表跳动。

### 请求取消

- 筛选、页码和刷新共享一个当前列表请求控制器。
- 新请求开始前取消旧请求；主动取消不显示错误。
- Dialog 只读取当前行数据，不发起额外事件详情请求。
- 路由离开时取消列表请求。

## 状态与错误矩阵

| 状态 | 页面呈现 | 保留内容 | 可执行操作 |
| --- | --- | --- | --- |
| 首次加载 | 稳定工具栏 + 列表骨架 | 当前 URL 筛选 | 等待或离开 |
| 查询成功 | 日志列表 + 分页 | 筛选和页码 | 筛选、刷新、查看详情 |
| 无审计事件 | 工具栏 + 中性零结果 | 筛选 | 调整筛选、刷新 |
| 后台刷新 | 旧列表弱化 + 刷新图标状态 | 全部旧结果 | 继续阅读 |
| 初始失败 | 列表区域错误状态 | 筛选 | 重试 |
| 刷新失败 | 旧列表 + 内联错误/Notice | 全部旧结果 | 重试、修改筛选 |
| 分页失败 | 当前页保持可见 | 当前页 | 重试下一页/上一页 |
| 非法时间范围 | 字段错误 + Notice | 当前结果 | 修正或清除时间 |
| 权限变化 `403` | 明确权限错误 | 筛选上下文 | 返回其它页面 |
| 未知详情结构 | 通用详情 + 原始 JSON | 完整事件 | 复制 JSON、关闭 |

## 前端模块拆分

当前实现：

```text
frontend/src/
  api/
    events.ts
    pagination.ts
  pages/
    EventsPage.vue
    EventsPage.scss
    events/
      catalog.ts
      details.ts
  components/events/
    EventFilterDialog.vue
    EventDetailDialog.vue
```

### `api/events.ts`

定义并导出：

- `EventListQuery`
- `EventLogResponse`
- `JsonValue`
- `listEvents(query, signal)`

`details` 使用递归 `JsonValue` 或 `unknown`，不能声明成固定业务对象。

### `api/pagination.ts`

把当前 `api/users.ts` 中的通用 `PaginatedResponse<TItem>` 移到共享 API 类型文件，用户和审计模块共同复用，不复制同名分页 DTO。

### `EventsPage.vue`

页面负责：

- 路由 query 与筛选状态同步。
- 列表请求、取消、分页、刷新和错误编排。
- 当前详情事件和 Dialog 开关。
- 快速筛选和筛选摘要。
- 权限变化后的页面反馈。

页面不直接实现 JSON 差异算法，也不硬编码每一种详情字段的渲染模板。

### `events/catalog.ts`

集中维护：

- 已知实体类型标签。
- 已知动作标签和视觉语义。
- 字段名中文映射。

所有映射函数都必须对未知值返回原始值。

### `events/details.ts`

纯函数负责：

- 判断 JSON 值类型。
- 解析通用前后快照。
- 计算字段差异。
- 计算权限新增和移除集合。
- 生成通用键值行。
- 安全格式化原始 JSON。

该模块适合添加单元测试，因为历史 JSON 兼容是页面可靠性的核心。

### 组件职责

- `EventFilterDialog.vue`：更多筛选草稿、校验和应用事件，不请求 API。
- `EventDetailDialog.vue`：通用 Dialog 外壳、固定上下文、语义化详情、通用差异、原始 JSON 回退、相关事件操作和焦点返回。

## 详情兼容与安全要求

- 审计详情是历史数据，字段会跨版本存在；前端不得只支持当前 DTO。
- 旧记录可能包含已经删除的字段，例如旧库位编码；仍应按原始字段展示。
- `details` 可能为空、标量、数组或对象，任何形态都不能让页面崩溃。
- 页面不得执行详情中的 HTML、URL、脚本或富文本。
- 所有字符串按普通文本渲染，不使用 `v-html`。
- 复制原始 JSON 只复制服务端响应，不附加 access token、路由状态或浏览器信息。
- 服务端负责禁止密码、token、哈希和密钥写入审计详情；前端仍不得为这些字段建立专门展示或回读逻辑。
- 超长字符串、深层对象和大数组必须限制默认展开高度，但完整值仍可在原始 JSON 区域查看和复制。

## 可访问性

- 列表使用正确的表格或列表语义；移动项目不伪装成表格行。
- 动作标签同时提供文字，不只依赖颜色。
- 所有筛选字段有可见标签或正确关联的隐藏标签。
- 刷新、更多筛选、详情和复制按钮提供 `title` 与 `aria-label`。
- 列表刷新使用区域 `aria-busy`，但不移除仍可阅读的旧结果。
- Dialog 打开时焦点进入标题或第一个可操作控件，关闭后返回原详情按钮。
- JSON 区域可键盘滚动，复制成功使用全局 Notice。
- 时间、事件 ID、用户 ID 和实体 ID 使用可读文本，不只放在 tooltip。

## 响应式验收

### `1440 × 900`

- 页面标题、完整工具栏、三段式列表和分页同时可见。
- 常用筛选保持一行，结果数量和刷新按钮不被推动。
- 左右固定区清晰，中间摘要充分利用剩余空间。
- 详情 Dialog 固定上下文和滚动详情边界明确。

### `1024 × 768` 与断点附近

- 工具栏稳定换成两行，不产生按钮孤立在中间的情况。
- 时间范围字段不压缩到不可编辑。
- 结果数量、更多筛选和刷新保持同一右侧操作组。
- 列表在三段式和移动项目之间只切换一次，不出现半表格状态。

### `390 × 844`

- 页面无横向溢出。
- 筛选摘要、数量、筛选和刷新按钮完整可见。
- 日志项目时间、动作、实体、操作人和摘要层级清楚。
- 详情全屏 Dialog 的标题、关闭和底部操作保持可见，JSON 只在自身区域滚动。

## 实施顺序

### 第一阶段：真实只读页面

已完成：

1. 新增 `api/events.ts` 和共享分页类型。
2. 建立实体、动作、字段映射与未知值回退。
3. 实现工具栏、服务端筛选、显式分页和稳定刷新。
4. 实现桌面三段式列表和移动日志项目。
5. 实现通用详情 Dialog、前后差异和原始 JSON。
6. 将 `/events` 从占位页切换为真实页面。
7. 覆盖路由 query、错误、权限和三档视口验收。

### 第二阶段：筛选值元数据

如后端新增审计筛选值接口：

- 用服务端返回的实体、动作和操作人候选替换前端维护选项。
- 保留未知值回退，不能因元数据缺失隐藏历史记录。
- 操作人候选应由审计权限拥有，不要求额外 `user.read`。

### 第三阶段：导出或关联导航

只有后端提供稳定契约后再实施：

- 服务端异步导出和下载状态。
- 审计事件到仍存在业务对象的安全跳转。
- 请求 ID、客户端或部署审计元数据。

不得直接在浏览器中拉取全部页拼接导出文件。

## 完成门槛

- `/events` 不再渲染占位页，路由、导航和权限代码保持不变。
- 页面只请求 `GET /api/events`，不依赖用户管理权限或其它业务详情接口。
- 所有筛选使用服务端查询参数，筛选变化回到第 1 页。
- 列表遵循时间倒序，不提供伪排序或前端全量搜索。
- 已知实体和动作中文可读，未知值完整保留原始代码。
- `details` 的对象、数组、标量、空值和未知历史字段都能正常展示。
- 前后差异、权限变化、删除快照、移库和替代关系具备语义化详情。
- 原始 JSON 可查看和复制，不使用 `v-html`。
- 刷新、初始失败、刷新失败、零结果、分页失败和权限变化状态明确。
- 桌面、断点附近和移动端复用同一筛选与详情状态，不维护两套请求逻辑。
- 验证 `pnpm build`、`git diff --check`、浏览器控制台和页面横向溢出。
- 使用真实审计数据验证超长用户名、空操作人、空实体 ID、历史字段、权限数组和未知实体类型。
