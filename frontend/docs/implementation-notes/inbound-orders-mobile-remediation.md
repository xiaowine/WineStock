# 入库单移动列表整改方案

## 问题结论

`/inbound/orders` 已有“卡片化”样式只落在 `@include mixins.tablet(900px)`，其实际范围是 **768px 至 900px**。`390px` 等移动视口不会命中该规则，继续使用桌面列表的 `min-width: 760px` 和三列网格，造成以下结果：

- 列表横向超出可视区域，右侧状态与查看操作被截断。
- 用户只能看到“桌面三段式行”的局部，而不是独立、可读的移动单据条目。
- 现有页面文档承诺的“移动单列条目”没有兑现。

这是前端响应式范围遗漏，不是数据或 API 缺失。现有列表响应已提供单据编号、来源、状态、时间、物品摘要、数量、金额和详情入口，首期无需改 core。

## 整改目标

可用宽度不超过 `900px` 时使用独立的单列入库单条目，不复用桌面列宽或横向滚动：

```text
入库单 #编号                         状态标签  查看
来源（最多两行）
创建时间
主物品缩略图 + 名称 / 编号 / 首项数量
明细数 · 数量摘要                         入库金额
状态时间或“等待审批，库存尚未增加”
```

- 整个条目点击、Enter、Space 打开详情；图片预览阻止冒泡并保持独立。
- 状态位于第一行，不放置只会重复打开同一详情的图标。
- 金额、明细数和数量摘要只出现一次；混合单位继续由现有 `quantityLabel` 输出，后续应修正为不伪造总数量。
- 不在移动列表显示备注、完整批次、库位、模板属性或审批操作；这些属于详情 Dialog。

## 实现设计

### 结构

新增 `frontend/src/components/inbound/InboundOrderList.vue`，只接收列表数据和展示派生值，不请求 API：

```text
InboundOrderList
├─ 桌面：保留三段式 role=table 行
└─ 移动：渲染 role=list / article 单列条目
```

不以 CSS 把同一套三列 DOM 强行压成移动布局。桌面表格语义、移动列表语义和焦点顺序不同；组件中分为桌面与移动两个呈现分支，但共用同一 `orders` 数组、格式化结果和 `open` 事件。

`InboundOrdersPage.vue` 继续拥有：URL query、搜索、筛选 Dialog、无限滚动、详情请求、权限与刷新。它把 `orders`、`statusLabel`、`statusTime`、金额/数量摘要和打开事件传给列表组件。

### 桌面与平板

- `min-width: 901px`：保留当前三段式桌面列表。
- `max-width: 900px`：隐藏桌面分支，显示同一紧凑单列条目；移除桌面最小列宽对窄内容区的影响。

### 移动条目视觉

- 条目之间用 `8–10px` 间距和 `1px` 边框区分，不堆叠阴影或大圆角卡片。
- 身份头部使用 `grid-template-columns: minmax(0, 1fr) auto auto`：编号/状态/查看操作稳定排列。
- 来源为次级文字，最多两行截断；创建时间单独一行，避免与状态竞争宽度。
- 物品摘要用已有 `AuthenticatedImage`、物品名和编号/首项数量；多明细只写“等 n 项”。
- 元信息行左侧显示“n 条明细 · 数量摘要”，右侧显示“¥金额”；金额右对齐，长数量允许换行。
- `pending` 使用一次库存语义说明；`approved` / `rejected` 显示对应状态时间。不要在状态标签外再重复同一状态。
- 卡片本身承担只读详情入口，不重复放置详情图标；图片预览保持独立触控目标。

### 工具栏、详情与筛选 Dialog

- 工具栏在移动端连续排列搜索、结果数、筛选、刷新和有权限时的新建图标；页面标题由 Shell 独占。
- 现有筛选 Dialog 已使用 `ModalDialog` 和项目专属 `DateTimeField`，继续复用；移动端只检查底部操作区可达和日期字段不溢出，不更换原生日期控件。
- 详情 Dialog 保持按需加载；移动端使用现有全屏 Dialog 行为。单据摘要保持单列；每条入库物品卡片的基础字段使用两列多行网格，物品头部金额可换行，属性值允许断行，不产生横向滚动。

## 数据与边界

首期不新增接口、不增加 N+1 物品或用户请求，也不改变无限滚动：

- `GET /api/inbound` 继续提供列表和服务端分页。
- `GET /api/inbound/{id}` 仍只在打开详情后请求。
- `IntersectionObserver` 的 root 继续是 `.inbound-orders-results`；移动列表分支必须保留尾部 sentinel。
- 筛选条件仍在 Dialog 中编辑并写入 URL query；移动端不能退回本地筛选。

同时修正数量摘要语义：若一张单据的明细单位不一致，显示“按明细分别计量”，不将不同单位相加为“合计数量”。

## 实施步骤

1. 抽取列表呈现组件和订单摘要派生函数，保持页面的请求、筛选和详情会话不变。
2. 实现桌面、平板、移动三种呈现分支；移动分支不设置桌面 `min-width`，不使用横向滚动。
3. 调整详情 Dialog：单据摘要单列、每条入库物品字段两列多行，并处理长文本断行；复核筛选 Dialog 的移动底部操作区。
4. 在 1440×900、约 768px、390×844 真实浏览器检查列表、筛选、详情、加载更多和错误状态。

## 验收标准

- 390×844 下 `document.documentElement.scrollWidth === clientWidth`；列表没有横向滚动。
- 390px 下每张单据可完整看到编号、状态、来源、时间、物品摘要、明细/数量和金额，整卡可打开详情。
- 桌面三段式列表不回退；768px 使用紧凑条目且不重叠。
- 点击卡片、Enter、Space 都只打开对应详情一次，点击图片只打开图片预览。
- 状态、筛选、无限滚动、刷新、空状态、加载失败和详情错误保持现有业务语义。
- `pnpm build`、`git diff --check` 通过；检查移动控制台无新增 error、warning 或 issue。
