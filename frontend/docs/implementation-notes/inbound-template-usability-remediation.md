# 入库模板可发现性与权限整改方案

本文针对正式入库工作台中“入库模板已经接入，但用户感知像是没有使用”的问题制定整改方案。整改目标不是重做入库流程，而是让模板的自动推荐、当前状态、待填属性、加载错误和权限限制在入库主任务中持续可见。

本方案涉及 `frontend` 与 `core` 的 HTTP 权限契约。实施时必须先更新 OpenAPI 和 core 业务文档，再调整前端状态与界面；不能只靠前端文案掩盖权限或默认模板解析失败。

> 实施状态：已完成。前后端契约、入库工作台交互、草稿兼容和三档真实视口验收均已落地；本文件末尾的“实施结果”记录当前验证证据。

## 现状结论

当前模板能力实际已经存在：

- 入库页挂载时调用 `GET /api/inbound-templates` 加载模板候选。
- 物品存在物品属性模板时，前端读取其 `default_inbound_template_id` 并尝试自动套用推荐入库模板。
- 明细“批次与属性”抽屉允许手动选择入库模板，并按模板渲染动态字段。
- 模板默认值会写入草稿；必填、数字、日期、URL、选择、布尔和图片字段会在提交前校验。
- 最终请求提交 `inbound_template_id` 和 `ext_attributes`，服务端继续执行最终校验。

因此问题不是功能完全缺失，而是以下体验和契约缺陷叠加后，让用户无法确认模板是否生效。

## 问题清单

### 1. 主列表没有模板状态

入库草稿主列表只展示物品、数量、单价、库位、小计和操作。用户必须打开“批次与属性”抽屉后，才能知道：

- 是否自动套用了推荐模板。
- 当前选择了哪套模板。
- 还有多少个必填属性未完成。
- 模板是否正在加载或加载失败。

这会让模板从主任务中消失，也让提交失败看起来是突然发生的。

### 2. 入口名称不能表达模板职责

“批次与属性”可以理解为批次号和普通附加信息，不足以提示其中包含“入库模板方案”。用户没有理由主动打开每一条明细检查模板。

### 3. 自动推荐没有反馈

新增物品后，推荐模板在后台异步加载。成功时没有行内反馈或 Notice，失败时错误只保存在明细状态中。用户看到的主列表与未启用模板时完全相同。

### 4. 权限契约不完整

进入入库页只要求 `stock.inbound.create`，但当前前端读取模板候选和物品属性模板详情还需要 `stock.template.read`。

这会产生以下不一致：

- 用户可以创建入库单，却可能无法获取入库模板字段。
- 页面只显示一次模板加载失败 Notice，模板选择器随后表现为空。
- 物品存在默认模板且字段必填时，用户可能无法完成入库任务。
- 前端无法区分“系统没有模板”和“当前账号没有模板读取权限”。

### 5. 失效默认模板会形成隐蔽阻塞

物品属性模板可以保留已删除入库模板的默认 ID。当前入库页会尝试加载该 ID，失败后把明细置为不可提交，但主列表不显示失效原因。

### 6. 切换模板会直接清空数据

手动更换或取消模板时，当前实现会删除该明细模板字段中的图片上传并清空全部扩展属性。用户没有看到明确的破坏性确认。

### 7. 模板候选加载失败没有持续状态

候选加载失败只通过临时 Notice 告知。Notice 消失后，页面缺少可重试入口和持续错误说明。

## 整改目标

- 用户不打开抽屉也能确认每条明细是否使用模板以及当前完成状态。
- 自动推荐模板成功、失败和失效都具有明确反馈。
- 入库创建权限足以完成入库任务，不要求用户额外拥有模板管理页面的读取权限。
- 模板切换不会静默丢失已填写属性或已选择图片。
- 模板候选加载失败可持续查看并重试，不伪装成空模板列表。
- 保持当前两步入库流程、单行明细模型和抽屉编辑方式，不增加独立模板选择步骤。

## 非目标

- 不把入库模板字段直接全部铺到主表格中。
- 不允许在入库工作台创建或修改模板结构。
- 不把物品长期属性复制为本次入库属性。
- 不增加服务端未提供的模板使用次数。
- 不改变模板字段、文件上传和最终入库校验的业务含义。

## 推荐交互方案

### 主列表模板摘要

不新增独立宽表格列，避免桌面与断点宽度再次被挤压。模板摘要放入现有物品身份区和操作区：

#### 物品身份区

物品基础信息下增加一行：

```text
入库模板：包装质检
```

显示规则：

| 状态 | 文案 | 颜色 |
| --- | --- | --- |
| 没有选择模板 | `入库模板：未设置` | 弱化色 |
| 正在解析默认模板 | `正在匹配推荐模板…` | 弱化色并带稳定等待状态 |
| 自动套用成功 | `入库模板：包装质检 · 已推荐` | 正文色，`已推荐` 使用主题色软标签 |
| 手动选择 | `入库模板：包装质检` | 正文色 |
| 推荐模板已删除 | `推荐模板已失效` | 警告色 |
| 模板加载失败 | `模板加载失败` | 危险色 |
| 无模板读取权限 | `无权读取入库模板` | 警告色 |

#### 操作区

把“批次与属性”改为“批次与入库属性”，按钮附近显示紧凑状态：

- `属性已完成`
- `待填写 2 项`
- `模板加载中`
- `需要处理`

按钮本身仍负责打开同一个明细抽屉，不在主表格重复模板选择器。

### 移动端明细卡片

移动端在库位和小计之后、操作按钮之前增加独立模板信息行：

```text
入库模板    包装质检 · 待填写 2 项
```

- 模板名称允许换行，不横向滚动。
- 错误状态整行可点击，点击后打开抽屉并聚焦模板选择或重试按钮。
- 触控目标保持至少 44px。

### 抽屉标题与结构

标题从“批次与属性”改为“批次与入库属性”，副标题继续显示物品名称、SKU 和单位。

抽屉内容顺序保持：

1. 批次号与有效期。
2. 入库模板方案。
3. 当前模板字段。
4. 完成按钮。

模板区域标题改为“入库模板”，说明文字为“记录本次收货状态，不会修改物品长期属性”。这可以同时解决用户对两类模板职责的混淆。

### 自动推荐反馈

新增物品后不自动打开抽屉，避免打断连续选品。改为行内反馈：

- 解析期间显示“正在匹配推荐模板…”。
- 推荐成功后显示模板名称和“已推荐”。
- 推荐模板存在必填字段时，状态立即显示 `待填写 n 项`。
- 推荐模板无必填字段且默认值有效时，可显示 `属性已完成`。
- 推荐失败时主列表显示持续状态，用户可进入抽屉处理。

不为每条成功推荐显示全局 Notice，避免多物品入库时产生提示轰炸。

### 模板切换确认

用户切换或取消模板时，先判断当前明细是否存在：

- 非空扩展属性。
- 已选择的本地图片。
- 已上传但尚未提交的文件 ID。

存在任一内容时显示嵌套确认 Dialog：

```text
更换入库模板？
当前已填写的模板属性和已选择图片会被清除。
```

操作为“继续编辑”和“清空并更换”。用户取消时选择器恢复原模板，不能先清空再询问。

### 候选加载失败

在模板选择器上方显示持续错误块：

- 加载失败原因。
- “重新加载模板”按钮。
- 已经成功加载到明细中的模板保持可编辑，不因全局候选刷新失败而清空。

权限不足与网络失败必须使用不同文案：

- `403`：`当前账号没有读取入库模板的权限。`
- 网络错误：`暂时无法加载入库模板，请检查服务连接。`
- 其它错误：`入库模板加载失败。`

## 状态模型整改

当前 `InboundDraftLine` 只有 `templateLoading`、`templateError`、`templateId` 和 `template`。建议增加明确来源和解析状态：

```ts
type InboundTemplateSource = 'none' | 'recommended' | 'manual'
type InboundTemplateState = 'idle' | 'resolving' | 'ready' | 'unresolved' | 'error'

interface InboundDraftLine {
  templateSource: InboundTemplateSource
  templateState: InboundTemplateState
  recommendedTemplateId: number | null
  templateId: number | null
  template: InboundTemplateResponse | null
  templateError: string
}
```

状态约束：

- `templateState = ready` 时 `template` 与 `templateId` 必须一致。
- `unresolved` 专门表示推荐 ID 已失效，不与网络错误混用。
- 手动选择成功后 `templateSource = manual`。
- 用户明确选择“不使用入库模板”后，不能再次被异步推荐响应覆盖。
- 迟到的默认模板请求不能覆盖用户已手动选择的模板。
- 草稿持久化保存来源、模板 ID 和字段值；恢复时重新解析活动模板定义。

## 权限与后端契约整改

### 推荐方案

模板管理页面继续使用：

- 读取：`stock.template.read`
- 写入：`stock.template.manage`

入库任务读取所需模板定义时，允许以下任一权限：

- `stock.inbound.create`
- `stock.template.read`

该放行只适用于读取活动入库模板列表和详情，不包含分类、物品属性模板、复制、修改或删除。

### 默认模板 ID 获取

当前前端为了读取 `default_inbound_template_id`，需要再次请求物品属性模板详情。建议把推荐入库模板 ID 放入入库选品契约：

```json
{
  "id": 12,
  "name": "红酒礼盒",
  "attribute_template_id": 3,
  "recommended_inbound_template_id": 5
}
```

由 core 在物品轻量选项查询中解析活动物品模板及其默认入库模板。前端不再为了入库任务读取完整物品属性模板结构。

失效默认 ID 有两种可选契约：

1. 推荐：返回原始 `recommended_inbound_template_id` 和 `recommended_inbound_template_available`，让前端明确显示失效状态。
2. 简化：只返回活动模板 ID；失效值返回空。缺点是用户无法区分“未设置”和“已失效”。

推荐采用第一种，以便主列表提供准确修复提示。

### OpenAPI 与文档

后端实施必须同步：

- 入库模板 GET 路由的任一权限规则。
- `ItemOptionResponse` 的推荐入库模板字段。
- OpenAPI schema 与权限说明。
- `core/docs/business-api/inbound.md`。
- `core/docs/business-api/permissions.md`。
- controller/service 定向权限测试。

## 前端模块调整

### `frontend/src/api/items.ts`

- 扩展 `ItemOptionResponse` 推荐模板字段。
- 不再通过 `getItemAttributeTemplate` 解析默认入库模板。

### `frontend/src/pages/inbound-draft/model.ts`

- 增加模板来源和解析状态。
- 增加 `requiredTemplateFieldCount`、`incompleteTemplateFieldCount` 和行模板摘要派生函数。
- 保持 `buildInboundRequest` 只提交最终模板 ID 与实际属性。

### `frontend/src/pages/InboundDraftPage.vue`

- 把候选列表加载改为可持续状态，而不是只有 Notice。
- 新增物品时直接读取 `recommended_inbound_template_id`。
- 使用请求版本或用户选择序号防止异步推荐覆盖手动选择。
- 编排模板切换确认 Dialog。
- 后端模板错误继续定位到对应明细抽屉。

### `frontend/src/components/inbound/InboundDraftStep.vue`

- 展示主列表模板摘要、来源和完成状态。
- “批次与属性”重命名为“批次与入库属性”。
- 错误状态可直接打开并聚焦对应模板控件。

### `frontend/src/components/inbound/InboundLineEditor.vue`

- 模板区域补充职责说明。
- 接收候选加载状态和重试事件。
- 切换模板只发出意图，不直接清理草稿。

### `frontend/src/pages/InboundDraftPage.scss`

- 桌面身份区增加不挤压数量、单价、库位列的模板摘要。
- 1024 附近允许模板状态自然换行。
- 移动端模板信息独占一行，错误和待填状态不被截断。

## 异步与竞态处理

### 推荐模板请求

- 每条明细拥有独立请求版本。
- 用户手动选择后增加版本，旧推荐请求响应直接丢弃。
- 删除明细时取消对应模板请求。
- 恢复草稿时以草稿中的明确手动选择为准，不重新覆盖为推荐模板。

### 候选列表刷新

- 后台刷新保留旧候选和已选模板。
- 刷新失败只更新错误状态，不把候选清空。
- 已选模板不再出现在活动候选中时，显示 `已删除模板 #<id>`，并要求用户处理。

### 提交期间

- 模板正在解析、加载失败或存在必填属性错误时继续阻止提交。
- 主列表与抽屉同时呈现同一原因。
- 服务端返回 `template_not_found`、`invalid_inbound_field` 或 `inbound_file_unavailable` 时，打开对应明细并聚焦模板区域。

### 第一阶段：后端契约与权限

1. 明确入库模板 GET 接口的任一权限规则。

3. 更新 OpenAPI、权限文档和 core 测试。
4. 用只有 `stock.inbound.create` 的账号验证模板可读、模板管理不可写。

### 第二阶段：前端状态模型

1. 扩展 `InboundDraftLine` 模板来源和解析状态。
2. 移除入库页对物品属性模板详情接口的依赖。
3. 增加异步请求版本和草稿恢复兼容迁移。
4. 增加模板完成度派生函数。

### 第三阶段：主列表可见性

1. 在桌面和移动明细中加入模板摘要。
2. 显示自动推荐、待填写、完成、失效和错误状态。
3. 重命名“批次与属性”入口。
4. 让错误状态直接打开对应抽屉位置。

### 第四阶段：抽屉与破坏性操作

1. 补充模板职责说明和候选加载错误块。

3. 增加模板切换清空确认。

### 第五阶段：真实场景验收

3. 在桌面、1024 断点和移动端截图审核。

## 验收标准

### 可发现性

- 每条入库明细在主列表中始终显示模板状态。
- 用户无需打开抽屉即可知道模板名称和待填必填项数量。
- 自动推荐模板成功后在当前行显示“已推荐”。
- “批次与入库属性”入口能准确表达其中包含模板字段。

### 权限

- 只有 `stock.inbound.create` 的用户可以读取并填写入库模板。
- 该用户仍不能进入模板管理页面或修改模板。
- 缺少模板读取能力时页面显示持续权限错误，不能伪装成“没有模板”。

### 数据安全

- 更换或取消模板前，已填写属性或图片存在时必须确认。
- 用户取消确认后原模板和全部字段值保持不变。
- 迟到的推荐响应不能覆盖手动选择。
- 删除或失效模板不会被静默当作未设置。

### 异步状态

- 推荐解析、候选加载、字段加载和重试状态互不覆盖。
- 后台刷新候选失败时保留旧候选与当前选择。
- 草稿恢复后模板状态、来源和字段值一致。
- 提交错误能够回到准确明细和字段。

### 响应式与界面

- `1440 × 900` 下模板摘要不挤压数量、单价、库位和操作列。
- `1024 × 768` 下模板名称和状态允许换行，操作按钮完整可见。
- `390 × 844` 下模板信息独占一行，无横向滚动或文字截断。
- 模板状态的参数名和值使用不同颜色和字重，错误不只依赖颜色表达。
- 动画复用现有 motion token，并遵守 `prefers-reduced-motion`。

## 截图场景

每个目标视口至少检查：

1. 未设置模板。
2. 自动推荐成功且属性已完成。
3. 自动推荐成功但仍有两个必填项。
4. 手动选择模板。
5. 推荐模板已删除。
6. 模板候选网络加载失败。
7. 只有入库权限、没有模板管理权限的账号。
8. 切换模板时的清空确认 Dialog。

## 完成定义

只有前后端权限契约、推荐模板字段、前端主列表状态、抽屉交互、破坏性确认、草稿兼容、定向测试和三档截图全部完成，才算本整改结束。仅修改按钮名称或增加一次性 Notice 不算完成。

## 实施结果

- 后端已让 `GET /api/inbound-templates` 与 `GET /api/inbound-templates/{id}` 接受 `stock.inbound.create` 或 `stock.template.read` 任一权限；`GET /api/items/options` 返回推荐模板 ID 与可用状态，失效模板保留原始 ID。
- 前端已使用选品轻量响应完成推荐模板解析，主列表持续展示模板名称、推荐标记、待填写数量、完成、失效和错误状态；模板候选错误提供持续重试入口，切换模板会先确认并清理属性/图片。
- 草稿存储升级为 `v5`，兼容 `v4`；推荐请求带独立版本，迟到响应不会覆盖手动选择，候选刷新发现已删除模板时会立即标记为失效。
- 定向验证已通过：`cargo fmt --all`、两条库存模板权限/推荐状态测试、`cargo test -p winestock-core http_openapi`、`pnpm build` 和 `git diff --check`。
- 真实运行截图位于 `target/validation/inbound-template-remediation/`：`00-desktop-no-template.png`（未设置）、`01-desktop-pending.png`（1440×900 推荐且待填）、`02-tablet-complete.png`（1024×768 完成态）、`03-template-switch-confirm.png`（模板切换确认）、`04-mobile-unresolved.png`（390×844 失效推荐）、`05-desktop-manual-template.png`（手动模板）和 `06-desktop-template-load-error.png`（候选加载错误与重试）。七个对应 JSON 记录的 `documentWidth` 均等于 `viewportWidth`，未发现横向溢出；只有入库创建权限的读取例外由后端定向权限测试覆盖。
