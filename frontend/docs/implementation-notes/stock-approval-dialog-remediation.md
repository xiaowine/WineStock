# 库存审批 Dialog 整改报告

本文记录入库审批与出库审批审核 Dialog 的问题分析、目标结构、重写边界和验收标准。

## 问题结论

旧版 Dialog 同时存在标题说明、库存影响块、上下文条和摘要卡片四套层级。状态、来源/去向和创建时间在不同区域重复出现，各区块又分别维护背景、边框和 margin，导致页面像多张小卡片连续堆叠。简单交换 DOM 顺序只会改变混乱出现的位置，不能建立稳定阅读层级。

## 对照项目模式

项目内成熟详情 Dialog 使用一个统一纵向工作区，通过父级 `gap` 管理“主要状态、结构化信息、业务详情”之间的距离。结构化键值采用连续边框网格，不让每个字段组成为独立浮动卡片。

## 最终结构

```text
Dialog Header：单号 + 一句稳定说明
Dialog Body
  库存影响：待审批状态、通过后的库存变化、提交时间、事务后果
  单据信息：来源/去向、创建时间、创建人、备注
  入库物品 / 出库物品：业务明细
Dialog Actions：关闭、拒绝、通过
```

## 重写原则

- 删除独立 `approval-dialog-context`，不再维护第三套上下文条。
- 状态和提交时间并入库存影响区。
- 来源/去向只在“单据信息”中出现一次。
- 标题说明只描述审核对象，不承担操作教程。
- 正文使用单一 `approval-review` 网格控制段落间距：桌面 `18px`，移动 `14px`。
- 单据信息使用连续边框网格：桌面两列，移动单列。
- 入库与出库只改变真实业务文案和明细内容，不改变页面骨架。

## 文案

- 入库说明：`核对待审批入库单的库存影响与业务明细。`
- 入库影响：`通过后将增加库存`
- 出库说明：`核对待审批出库单的库存影响与业务明细。`
- 出库影响：`通过后将扣减库存`

## 实施范围

- `ApprovalReviewDialog.vue`：重写正文结构和文案。
- `StockApprovalWorkspace.scss`：删除旧上下文条和零散 margin，建立统一 review/section/metadata 样式。
- `page-stock-approvals.md`：同步最终信息架构。

不修改 API、权限、审批事务、确认阶段或成功后的队列协调。

## 验收标准

- 首屏只存在“库存影响、单据信息、业务明细”三个正文层级。
- 来源/去向和创建时间不在正文重复出现。
- 库存影响标题、状态和提交时间在同一区域内对齐。
- 单据信息桌面两列、移动单列，无横向溢出。
- Dialog Actions 始终保持可见，不被正文 margin 推动或覆盖。
- 在 `1440 × 900`、约 `768px`、`390 × 844` 截图检查层级、留白、滚动和按钮区。
- `pnpm build`、Prettier、`git diff --check` 和浏览器控制台检查通过。
