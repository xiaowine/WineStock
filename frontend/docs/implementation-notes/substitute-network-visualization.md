# 替代关系星链网络实施方案

本文定义替代关系页面的“星链式关系网络”扩展方案，包括入口位置、信息架构、力导向布局、视觉语义、交互、响应式、可访问性、性能边界、模块拆分和验收标准。

本方案是 [`../page-substitutes.md`](../page-substitutes.md) 的可视化扩展，不替代现有三段式关系列表，也不改变 `core` 的有向关系、整体替换、循环校验和权限规则。

## 一、设计结论

关系网络用于理解全局结构，列表继续承担精确浏览和管理：

- **三段式列表**：适合搜索、阅读名称与 SKU、查看优先级摘要和进入编辑器。
- **星链网络**：适合发现多级替代链、共同依赖节点、交叉关系和影响范围。
- **替代关系编辑 Dialog**：继续拥有候选搜索、优先级、备注、移除和整体保存。

星链网络第一阶段只读。用户可以在网络中选择和分析节点，但不能直接拖动连线创建关系，也不能删除边。需要修改时，从节点详情进入现有编辑 Dialog。

这样可以避免出现三套业务逻辑：列表一套、星图一套、物品 Dialog 一套。

## 二、页面入口

### 工具栏按钮

在替代关系页面工具栏新增“关系网络”图标按钮：

```text
搜索关系       4 个主物品 / 9 条关系    [刷新] [关系网络] [+]
```

按钮规则：

- 使用中性 `icon-button`，不使用主题色填充。
- 放在刷新按钮与主题色新增按钮之间。
- 图标复用库位管理“选择分组”的树状层级图标，表达多个节点及连接关系，并继续使用项目统一的 `18px` 单色圆端线性语言。
- `title` 和 `aria-label` 使用“查看替代关系网络”。
- 只依赖 `stock.substitute.read`；只读用户同样可以查看网络。
- 页面尚未加载完成时禁用；刷新期间仍可查看旧网络，但按钮显示当前数据正在刷新。

新增关系仍是唯一主题色主操作，关系网络属于辅助观察入口。

## 三、Dialog 信息架构

使用项目通用 `ModalDialog` 的 `workspace` 形态，标题为“替代关系网络”。

### 桌面结构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 替代关系网络                                              [关闭]      │
│ 查看物品之间的有向替代链、共同依赖和上下游影响                       │
├──────────────────────────────────────────────────────────────────────┤
│ [搜索名称或 SKU] [全部关系 / 直接关系]  7 个节点 · 9 条关系          │
│                                                                      │
│  [适应画布] [放大] [缩小] [复位]                      [图例]          │
│                                                                      │
│       ○ 物品 B ──1──▶ ● 当前物品 A ──2──▶ ○ 物品 C                  │
│          ╲                       ╲                                    │
│           ╲3                      ╲1                                  │
│            ▶ ○ 物品 D              ▶ ○ 物品 E                       │
│                                                                      │
│                         星链画布                                     │
├──────────────────────────────────────────────────────────────────────┤
│ 当前节点：物品 A · SKU A001                                          │
│ 上游 2 个 · 直接替代 3 个 · 可到达 5 个                     [维护关系] │
└──────────────────────────────────────────────────────────────────────┘
```

Dialog 分为四层：

1. 固定标题栏：标题、说明和关闭按钮。
2. 固定网络工具栏：搜索、观察范围、统计和画布控制。
3. 弹性画布：节点、方向边、优先级和聚焦效果。
4. 画布内悬浮节点详情：当前节点摘要和进入现有编辑器的操作，不占用网格行或改变画布尺寸。

画布独立占满剩余高度，Dialog 本身不跟随节点数量无限增高。

### 移动结构

- Dialog 使用全屏或接近全屏工作面板。
- 搜索独占一行，统计和画布控制组成第二行。
- 画布占主要高度，不能在移动端退化成缩小版桌面截图。
- 节点详情使用覆盖在画布底部的悬浮摘要栏；点击后可向上展开关系详情，不推动或重排画布。
- 不显示依赖悬浮的 Tooltip；选中节点后直接显示详情。
- 放大、缩小和复位必须有按钮，不能只依赖双指手势。

## 四、星链视觉语言

### 整体风格

目标是“浅色星图”，不是深色监控大屏：

- 画布使用项目表面色或略微偏灰的浅色背景。
- 普通节点使用白色表面、细灰边框和轻微阴影。
- 每个物品按稳定 ID 分配一种低饱和浅色和对应边框色，帮助用户在交叉连线中区分节点；颜色只承担识别辅助，不承担方向、优先级或状态语义。
- 选中节点使用酒红主题色边框、浅主题色填充和低强度光晕。
- 连线使用低饱和灰色；当前链路使用主题色。
- 不使用霓虹蓝、黑色宇宙背景、强发光粒子或持续闪烁动画。
- 不通过颜色单独表达方向和优先级；箭头和数字必须始终可见。

### 节点

节点由圆形星点和文字标签组成：

- 圆形主体建议直径 `36–52px`。
- 节点大小按连接度分为三档，而不是按库存或价格连续缩放。
- 标签显示物品名称，第二行可显示 SKU。
- 标签使用贴附节点的浅色信息牌，名称作为主层级，`SKU · 编号` 作为次层级，避免文字悬空后无法判断归属。
- 名称默认最多两行，超长省略；选中后在详情区显示完整值。
- 节点连接度高时只增加有限尺寸，不能让核心节点遮挡邻居。
- 只有出现在 `/api/substitutes` 关系中的物品才生成节点；当前接口无法生成完全没有关系的孤立物品。

节点状态：

| 状态       | 表现                               |
| ---------- | ---------------------------------- |
| 普通       | 白色节点、灰色边框、正常标签       |
| 悬浮       | 边框增强，显示简短名称/SKU Tooltip |
| 键盘焦点   | 项目统一焦点环，不与选中态混淆     |
| 选中       | 酒红边框、浅主题背景、轻微光晕     |
| 直接上游   | 边框增强，关系边高亮并指向当前节点 |
| 直接下游   | 浅主题色边框，关系边从当前节点指出 |
| 非当前链路 | 降低透明度，但仍保持可辨识和可点击 |

### 方向边

每条边表示一条真实关系：

```text
主物品 ──优先级──▶ 替代物品
```

规则：

- 箭头始终指向替代物品。
- 边中部显示优先级数字，使用紧凑浅色标签。
- 优先级不能仅通过线条粗细或颜色深浅表示。
- 备注不直接铺在画布上；选中边或相关节点后在详情区显示。
- 多条边交叉时保持细线，并通过曲线弧度或轻微偏移减少完全重叠。
- A→B 和 B→A 如果历史数据异常同时存在，必须画成两条方向明确的弧线；当前服务端正常情况下会阻止循环。

## 五、数据模型

网络直接复用 `SubstitutesPage.vue` 已加载的 `SubstituteRelationResponse[]`，打开 Dialog 不重复请求全局接口。

### 节点模型

```ts
interface SubstituteNetworkNode {
  id: number;
  name: string;
  sku: string;
  incomingCount: number;
  outgoingCount: number;
  degree: number;
}
```

节点来自所有关系中主物品与替代物品的并集，以物品 ID 去重。

### 边模型

```ts
interface SubstituteNetworkEdge {
  id: string;
  sourceId: number;
  targetId: number;
  priority: number;
  notes: string | null;
  createdAt: string;
}
```

边 ID 使用稳定组合键：

```text
<主物品 ID>:<替代物品 ID>
```

不能用数组下标作为节点或边 key。

### 派生数据

前端可从当前全量关系派生：

- 节点入度：有多少主物品把它作为替代物品。
- 节点出度：它配置了多少个直接替代物品。
- 直接上游和直接下游。
- 从当前节点可到达的下游节点。
- 当前节点所在的弱连通分量。
- 连接度最高的核心节点。

前端不得派生或伪造：

- 未配置关系物品数量。
- 节点库存状态。
- 替代成功率。
- 关系使用次数。
- 风险评分。

这些能力需要后端提供额外数据后才能加入。

## 六、力导向布局

### 布局目标

网络应呈现自然分布的星链，而不是固定树形层级：

- 有关系的节点自动靠近。
- 高连接度节点自然位于局部中心。
- 不同连通分量保持间距。
- 节点之间有碰撞边界，不发生文字完全覆盖。
- 用户拖动节点后，节点保持在新位置，不立刻弹回。

### 推荐实现

推荐使用“原生 SVG 渲染 + 力导向布局计算”：

- SVG 负责节点、方向边、文字、箭头、焦点和可访问性。
- 力导向算法只负责计算 `x/y`，不直接操作 DOM。
- Vue 继续拥有状态和渲染，不能让第三方库接管组件树。

实现前需要完成依赖决策：

1. 优先评估轻量、自维护的确定性力导向实现是否满足当前规模。
2. 若使用 `d3-force`，必须按照项目依赖规则核对当前稳定版本、包体积、许可证和 Tree Shaking，再更新 `package.json` 与锁文件。
3. 不为了整个 D3 生态只引入一个布局能力；只允许引入力计算所需模块。

### 建议参数范围

参数最终以浏览器截图和真实尺寸调优，不作为硬编码业务规则：

- 节点斥力：约 `-180` 到 `-320`。
- 连线目标距离：约 `88px` 到 `150px`。
- 碰撞半径：节点半径加标签避让空间。
- 中心力：只保证网络留在画布附近，不把所有节点压在中心。
- 衰减：布局稳定后停止持续计算，避免页面长期消耗 CPU。

优先级不直接决定连线距离。优先级是业务顺序，不代表关系强度或空间远近。

### 稳定布局

关系网络不能每次打开或刷新都随机换位：

- 初始位置使用物品 ID 派生的确定性种子。
- 同一批数据重复打开时尽量保持节点位置。
- 刷新后保留仍存在节点的位置。
- 新节点优先从相邻节点附近进入。
- 关系编辑或刷新导致节点消失时直接移除；网络本身没有删除入口，不为不可直接触发的操作维护专用删除动画，剩余节点位置仍应保持稳定。
- 用户拖动的位置在本次页面会话中保留，不写入服务端。

## 七、交互设计

### 打开网络

- 点击工具栏“关系网络”按钮打开 Dialog。
- 首次打开自动适应全部节点。
- 如果页面当前有搜索词，网络仍默认展示完整关系，不把列表局部搜索误认为网络数据范围。
- 可提供“仅显示搜索命中链路”按钮，由用户明确切换。

### 选择与聚焦

点击节点后：

1. 当前节点进入选中态。
2. 直接上游、直接下游和对应方向边高亮。
3. 其它节点降低透明度。
4. 节点详情区显示名称、SKU、入度、出度和关系摘要。
5. 再次点击空白画布清除选中。

观察范围：

- `全部关系`：显示完整网络，非相关节点降低透明度。
- `直接关系`：只显示当前节点和一跳上下游。
- 后续可增加 `两级关系`，但第一阶段不要同时提供过多层级选项。

### 搜索定位

- 搜索匹配节点名称和 SKU。
- 输入防抖后高亮匹配节点，不删除其它节点。
- 单个命中时自动平移到画布中心。
- 多个命中时显示紧凑结果列表，选择后定位。
- 无结果只显示“没有匹配的网络节点”，不影响画布现有状态。
- 清除搜索恢复当前缩放和选中节点。

### 画布操作

- 鼠标滚轮或触控板缩放。
- 拖动画布平移。
- 拖动节点调整位置。
- `+`、`−` 按钮按固定级别缩放。
- `适应画布` 把所有可见节点放入视口。
- `复位布局` 重新运行确定性布局，需要二次确认或明确说明会丢弃本次拖动位置。
- 缩放范围建议限制在 `0.45–2.2`，避免节点无限缩小或放大。

### 进入编辑

节点详情提供：

- `维护关系`：仅 `stock.substitute.manage` 显示；关闭网络 Dialog，然后打开现有 `SubstituteEditorDialog`。

不要在大型网络 Dialog 上再叠加另一个大型编辑 Dialog。推荐流程：

```text
网络 Dialog
  -> 记录选中节点和画布状态
  -> 关闭网络
  -> 打开现有编辑 Dialog
  -> 保存或关闭
  -> 返回网络并恢复原选中节点与缩放位置
```

## 八、动效

### Dialog 动效

- 继续复用 `ModalDialog` 的打开和关闭 motion token。
- 不新增全屏淡入以外的独立遮罩动画。

### 网络动效

- 首次布局从邻近确定性位置短距离展开，不从画布中心爆炸散开。
- 聚焦节点时只过渡透明度、边颜色和轻微缩放。
- 新增节点从关联节点附近进入。
- 关系编辑或刷新后直接移除已经不存在的节点，不增加网络内删除动效。
- 布局稳定后停止持续漂浮；星链感来自结构，不来自永不停息的晃动。

### 减少动态效果

`prefers-reduced-motion: reduce` 时：

- 跳过节点展开和位置补间。
- 直接使用最终布局。
- 保留选中、方向和焦点状态。
- 不影响搜索、防抖和异步稳定状态计时。

## 九、异步状态

网络复用页面已经成功加载的数据：

| 状态         | 表现                                         |
| ------------ | -------------------------------------------- |
| 页面尚未加载 | 网络按钮禁用                                 |
| 打开时有数据 | 立即构建网络，不重复请求                     |
| 空关系       | Dialog 显示“暂无可构建的替代关系网络”        |
| 页面后台刷新 | 保留现有节点和位置，显示“数据正在刷新”       |
| 刷新成功     | 合并节点与边，保留已有位置和选中态           |
| 刷新失败     | 网络继续使用旧数据，显示页面已有错误 Notice  |
| 编辑保存成功 | 使用页面刷新后的关系重建网络，并恢复来源节点 |

布局计算超过 `200ms` 时才显示“正在整理关系网络…”，出现后至少保持 `350ms`。不能先显示空画布再突然跳出节点。

## 十、响应式设计

### `1440 × 900`

- Dialog 建议宽度 `min(1180px, calc(100vw - 40px))`。
- 画布可用高度至少 `600px`。
- 节点详情固定在底部或右侧，但不能同时占用两块大区域。
- 工具栏保持一行，搜索宽度约 `280–360px`。

### `1024 × 768`

- Dialog 接近全屏。
- 搜索独占第一行；范围、统计和画布控制进入第二行。
- 节点详情使用底部横向摘要，避免压缩画布宽度。
- 图例默认收起，通过图标按钮打开。

### `390 × 844`

- 使用移动全屏工作面板。
- 工具栏固定，画布独立占据剩余区域。
- 节点标签只显示名称，SKU 进入底部详情。
- 触控节点视觉直径可以小于 `44px`，但透明点击范围必须至少 `44×44px`。
- 单指拖动画布，双指缩放；拖动节点需要短按命中后移动，避免和页面滚动冲突。
- 网络打开时锁定背景页面滚动，关闭后恢复主列表原滚动位置。

## 十一、可访问性

SVG 星图不能只对鼠标用户可用：

- 画布使用 `role="application"` 或经过验证的等价结构，并提供简短操作说明。
- 节点使用可聚焦元素或 SVG button 等价语义。
- 使用 roving tabindex，避免数百个节点全部进入 Tab 顺序。
- 方向键在邻近节点间移动焦点；Enter 选中，Escape 清除选中或关闭最上层浮层。
- 节点可访问名称包含名称、SKU、上游数量和替代数量。
- 边无需全部进入 Tab 顺序；选中节点后在详情区以文本列表展示其有向关系和优先级。
- 关闭网络后返回原关系列表；列表是网络不可访问时的完整等价信息来源，不在悬浮详情中重复增加“查看列表”按钮。
- 颜色不是唯一信息，方向箭头、优先级数字和文字摘要必须保留。

## 十二、性能边界

当前 `/api/substitutes` 是全量接口，第一阶段按以下规模设计：

| 规模           | 策略                                                       |
| -------------- | ---------------------------------------------------------- |
| `≤ 80` 节点    | 默认显示完整星链网络                                       |
| `81–180` 节点  | 仍可显示完整网络，但标签按缩放级别隐藏，布局稳定后停止计算 |
| `181–300` 节点 | 默认只显示连接度较高节点和当前搜索链路，并提供“显示全部”   |
| `> 300` 节点   | 不直接渲染完整 SVG；提示通过搜索选择中心节点后查看局部网络 |

性能要求：

- 打开已有小型网络不重复请求 API。
- 布局计算不能阻塞页面输入和关闭操作。
- 大规模时考虑把力计算移入 Web Worker，但第一阶段不提前引入。
- 缩放过程中不重新运行力布局。
- 节点文字按缩放级别显示，避免大量 SVG 文本长期参与绘制。

## 十三、前端模块拆分

职责：

- `SubstituteNetworkDialog.vue`：拥有搜索、观察范围、画布控制、详情和关闭编排。

## 十五、验收标准

### 数据正确性

- [ ] 节点集合等于所有主物品与替代物品 ID 的并集。
- [ ] 边数量等于当前全局关系数量。
- [ ] 每条边从主物品指向替代物品，优先级数字正确。
- [ ] 搜索、刷新和编辑保存后不会产生重复节点或重复边。
- [ ] 网络不显示接口没有提供的库存状态、孤立物品或风险评分。

### 交互

- [ ] 网络按钮位置、尺寸和中性样式与刷新按钮一致。
- [ ] 点击节点能高亮直接上下游，点击空白可清除选中。
- [ ] 搜索能定位名称和 SKU，清除后恢复原画布状态。
- [ ] 缩放、平移、拖动节点、适应画布和复位均可使用。
- [ ] 从节点进入编辑器后，保存或关闭能恢复网络上下文。
- [ ] 网络中不存在直接创建、删除关系的重复编辑入口。

### 响应式与真实尺寸

- [ ] `1440 × 900` 截图中完整显示工具栏、画布和节点详情。
- [ ] `1024 × 768` 不压缩搜索、关闭按钮或画布控制。
- [ ] `390 × 844` 使用移动全屏工作面板，无页面级横向滚动。
- [ ] Dialog、画布、节点详情满足 `scrollWidth === clientWidth`。
- [ ] 节点点击区域至少 `44×44px`，移动端底部详情不遮挡最后一行画布控制。
- [ ] 打开和关闭网络后，主列表滚动位置不变。

### 动效与性能

- [ ] 网络稳定后停止力计算，不持续漂浮或占用 CPU。
- [ ] 刷新保留已有节点位置，新节点从邻近位置进入。
- [ ] `prefers-reduced-motion` 下直接使用最终布局。
- [ ] 80、180 和 300 节点测试数据分别触发正确呈现或降级策略。
- [ ] 浏览器性能记录无明显长任务，关闭 Dialog 后无遗留定时器或 Worker。

### 可访问性与控制台

- [ ] 键盘可以选择节点、查看文本关系并返回触发按钮。
- [ ] 读屏能够识别节点名称、SKU、方向和关系数量。
- [ ] 颜色不是方向、选中或优先级的唯一表达。
- [ ] 三档视口控制台无新增错误、警告或未处理 Promise。

## 十六、当前不实施的能力

- 不在网络中直接拖线创建替代关系。
- 不在网络中删除单条边。
- 不提供深色科技大屏主题。
- 不根据优先级改变节点距离。
- 不把替代关系自动解释为双向。
- 不显示全局库存状态，直到后端提供批量摘要契约。
- 不保存用户拖动后的节点位置到服务端。
- 不引入 3D、WebGL 或粒子背景。
