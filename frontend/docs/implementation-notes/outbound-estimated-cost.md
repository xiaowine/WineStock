# 新建出库预计成本统计实施方案

## 结论与范围

`/outbound` 需要补充的是提交前的**预计出库成本**，与 `/inbound` 的“预计金额”同属前端草稿统计：用户填写数量、选择 FIFO 或指定批次后，页面基于当前批次库存快照估算本次出库的成本。

首期不改数据库、不改 `POST /api/outbound` 请求，也不写入成本。预估值不是实际成本：直接出库或后续审批真正扣减库存时，仍会基于当时批次确认，因此 FIFO 结果仅能是预估。

本方案只属于 `frontend`。前端通过 HTTP 读取现有 core 契约，不直接访问 Rust 业务或数据库。

## 已有契约与可复用数据

现有 `GET /api/items/{item_id}/batches` 已返回仍有余额的批次分页，单个批次包含：

| 字段                           | 用途                                      |
| ------------------------------ | ----------------------------------------- |
| `id`                           | 指定批次匹配与缓存键。                    |
| `location_id`、`location_name` | FIFO 限制库位与扣减说明。                 |
| `remaining_quantity`           | 批次可参与预估的当前余额。                |
| `unit_cost`                    | 批次单位成本。                            |
| `received_at`                  | FIFO 排序依据；不得依赖当前页面加载顺序。 |

前端现有 `ItemBatchStockResponse` 已声明 `unit_cost`。因此首期不需要新增 core API。请求权限沿用当前 `stock.item.read` 或 `stock.outbound.create` 的批次读取边界。

## 成本口径

### 指定批次

当明细选择 `specific_batch` 且批次候选已加载：

```text
预计成本 = 出库数量 × 指定批次 unit_cost
```

该值是当前批次快照下的精确算术结果；它仍不是审批完成后的成本事实。

### FIFO

当明细选择 `fifo`：

1. 读取该物品的所有仍有余额批次，直到分页耗尽。
2. 如设置 `location_id`，只保留该库位的批次；未设置时保留所有库位。
3. 按 `received_at` 升序排序；同一时间以 `id` 升序保证前端计算稳定。
4. 从最早批次开始分配 `min(待分配数量, remaining_quantity)`。
5. 对每段分配累加 `分配数量 × unit_cost`，直到数量耗尽或无可用批次。

FIFO 预估须同时返回覆盖状态：

- `complete`：当前快照可覆盖全部数量，展示预计成本。
- `insufficient`：当前库存快照无法覆盖全部数量，成本显示为“以实际出库为准”；不得阻止创建待审批单。
- `loading`：等待批次分页完成，不展示误导性的零金额。
- `failed`：读取失败或无权限，显示“暂无法估算”；不阻断提交。

不同物品单位不能相加为总数量，但货币成本可以跨物品汇总。

## 前端状态与模块调整

在 `pages/outbound-draft/model.ts` 增加纯函数和类型，不将计算散落在 Vue 模板：

```ts
type EstimatedCostState = "idle" | "loading" | "complete" | "insufficient" | "failed";

interface OutboundCostEstimate {
  state: EstimatedCostState;
  amount: number | null;
  coveredQuantity: number;
  requestedQuantity: number;
  allocationCount: number;
}
```

- `estimateSpecificBatchCost(line, batch)`：只在数量有效且批次存在时计算。
- `estimateFifoCost(line, batches)`：执行排序、库位过滤和逐批分配；输入数组不原地排序。
- `formatMoney` 复用入库页既有金额格式化规则，统一保留两位小数和 `¥` 前缀。

在 `OutboundDraftPage.vue` 维护按 `lineId` 分组的批次快照与请求状态。缓存键必须包含物品 ID；同一物品多次变更数量或方式时复用已完整加载的快照。物品被移出、页面卸载或刷新批次时清理对应请求控制器和缓存。

批次请求采用现有分页契约逐页追加，延续项目的无限滚动原则；成本计算可以在后台预取全部页，不能偷偷使用未分页的大请求。请求取消不显示错误，失败不清空已填写的出库草稿。

## 界面设计

### 页面头部摘要

在第二步已有“明细数 / 数量摘要”旁加入：

```text
预计出库成本  ¥1,280.00
```

- 仅当所有有效明细估算完成并且均可完整覆盖时显示金额。
- 仍在读取时显示紧凑的“正在估算成本…”，使用既有稳定等待规则，不闪烁骨架。
- 存在不足或失败明细时显示“部分成本待确认”，不显示看似准确的总金额；摘要本身不新增显眼状态色块。

### 明细行扣减摘要

现有可点击的“FIFO / 指定批次”摘要块补充一行成本信息：

- 指定批次：`预计 ¥xx.xx`。
- FIFO 完整覆盖：`预计 ¥xx.xx · n 个批次`。
- FIFO 快照无法覆盖：`成本以实际出库为准`。
- 加载：`正在估算成本…`。
- 无法读取：`暂无法估算成本`。

成本是扣减设置的派生信息，放在该摘要块内，不在数量输入框附近重复展示。

### 扣减设置 Dialog

指定批次候选继续显示批次、库位、余额和有效期，并增加紧凑成本信息：`成本 ¥xx.xx / 单位`。选中后在 Dialog 底部显示本明细“预计出库成本”，供用户在应用前确认。

FIFO 模式显示说明：

> 按当前批次可用数量和先进先出顺序估算；实际出库时会按实际库存重新校验，预计成本可能变化。

该提示仅在成本已完成、不足或失败时按状态变化，避免在主工作区重复解释。

### 提交确认 Dialog

在“出库去向、明细”后增加“预计出库成本”。金额仅在总估算完整时展示；否则展示“实际出库时按扣减批次确认”，并保留直接出库或提交审核的原有语义。预估失败、库存快照无法覆盖不阻塞提交。

## 刷新、草稿与直接出库

- 草稿只保存用户输入的数量、扣减方式、批次和库位，不保存估算金额或批次快照。恢复草稿后重新读取成本数据。
- 数量、模式、指定批次或 FIFO 库位变化时，立即使对应估算失效，再基于缓存或新请求重算。
- 直接出库用户在“确认直接出库”前也只看到预估。创建后到审批请求间或审批事务内的库存变化，均由服务端最终判断。
- 提交审核用户的预估只用于申请前决策；待审批期间不持续刷新或推送成本。

## 错误与边界

| 场景              | 呈现与行为                                                        |
| ----------------- | ----------------------------------------------------------------- |
| 批次读取 403      | 显示“无权读取批次，暂无法估算成本”；不暴露成本值，不阻止提交。    |
| 网络或解析失败    | 明细和汇总显示“暂无法估算”；提供在扣减 Dialog 内重试。            |
| FIFO 快照无法覆盖 | 显示“成本以实际出库为准”；不以快照替代实际出库库存校验。          |
| 指定批次失效      | 沿用当前明细校验，要求用户重新选择；不计算成本。                  |
| 货币精度          | 计算阶段使用 number，展示统一两位小数；不把显示值回写请求或草稿。 |

若未来需要保存审批后的实际成本、审计成本分摊或统计销售毛利，再单独启动 core 迁移与事务方案；这不是本方案的工作内容。

## 实施步骤

1. 抽取并单测 FIFO/指定批次的纯估算函数，覆盖库位过滤、同时间稳定排序、跨批次分摊、库存快照无法覆盖和非法数量。
2. 在页面增加按明细批次快照的缓存、取消与分页加载，完成草稿恢复后的重算。
3. 接入明细摘要、页面摘要和提交确认 Dialog；沿用入库金额格式与既有线性图标/低密度信息层级。
4. 在扣减设置 Dialog 中补充单位成本、单行预估和 FIFO 口径说明。
5. 浏览器检查桌面 `1440×900`、约 `768px`、移动 `390×844`：无重叠、横向溢出、摘要不遮挡按钮、Dialog 内容可滚动且操作区可达。

## 验收标准

- 指定批次数量变更后，单行、头部与确认 Dialog 的预计成本一致。
- FIFO 跨多个批次的结果符合 `received_at`、`id` 的稳定排序和逐批分摊规则。
- FIFO 限定库位后，只使用该库位批次；不同物品成本正确汇总。
- 库存快照无法覆盖、候选为空、网络失败、403、草稿恢复和直接出库/提交审核都不会显示虚假的确定金额，也不影响既有提交路径。
- `pnpm build` 与 `git diff --check` 通过；真实浏览器三个目标视口无新增控制台 error、warning 或横向溢出。
