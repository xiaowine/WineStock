# 异步状态切换

本文记录 WineStock 各平台通用的异步呈现规则，避免加载、恢复和刷新等快速异步操作造成闪烁、尺寸跳变或重复遮挡。
规则平台无关：前端页面、桌面/Android shell 的原生加载遮罩都应遵循同一套语义。
组件特定的实现文件和参数落地记录在各自组件的文档中，本文只定义通用规则。

## 目标

异步状态需要同时满足：

- 快速完成的操作不闪现加载提示。
- 已经出现的加载提示不会立即消失。
- 明确错误及时呈现，不因视觉延迟掩盖故障。
- 后台刷新尽量保留已有内容，不反复清空界面。
- 同类场景使用一致的时间参数和状态语义。

## 状态与呈现分离

请求状态必须立即更新，业务逻辑不能为了动画人为等待。
界面是否显示加载提示由单独的稳定呈现层决定。

```text
即时状态 pending
  -> 延迟显示判断
  -> 最短展示判断
  -> 视觉状态 visible
```

不要通过给请求、路由或成功结果增加固定延迟来解决闪烁；这会让所有快速操作都变慢。

## 默认时间

当前默认建议：

- 延迟显示：`200ms`。
- 最短展示：`350ms`。
- 进入和离开动画：使用各平台现有的短时 motion 参数（前端为 `120ms` 或 `160ms` token）。

这两个计时不属于装饰动画：延迟显示用于过滤快速完成，最短展示用于避免已经出现的提示形成闪光。
具体场景只有在可用性、安全性或用户预期明显不同的情况下才调整参数。

## 初始启动

应用启动时尚无可保留的业务内容，采用启动门：

```text
开始检查
  |- 200ms 内成功：直接显示业务界面
  |- 超过 200ms：显示加载提示
  |    `- 提示出现后至少保持 350ms
  `- 明确失败：立即显示错误状态
```

延迟窗口内保持与应用一致的中性背景，不提前挂载业务内容，也不显示短暂的加载提示。
中性背景遮挡首帧空白不属于加载提示，可以立即出现；受延迟和最短展示约束的是加载指示器本身。

## 后台刷新

界面已经有可用内容时，优先采用保留内容的刷新方式：

- 定时或周期性检查不切换为全屏“检查中”。
- 列表筛选、分页和重新加载优先保留旧结果，并在局部显示轻量刷新状态。
- 新请求取消、旧请求被替换不属于错误，不显示断连或失败状态。
- 只有确认当前内容已经不可安全使用或服务不可达时，才使用阻断层。

## 错误和恢复

- 网络连接失败、权限失效等明确结果不等待加载提示的延迟计时。
- 错误恢复后，尽量恢复原有上下文（路由、筛选条件、滚动位置等）。
- 错误面板自身的标题、说明和按钮区域应预留稳定空间，避免状态文字变化引起容器跳动。
- 自动重试与手动重试必须复用同一个并发请求，避免重复提交。

## 可访问性

- 纯等待状态使用礼貌播报，避免短暂状态频繁打断读屏。
- 明确错误使用 `alert` 或等价语义，并提供可执行的恢复入口。
- 加载提示隐藏后，焦点应回到恢复的业务上下文或合理的默认位置。
- 减少动态效果偏好只压缩视觉动画，不跳过延迟显示和最短展示的稳定性规则。
