# 立创物品一键批量创建 + 第三方备份导入（2026-07-27，方案待实施）

> 实施状态：**特性一（一键批量创建）已实施**（2026-07-27）——
> `components/items/useBatchLcscItemCreation.ts` 批量会话 +
> `BatchLcscCreateOptionsDialog.vue` 批次选项 + `LcscOrderImportDialog` 操作区入口
> （modal-actions 左侧独立左置，与右侧“取消/加入明细”决策流分开，经用户确认）与
> `creating`/`create-failed` 行状态（行内重试/手动新建，关闭中止安全）。
> **特性二（备份导入器）已实施**（2026-07-27，阶段2）——落地细化与状态见
> `erp-backup-import-implementation.md`；复用了特性一的批量创建 composable。

两个关联特性：

1. **一键批量创建物品**：导入预览中的未匹配真 C 码行，一次性按立创资料批量建物品，
   不再逐行打开确认 Dialog。
2. **第三方备份导入器**：解析开源 App「LCSC Android ERP」的 xlsx 备份
   （四表：meta / storage_locations / components / inventory_items），
   落成库位 + 物品 + 期初入库。

## 背景与依据

- 现状：`LcscOrderImportDialog` 未命中行的"新建"逐行打开 `LcscLookupFlowDialog` 人工确认，
  批量场景是纯机械操作。
- 批量化的两个前置条件已具备：全局默认物品属性模板（自动预选并应用）与成熟的
  立创资料 → 物品草稿映射。
- **关键性质（`itemLcscMapping` 测试已覆盖）**：立创参数匹配模板字段的进结构化字段
  （`custom: false`），匹配不上的自动落自定义属性（`custom: true`），参数不丢失。
  模板选择只影响结构化程度，不影响数据完整性——这使"整批一个模板"成为低风险操作。
- 备份格式语义已经对照其源码（`InventoryBackupManager.kt` 等）核实，
  见下文"备份格式事实"。

## 已确认的决策

- **勾选子集分批（2026-07-27 修订）**：原定"整批一个模板不做勾选"，用户实际使用后要求加回
  勾选——未匹配/失败行带勾选框（默认全选、表头全选/半选联动），"创建选中的 N 个物品"
  只作用于勾选行。这样不同类别可分批用不同模板：勾电阻→电阻模板创建，再勾连接器→连接器
  模板创建。单批内仍是一个模板（不做按行选模板），分组决定交给勾选。
- **前置"批量创建选项"对话框**：模板（预选全局默认，可换其它或"不使用模板"，
  批次级覆盖不改全局设置）、分类（默认不指定，可统一指定一个）、单位（默认"个"）。
  同一导入会话内记住上次选择，不持久化（避免与全局默认模板形成两套默认值语义）。
- **分类不做"按立创分类名自动匹配"**：批次统一指定或留空，不自动建分类、不自动绑定。
- **C0 手工器件暂不导入，只给提示文案**（见下文文案）。
- **备份内嵌图片忽略，图片一律在线获取**（走现有立创查询链路）。
- **单个新建流程保留不变**：`LcscLookupFlowDialog` 仍是精细控制入口，批量与单个不互斥。

## 特性一：一键批量创建物品

### 交互

- 导入预览（订单导入 / 备份导入共用）出现"一键创建 N 个物品"入口，N = 未匹配的
  真 C 码去重数。
- 点击 → "批量创建选项"对话框（模板/分类/单位）→ 确认后逐项执行。
- 执行中：进度（创建中 i/N）+ 逐行状态徽标：待创建 / 已创建 / 失败（可见原因）/ 跳过。
- **失败不阻塞后续**；失败行可单独重试，或回落现有单个新建 Dialog 人工处理。
- 同 C 码重复行只创建一次，其余行自动匹配到同一物品；创建成功的行自动转为已匹配。

### 数据映射（批量时的规则）

- 名称/品牌/封装/参数：沿用现有立创映射；参数按上述性质进模板字段或自定义属性。
- 属性模板：批次所选（默认=全局默认模板）。
- 分类：批次所选或留空；单位：批次所选（默认"个"）。
- 图片：优先在线拉取并进入现有图片草稿/上传链路；商城明确无图时生成带客编的“暂无商品图片”PNG，
  不因第三方缺图阻断有效器件创建。

### 技术路线

- 前端循环现有端点（立创 lookup → 图片上传 → 创建物品），**不新增 core 批量接口**。
- 串行执行天然限速，避免触发立创反爬（该第三方 App 为绕反爬专门实现了验证 cookie
  的 RC4 解算，说明批量抓取确实会被拦截）。
- 实现为可复用 composable（如 `useBatchLcscItemCreation`），订单导入、备份导入
  及未来 BOM 导入共用。

## 特性二：第三方备份导入器

### 备份格式事实（对照 LCSC Android ERP 源码核实）

- xlsx 四表；`meta.schemaVersion != 1` 拒绝；字段**按表头名**取列（对列顺序不敏感）；
  数值单元格为 double（读取按 long/int 解析）。
- `components.partNumber`：真立创 C 码，或 `C0<自增序号>` 手工入库伪码
  （`^C0\d+$`，真 C 码无前导零不会冲突）。
- 图片以 XSSF 浮动图片锚定在 components 行（`xl/media/`），SheetJS CE 读不到——
  按已确认决策忽略，在线补图。
- 该 App 的流水表 `inventory_txn` 不进备份；备份是存量快照
  （`inventory_items`：器件 × 库位 × 数量 + `lastInboundAt`）。
- 无批次、无有效期、无单价、无单位；`ComponentEntity.mpn` 不进备份。
- `meta.recentLocationColors` 为 UI 偏好，忽略。

### 导入流程

1. 解析四表（SheetJS，复用订单导入的文件读取模式；动态 import 不进主包）。
2. **库位预览**：按 `code` 匹配已有库位；缺失的在默认库区下新建。
3. **物品预览**：
   - 已有同 C 码物品 → 直接匹配复用；
   - 未匹配真 C 码 → 走特性一的一键批量创建；
   - `C0*` 手工器件 → 跳过：预览中灰显、不可选、标"手工器件"徽标，并提示（文案见下）。
4. **期初入库**：写入入库草稿（与订单导入同构，最大化复用草稿全链路），
   每条 inventory_items 行 → 一条草稿行：
   - 数量 = `quantity`（为 0 的行跳过）；
   - 单价 = 0（**不用立创当前参考价**——那是今日售价非当时成本，会污染成本统计）；
   - 库位 = 对应库位；批次留空（审批阶段自动生成内部批次号）；有效期留空。
5. 提交时预填：`source = "第三方备份导入"`（可筛选、可追溯），
   `notes` = 备份文件名 + 备份内时间（`lastInboundAt`/导出时间）+ 跳过的 C0 项数。
   走现有提交/审批流程；本机单人模式建议直接完成入库（以现有提交 UI 能力为准）。
6. **重复导入防护**：导入前查询是否已存在 `source = "第三方备份导入"` 的单据，
   存在则警告"此备份可能已导入过，再次导入会使数量翻倍"，由用户决定继续与否。

### 时间戳边界（明确不做）

WineStock 单据与流水时间由服务端在创建/审批时生成（审计一致性），
**不把备份的 `lastInboundAt` 伪造成历史流水时间**；历史时间只以文本形式存在于单据备注。
明细行无备注字段，逐行保留 `lastInboundAt` 不可行，接受为快照式备份的固有损失。

### C0 跳过提示文案（已确认）

> **已跳过 N 项手工录入器件**
> 编号以 C0 开头的器件（C01、C02…）是原软件里手工创建的，不对应立创商品，
> 无法在线获取资料，本次导入不包含。如需保留，请在导入完成后手工创建这些物品。

## 明确不做

- 按行/按分类**自动**分组选模板（单批内仍一个模板；分批由用户勾选决定，见"已确认的决策"）；
- 立创分类名自动匹配/自动创建 WineStock 分类；
- 解析备份内嵌图片（在线补图替代）；
- C0 手工器件导入（后续有需要再做手工映射流程）；
- 还原历史流水/伪造历史时间戳；
- core 侧批量创建接口（前端串行循环现有端点）。
