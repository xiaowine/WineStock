# 物品目录库存监控实施方案

> 实施状态：已完成（2026-07-13）

本文记录物品管理页面从基础资料目录扩展为“物品维护 + 库存监控 + 补货判断”工作台的确认方案。
本方案同时涉及 `core` 数据库、repository、service、HTTP/OpenAPI 契约，以及 `frontend` 桌面表格、移动列表和物品 Dialog，因此放在根级跨组件实施记录中。

本文既保留确认过的实施依据，也记录最终验收边界。最终结构已经同步到数据库文档、业务 API 文档、校验文档、前端交互文档和前后端代码地图。

## 目标

当前物品目录一行只展示主图、名称、SKU、单位、分类和属性数量，桌面横向空间利用率较低，也不能直接判断库存风险。

目标调整为：

- 物品目录继续承担物品资料查找、新建和编辑。
- 同时展示实时库存量、库存价值、补货点和补货状态。
- 桌面端使用紧凑表格提高横向信息密度和同屏物品数量。
- 移动端使用无横向滚动的库存卡片。
- 物品 Dialog 复用现有多页 Dialog 语言，补充库位和批次详情。
- 库存数据基于批次实时聚合，不增加需要额外同步的库存汇总表。

## 已确认决策

- 列表库存量和库存价值使用数据库实时聚合。
- 补货状态使用固定规则，不计算建议补货数量。
- 桌面使用“固定表格骨架 + 复合纵向单元格”，不使用商城式卡片或每个字段独占一列的宽表格。
- 桌面固定左侧物品身份列和右侧库存判断列，中间列允许横向滚动。
- 模板显式定义最多三个目录展示属性。
- 自定义属性默认不进入目录。
- 默认筛选为“全部”，默认按补货紧急程度排序。
- 主筛选保留“全部、需要处理、缺货、待补货、需配置”，并展示服务端全量数量。
- 库存价值继续使用 `stock.item.read`，不增加独立成本查看权限。
- 批次使用服务端分页，每页二十条。
- 已有物品 Dialog 使用“物品资料、库存详情”双页结构；新建物品继续复用同一编辑器，但保持单页创建会话。
- 库存详情按需加载、会话内缓存并支持手动刷新，不自动轮询。
- 本功能一次完成端到端交付，内部按数据库、后端、列表、Dialog 和验收阶段推进。

## 库存状态语义

状态按以下优先级判断：

```text
current_quantity <= 0
  -> out_of_stock / 缺货

current_quantity > 0
且 reorder_point 已设置
且 current_quantity <= reorder_point
  -> reorder_due / 待补货

current_quantity > 0
且 reorder_point 未设置
  -> needs_configuration / 需配置

其它
  -> normal / 库存正常
```

补充规则：

- 到达补货点即触发待补货，使用 `<=` 而不是 `<`。
- 库存为零时优先判定缺货，即使补货点未设置也不归入需配置。
- `需要处理` 是缺货和待补货的并集。
- `需配置` 不属于需要处理；它表示资料配置不完整，不直接表示需要采购。
- `reorder_point` 只是触发阈值，不是目标库存，不能据此计算建议补货数量。

## 数据库调整

### 目录展示属性

在统一属性定义结构 `stock_item_attribute_definitions` 中增加：

```text
catalog_visible BOOLEAN NOT NULL DEFAULT FALSE
```

约束：

- 只有模板属性定义允许设置 `catalog_visible = TRUE`。
- 物品私有自定义属性定义固定为 `FALSE`。
- 每个模板最多三个目录展示属性。
- 目录属性展示顺序复用定义已有的 `sort_order`，不增加第二套顺序字段。
- 创建和更新模板时由 service 校验数量上限，不能只依赖前端限制。

本字段应与 `unified-item-attribute-definitions.md` 中的统一定义结构一起落地，避免在旧模板字段表和新定义表中分别实现。

### 库存数据

不新增库存快照或汇总表。库存事实继续来自当前批次：

```text
stock_batches.item_id
stock_batches.location_id
stock_batches.remaining_quantity
stock_batches.unit_cost
```

只统计：

```sql
remaining_quantity > 0
```

## API 契约重构

本次不是在现有通用物品 CRUD 响应上追加库存字段，而是按使用场景重新设计命令与查询契约。
当前 `ItemResponse` 同时被物品目录、编辑器和入库选择复用，继续扩展会使调用方获得大量无关字段，也会把库存分页状态污染到创建和更新响应中。

本次允许破坏性修改，不保留没有业务意义的旧响应兼容层。前端所有调用方、OpenAPI、测试和业务文档必须在同一阶段完成迁移。

### 删除的旧契约

- 删除通用 `ItemResponse`。
- 删除 `PaginatedResponse<ItemResponse>` 形式的旧物品列表响应。
- 删除同时包含物品资料、库位汇总和完整批次数组的旧 `ItemDetailResponse`。
- 删除只为旧响应服务的 service 转换函数、repository 包装模型、前端类型和兼容测试。
- 不保留新旧响应并行、字段别名或旧路径包装器。

### 保留的写入能力

物品仍然需要新建、更新和软删除，因此保留：

```text
POST   /api/items
PUT    /api/items/{id}
DELETE /api/items/{id}
```

`POST` 和 `PUT` 继续分别接收结构化的 `ItemCreateRequest` 与 `ItemUpdateRequest`，但不再返回目录或编辑器查询实体，统一返回轻量命令结果：

```text
ItemMutationResponse
  id
  updated_at
```

保存成功后，调用方根据场景重新加载目录或轻量选择列表。`DELETE` 继续返回 `204 No Content`。

### 分层边界

HTTP、service 和 repository 不共用同一个万能结构体：

- controller DTO 只表达公开 HTTP 契约和参数校验。
- service 使用领域查询条件和领域结果，统一计算库存状态及业务边界。
- repository 使用数据库查询输入和投影记录，不直接返回 HTTP DTO。
- controller 或明确的响应投影层负责把 service 结果转换为 HTTP 响应。
- HTTP 枚举值必须稳定，数据库查询实现不能成为公开契约的一部分。

### 新查询契约总览

```text
GET /api/items
  ItemCatalogQuery
  -> ItemCatalogPageResponse

GET /api/items/options
  ItemOptionQuery
  -> ItemOptionPageResponse

GET /api/items/{id}
  -> ItemEditorResponse

GET /api/items/{id}/inventory
  -> ItemInventoryResponse

GET /api/items/{id}/batches
  ItemBatchQuery
  -> ItemBatchPageResponse
```

静态路径 `/api/items/options` 必须显式注册，并由路由与 OpenAPI 契约测试保证它不会被动态 `/{id}` 路径误解析。

## 物品列表查询

`GET /api/items` 破坏性升级为物品目录库存查询，不再承担编辑器资料或通用物品选择职责。

### 查询参数实体

目录使用独立的结构化查询参数：

```text
ItemCatalogQuery
  page
  page_size
  search
  category_id
  attribute_template_id
  stock_filter
  sort
```

- controller 负责页码、非空搜索词、枚举值和 ID 的基础校验。
- service 把 HTTP 参数归一化为 `ItemCatalogCriteria`，补齐默认筛选和默认排序。
- repository 只接收已经校验的 `ItemCatalogCriteria`，不能接收原始查询字符串。
- 新增筛选和排序必须扩展明确枚举，不能使用任意字段名或任意 SQL 排序字符串。

### 实时聚合

物品分页查询通过按 `item_id` 分组的子查询或 CTE 一次聚合：

```text
current_quantity = SUM(remaining_quantity)
inventory_value = SUM(remaining_quantity * unit_cost)
location_count = COUNT(DISTINCT location_id)
batch_count = COUNT(batch.id)
```

没有有效批次的物品统一返回零，不能返回 `null`。

禁止前端对每一行调用物品详情接口。默认每页五十个物品时，不能产生五十个详情请求。

### 目录专用响应

目录使用独立响应，避免创建、更新、编辑器和选择器被库存分页字段污染：

```text
ItemCatalogEntryResponse
  item fields
  catalog_attributes
  current_quantity
  inventory_value
  location_count
  batch_count
  stock_state

ItemCatalogCountsResponse
  total
  needs_attention
  out_of_stock
  reorder_due
  needs_configuration

ItemCatalogPageResponse
  items
  counts
  page
  page_size
  total
  total_pages
```

目录属性建议由后端直接返回筛选后的展示值：

```json
{
  "catalog_attributes": [
    { "name": "型号", "value": "CH32V203F8T6", "unit": null },
    { "name": "封装", "value": "LQFP48", "unit": null }
  ]
}
```

后端按模板定义的 `catalog_visible` 和 `sort_order` 选择最多三个属性。前端不猜测字段名称，也不自行从全部属性中选择。

`ItemCatalogPageResponse` 是完整的目录查询响应，不再外包一层通用 `PaginatedResponse<ItemResponse>`。

两个 `total` 的口径必须明确区分：

- `ItemCatalogPageResponse.total` 是应用当前 `stock_filter` 后的分页总数，用于计算当前结果页数。
- `ItemCatalogCountsResponse.total` 忽略当前 `stock_filter`，表示当前搜索、分类和模板条件下的全部物品数，对应“全部”筛选数量。
- 两者只有在 `stock_filter = all` 时才应相等。

### 筛选参数

增加列表库存筛选参数：

```text
stock_filter = all
             | needs_attention
             | out_of_stock
             | reorder_due
             | needs_configuration
```

筛选含义：

- `all`：全部物品。
- `needs_attention`：缺货或待补货。
- `out_of_stock`：仅缺货。
- `reorder_due`：仅待补货。
- `needs_configuration`：仅库存大于零且未设置补货点。

### 状态数量

列表响应增加状态汇总：

```text
total
needs_attention
out_of_stock
reorder_due
needs_configuration
```

统计口径：

- 使用当前搜索、分类、模板等资料筛选条件。
- 忽略当前 `stock_filter`，保证切换库存筛选时其它选项数量稳定。
- 统计全量匹配数据，不能使用当前分页或前端已加载列表计算。
- `needs_attention = out_of_stock + reorder_due`。

### 排序参数

增加服务端排序：

```text
sort = replenishment_priority
     | name
     | quantity_asc
     | quantity_desc
     | inventory_value_desc
     | updated_desc
```

默认排序 `replenishment_priority`：

```text
缺货
待补货
需配置
库存正常
```

同一状态内按名称、SKU 和物品 ID 稳定排序。
其它排序也必须把物品 ID 作为最终稳定排序键，避免滚动分页重复或漏项。

## 轻量物品选择查询

入库单等业务选择物品时不需要库存监控表格的全部聚合字段，也不应继续依赖旧通用物品列表。

增加：

```text
GET /api/items/options
```

查询参数：

```text
ItemOptionQuery
  page
  page_size
  search
  category_id
  attribute_template_id
```

响应：

```text
ItemOptionResponse
  id
  name
  sku
  category_id
  category_name
  image_file_id
  image_url
  unit

ItemOptionPageResponse
  items
  page
  page_size
  total
  total_pages
```

约束：

- 不返回参考价格；选择物品阶段尚未填写本次入库价格，展示该值没有明确操作意义。
- 不返回完整属性、库存价值、状态计数、库位数或批次数。
- 返回全部仍有效且允许选择的物品，不因为已经存在于当前前端草稿而改变服务端查询结果；同一物品只能加入一次由草稿领域状态保证。
- 搜索、分页和取消旧请求继续遵守统一异步状态规范。
- 后续其它业务需要选择物品时优先复用该轻量契约，不能重新复用目录库存响应。

## 物品详情与批次分页

### 编辑器资料

`GET /api/items/{id}` 只返回编辑器恢复草稿所需的资料：

```text
ItemEditorResponse
  基础资料
  主图引用
  分类和模板引用
  模板属性值
  自定义属性定义和值
  created_at
  updated_at
```

它不返回库存聚合、库位或批次分页数据。编辑图标打开资料页时只请求该接口。

### 库存详情

增加：

```text
GET /api/items/{id}/inventory
```

返回 `ItemInventoryResponse`：

- 物品 ID、名称、SKU 和单位等只读上下文。
- 当前库存量。
- 当前库存价值。
- 补货状态。
- 按库位汇总的库存分布。
- 当前有效批次数量。

库位汇总包含：

```text
location_id
location_code
location_name
quantity
value
batch_count
```

库存详情不携带批次数组，避免详情响应大小随历史批次数增长。

### 批次接口

批次使用独立查询参数和分页响应：

```text
GET /api/items/{id}/batches?page=1&page_size=20

ItemBatchQuery
  page
  page_size

ItemBatchPageResponse
  items
  page
  page_size
  total
  total_pages
```

权限继续使用：

```text
stock.item.read
```

只返回 `remaining_quantity > 0` 的批次，字段包括：

```text
id
batch_no
location_id
location_code
location_name
initial_quantity
remaining_quantity
unit_cost
value
received_at
expires_at
```

默认顺序：

1. 有有效期的批次优先。
2. 有效期从近到远。
3. 入库时间从早到晚。
4. 批次 ID 从小到大。

无有效期批次排在有有效期批次之后。

## 模板 API 与界面

模板字段创建、更新和响应 DTO 增加：

```text
catalog_visible
```

模板编辑界面：

- 每个模板属性提供“在物品目录展示”复选框。
- 已选三个后，其它未选复选框禁用。
- 不能通过前端禁用替代服务端校验。
- 保存失败时把结构化字段错误定位到对应模板字段。
- 自定义物品属性编辑器不显示此配置。

当前完整“分类与模板”业务页尚未进入实现范围，因此目录展示字段先通过物品目录工具栏的“目录属性设置”会话维护。该会话只编辑现有模板的 `catalog_visible`，不重复承担模板字段增删、类型或单位规则编辑；后续模板管理页落地时应迁移同一配置并删除当前入口，不能同时保留两个设置位置。

## 桌面物品目录

桌面端使用紧凑的分组式列表行：保留用户管理页的固定列、跨行对齐和排序能力，但允许一个单元格内部纵向展示多个相关字段。

这种结构参考元件商城“图片开头、参数分组纵向排列”的信息组织方式，但不复制促销标签、价格阶梯、收藏、对比、购物车、整行大卡片阴影或过大的图片和内边距。

目标是同时满足：

- 固定字段能够跨行快速比较。
- 不同模板的动态属性不需要强行映射到统一表头。
- 单行可以展示足够的库存判断信息，但仍保持管理工具所需的紧凑密度。
- 左侧身份和右侧库存判断不随中间区域横向滚动消失。

### 固定左侧：物品身份

建议宽度约 `280px` 至 `320px`，图片建议使用稳定的 `72px` 至 `80px` 方形尺寸。单元格内部组合展示：

- 物品主图。
- 物品名称。
- SKU。
- 分类。
- 编辑图标。

名称、SKU 和分类在图片右侧纵向排列。SKU 和分类属于身份信息，不再额外占用中间列；长名称不能压缩图片或编辑操作。

### 中间可滚动复合列

```text
关键属性
库存辅助信息
资料信息
```

说明：

- “关键属性”是一个约 `220px` 至 `260px` 的复合单元格，最多纵向展示三项目录属性。
- 每项采用弱化属性名、突出属性值的“名称：值”形式，不为动态模板属性创建独立表头列。
- 属性名和属性值均需要稳定截断，超长内容省略并提供原生标题查看。
- “库存辅助信息”纵向展示库存价值、库位数和批次数；库位与批次可以显示为“3 个库位 · 5 个批次”。
- “资料信息”可以纵向展示参考单价和资料更新时间；参考单价不能与批次成本聚合出的库存价值混为一个指标。
- “资料更新”明确表示物品资料更新时间，不表示最近库存变动。
- 中间复合列可以整体横向滚动，但其内部字段不能因为内容变化改变整行高度。

### 固定右侧：库存判断

建议宽度约 `180px` 至 `220px`，纵向展示：

- 当前库存量和单位。
- 补货点。
- 库存状态。

当前库存是该区域最醒目的数值，补货点和状态保持稳定位置。库存状态不能只通过颜色表达。

固定左右列必须保持自身背景和边界，横向滚动时不能与中间内容叠字。
正常桌面宽度应尽量完整展示；窄桌面允许中间列滚动，但物品身份和库存判断始终可见。

### 行高与密度

- 单行高度由图片和三行参数共同决定，建议控制在约 `96px` 至 `112px`，不能扩展成商城式大卡片。
- 行内垂直间距应紧凑且稳定，不使用 `20px` 级的大面积四周内边距。
- 不使用每行独立圆角卡片和悬浮阴影；继续保持连续列表或表格的扫描关系。
- 最长名称、三个长属性、大库存数字和错误占位均不能改变其它行的列位置。

### 行交互

- 点击整行打开同一个物品 Dialog，默认进入库存详情。
- 点击物品身份列中的编辑图标进入物品资料页。
- 编辑图标阻止行点击，两个交互不能同时触发。
- 不保留无意义的右侧箭头。

### 工具栏

主筛选保留：

```text
全部 | 需要处理 | 缺货 | 待补货 | 需配置
```

每项显示服务端返回的全量数量，并使用稳定尺寸，不能因数字变化导致操作位置移动。

排序入口：

```text
补货优先
名称
库存从低到高
库存从高到低
库存价值从高到低
最近更新
```

桌面可以使用可排序表头；移动端使用排序菜单。筛选和排序变化均重新请求第一页，不能只处理当前已加载数据。

## 移动物品目录

移动端不渲染桌面表格，也不使用横向滚动。

每个物品使用单列库存项目，展示：

- 主图、名称、SKU 和分类。
- 当前库存。
- 补货点。
- 库存状态。
- 最多两个关键属性。
- 库存价值。
- 编辑图标。

移动端隐藏：

- 参考单价。
- 库位/批次数量。
- 资料更新时间。

点击项目进入库存详情；编辑图标进入物品资料。
状态、数值和操作必须有稳定位置，长名称不能挤压编辑图标或库存状态。

## 物品多页 Dialog

### 页面结构

现有 `ItemCreateDialog -> ItemEditorDialog -> ItemEditor` 复用关系继续保留，不能为了增加库存页复制一套新建表单。
共享不等于所有会话展示相同页面，Dialog 必须在打开时确定不可变的会话模式：

```text
ItemDialogMode
  create
  existing
```

- `create`：没有持久化物品 ID，只展示物品资料表单。
- `existing`：拥有明确物品 ID，允许展示物品资料和库存详情。
- 会话模式由调用入口显式传入，不能只根据可变草稿中的 `draft.id` 临时推断。
- 创建接口成功返回 ID 后，当前 `create` 会话仍然是创建会话；它应关闭并把创建结果交给调用方，不能原地变成已有物品 Dialog。
- 重新打开刚创建的物品时，才建立新的 `existing` 会话并允许加载库存。

编辑或查看已有物品时提供：

```text
物品资料
库存详情
```

新建物品没有库存，不渲染页面导航、库存详情入口、库存摘要占位或库存刷新操作，也不能发起 inventory/batches 请求。

交互参考用户权限设置 Dialog：

- 宽桌面使用左侧页面导航；物品工作区使用独立宽度变体，左侧导航不能侵占当前物品表单的有效内容宽度。
- 窄桌面和移动端在表单内容宽度不足前切换为顶部横向页面导航。
- 页面内容使用 `out-in` 过渡。
- Dialog 标题、物品上下文和底部操作区位置固定。
- 页面切换只替换内容，不重新打开 Dialog。

### 表单宽度约束

当前物品表单在约 `720px` 的宽 Dialog 中使用三列字段。多页导航不能直接插入现有宽度后仍强制三列，否则会把输入框压缩到不可用宽度。

实施要求：

- 为物品多页 Dialog 增加局部 workspace 宽度变体，建议最大宽度约 `920px`；不能修改所有通用 Dialog 的宽度。
- 宽桌面左侧页面导航建议占用 `140px` 至 `160px`，资料面板应保留接近改造前的有效宽度。
- 当视口无法同时容纳导航和资料面板时，优先把导航切换到顶部横向形式，不能继续压缩输入框。
- 表单列数必须根据 Dialog 内容容器宽度决定，不能只使用页面视口媒体查询。
- 资料面板可用宽度足够时保持三列；中等宽度回落两列；极窄宽度回落一列。
- 基础资料、模板属性和自定义属性继续使用同一列系统，不能出现基础资料两列、模板属性三列的情况。
- 描述字段继续独占整行，图片字段独立于普通输入列。
- 自定义属性删除按钮必须保留独立布局空间，不能因降列重新覆盖输入框。
- 左侧导航、顶部导航、加载状态、错误提示和库存页切换均不得改变资料输入框的实际宽度。

验收时必须读取 `getBoundingClientRect()` 比较改造前后的输入框宽度，并检查最长模板字段、自定义属性、单位控件和删除按钮。

### 物品资料页

继续复用现有物品编辑器，展示基础资料、主图、模板属性和自定义属性。

操作区：

```text
取消 | 保存物品
```

保存成功后关闭 Dialog 并刷新物品列表。

### 库存详情页

展示：

- 当前库存量、库存价值、补货点和库存状态。
- 库位汇总。
- 分页批次列表。

库存页右上角使用刷新图标。刷新时：

- 保留已经显示的数据。
- 使用稳定异步提示，不清空整个页面。
- 重置批次分页并重新加载第一页。

操作区：

```text
关闭
```

### 加载策略

- `create` 会话不创建库存异步状态，不挂载库存页面，也不预请求库存接口。
- 点击列表行进入库存详情时立即加载。
- 点击编辑图标进入物品资料时暂不加载库存详情。
- 第一次切换到库存详情时按需加载。
- 已加载数据在本次 Dialog 会话内缓存。
- 不自动轮询。
- 资料草稿跨页面切换保持不变。
- 在库存页关闭存在未保存资料的 Dialog 时，继续使用统一放弃确认。

## 前端异步状态

- 列表搜索、筛选、排序和刷新保留现有内容，使用稳定 pending 提示。
- 新请求取消旧请求，取消不显示错误。
- 筛选数量、表格列和固定列不能在加载时跳动。
- 库存详情初次加载、刷新失败和批次分页失败使用独立状态。
- 批次分页失败保留已加载批次，并提供“重试本页”。
- Dialog 关闭时取消仍在进行的详情和批次请求。

## 权限

- 物品目录、库存数量、库存价值、库位和批次详情统一使用 `stock.item.read`。
- 物品新建和编辑继续使用 `stock.item.manage`。
- 不增加单独库存成本权限。
- 前端隐藏编辑图标不替代服务端权限校验。

## 不在本次范围

- 建议补货数量。
- 目标库存、安全库存、采购周期和平均消耗模型。
- 自动创建采购单或入库单。
- 库存详情自动轮询。
- 独立库存汇总表或物化视图。
- 重新设计侧栏图标。
- 在物品列表内直接修改库存、批次或库位。

## 验收清单

### 后端

- 旧通用 `ItemResponse`、旧列表响应和旧复合详情响应已删除，没有无意义兼容包装。
- 创建和更新只返回 `ItemMutationResponse`，删除继续返回 `204`。
- 目录、选择、编辑资料、库存详情和批次分页使用相互独立的请求与响应实体。
- controller、service 和 repository 模型职责分离，repository 记录没有直接暴露为 HTTP DTO。
- 入库选择接口不返回参考价格或库存监控冗余字段。
- 实时聚合结果与批次表余额一致。
- 无批次物品返回零库存和零价值。
- 状态边界覆盖零库存、等于补货点、未设置补货点和正常库存。
- `需要处理` 数量等于缺货与待补货数量之和。
- 状态数量不受当前库存状态筛选影响，但受搜索等资料条件影响。
- 每种排序均稳定分页，无重复或漏项。
- 目录展示属性最多三个且顺序稳定。
- 批次分页只返回有余额批次并按确认顺序排列。
- OpenAPI 与实现一致。

### 桌面前端

- 固定物品列和库存判断列在横向滚动时保持可见。
- 固定列背景、边界和阴影不会遮挡中间文字。
- 关键属性使用一个纵向复合单元格，不因不同模板动态生成横向表头列。
- 左侧身份、关键属性、库存辅助信息和右侧库存判断形成清晰的信息分组。
- 单行保持紧凑管理列表密度，不出现商城式促销标签、操作条、大卡片阴影或过大留白。
- 一屏信息密度明显高于当前三行目录。
- 状态筛选数量来自服务端全量结果。
- 点击行与点击编辑图标不会同时触发。
- 长名称、长 SKU、三项长属性和大数值不撑开列宽。

### 移动前端

- 不出现横向滚动。
- 当前库存、补货点和状态无需进入 Dialog 即可查看。
- 长名称不会遮挡状态或编辑图标。
- 五项筛选和排序入口在窄屏仍可操作。
- 点击项目和编辑图标语义分离。

### Dialog

- 桌面左侧导航和移动顶部导航与用户权限 Dialog 风格一致。
- 新建和已有物品继续复用同一编辑器；新建会话只显示资料页，不出现空库存页或库存相关请求。
- Dialog 会话模式在打开时固定，创建成功获得 ID 不会使当前新建 Dialog 临时出现库存导航。
- 宽桌面资料面板的输入框宽度不得因左侧导航明显缩小；空间不足时导航必须先切换到顶部。
- 基础资料、模板属性和自定义属性必须按 Dialog 内容宽度同步切换三列、两列或一列。
- 自定义属性删除按钮在所有列数下均不覆盖名称、类型、值或单位输入框。
- 从物品资料切换到库存详情不丢失草稿。
- 库存详情按需加载且只请求一次，手动刷新除外。
- 库位和批次数据与后端详情一致。
- 批次加载更多失败不清空已有数据。
- 新建物品不渲染库存详情页、库存导航、库存占位和库存刷新操作。
- 关闭存在未保存修改的 Dialog 仍有统一确认。
