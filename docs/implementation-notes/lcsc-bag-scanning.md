# 立创料袋扫码方案（2026-07-26 设计定稿，同日实施完成）

本文记录扫码录入功能的跨组件设计决策；实施状态见文末交付顺序。
涉及 frontend 扫码组件与业务接线、android shell 摄像头权限，不改动 core 契约。

实施期追加的用户决策：只识别 QRCode 并尽可能加快扫描（相机帧速度优先解码 + 降采样 +
50ms 取帧间隔，静态图片保持精度优先）；扫码 Dialog 提供摄像头切换（图标按钮循环切换、记住
上次选择，失效自动回退默认后置）与手电筒图标按钮；工作台“扫码添加”与“添加物品”并排放置；
提示行固定在取景画面上方（底部面板中文字变化不挪动画面）；点击取景区触发一次全局对焦后回到
连续对焦（默认自动；Web API 的区域对焦 pointsOfInterest Chromium 未实现，做不到点哪对哪）。
取景区独立为 `BarcodeCameraView` 组件，Dialog 只保留编排与降级路径。
摄像头切换或扫码层关闭时，停止旧流前同步隐藏 video 合成表面；新流进入 `playing` 且组件状态更新后再显示，
切换间隙只呈现取景区固定深色背景，不暴露浏览器或 WebView 的默认 video 占位。

## 背景与选型

- 目标：用扫描立创商城料袋上的二维码代替手工搜索选品，加速新建物品、入库、出库三类高频操作。
- 解码引擎选型 `zxing-wasm`（3.1.2）。评估记录：wasm 由 Vite `?url` 自托管（Android 离线打包可用，无 CDN 依赖）；
  桌面 1280×720 实时解码单帧约 30ms；真实料袋码、生成回环、图片/粘贴解码全部验证通过。
  正式功能使用 `zxing-wasm/reader` 子模块并动态 import，不进入主包。
- 已评估未选：`vue-qrcode-reader`（默认 CDN 加载 wasm、UI 难融入现有设计体系）、`@zxing/library`（维护停滞）、
  `html5-qrcode`（无维护）、`jsQR`/`qr-scanner`（仅 QR，覆盖不了后续 1D 码需求）。

## 料袋码格式与解析

```text
{on:SO26010926692,pc:C2687125,pm:SM05.TCT,qty:100,mc:,cc:1,pdi:193942893,hp:11}
```

键值均无引号，属于立创私有格式。解析纯逻辑由 `frontend/src/lcsc/bagCode.ts` 拥有：

- 仅当能确认为料袋格式且 `pc` 匹配 `C+数字` 时返回结果（`pc` 归一化为大写 C 前缀）；
- 其余任何内容一律返回 null，调用方**静默忽略**，不作为搜索词或错误提示；
- `qty` 非正整数、`pm`/`on` 缺失或为 `null` 占位时对应字段为 null。

物品匹配规则：C 号即物品编号（立创导入已写入 `draft.sku`），按 SKU 精确匹配；不做型号模糊匹配兜底。

## 三场景语义

| 场景     | 入口                                         | pc                     | qty                                | on（订单号）     | 未命中物品                                                 |
| -------- | -------------------------------------------- | ---------------------- | ---------------------------------- | ---------------- | ---------------------------------------------------------- |
| 新建物品 | 与「编号填写」按钮同区（原「查询立创资料」） | 填入立创查询并自动执行 | 忽略                               | 忽略             | 不适用                                                     |
| 入库     | 工作台独立「扫码添加」操作按钮               | 匹配 SKU 进入明细      | 预填入库数量，可改                 | 询问后填整单来源 | 弹快速新建 Dialog，自动以 C 号拉立创资料预填，创建后回明细 |
| 出库     | 同款「扫码添加」按钮                         | 匹配 SKU 进入明细      | 忽略（袋上是包装量，与出库量无关） | 忽略             | 仅提示库中无此物品，不引导新建                             |

## 入库订单号 → 整单来源

来源是入库单级自由文本字段（`buildInboundRequest.source`）。规则：

- 来源为空且扫到 `on` 时，在明细 Dialog 顶部以提示条询问：`[填入] [忽略] [本单不再提示]`，不弹独立确认框；
- 写入格式待定稿时确认：默认「立创 SO26010926692」（带前缀），或按用户要求裸写 SO 号；
- 来源已填（手填或此前扫入）则完全静默；混扫多订单先到先得，不追加不覆盖；
- 「忽略」只对该次生效；同一 SO 不重复询问，换不同 SO 才再问；
- 「本单不再提示」随入库草稿持久化，提交或清空草稿后重置。

## 交互节奏：串行确认

明确弃用"批量静默堆积"模式，采用与现有单物品串行工作台一致的节奏：

```text
工作台 [扫码添加] → 扫码 Dialog（常驻）
  → 命中：关扫码 → 开明细（入库 qty 预填、来源提示条）
      ├─ 保存/暂存/取消明细 → 自动重开扫码，继续下一袋
  → 重复扫到已在草稿的物品：不新增，提示「已在草稿中」+ 编辑入口
  → 关闭扫码 Dialog（X / Escape / Android 返回）= 结束本轮
```

- 扫中反馈：触发震动（Vibration API，不支持的平台自动无感跳过）；
- 识别到非立创内容：静默忽略，扫码 Dialog 保持打开。

## 扫码组件与降级

`BarcodeScanDialog` 为业务无关通用组件：只识别 QRCode 格式并回传原文，由调用方解析与决策。

- 摄像头流：`getUserMedia` 后置优先，torch 支持时提供手电筒；
- 降级路径：拍照（`capture`）、选图、拖放、粘贴共用同一解码入口——覆盖局域网 HTTP
  非安全上下文无摄像头 API 的场景（self-hosted/Android/Tauri 均为 127.0.0.1 安全上下文，不受影响）;
- 遵循异步状态切换规范（200ms/350ms 稳定等待）、ModalDialog 嵌套层级与原生返回 registry。

## 平台任务

Android shell 需放行 WebView 摄像头：`WebChromeClient.onPermissionRequest` + manifest `CAMERA` +
运行时权限请求，属 `android/` 独立任务，未完成前 Android 端走拍照降级路径。

## 出库移动端入口

配套决定：删除出库导航的 `desktopOnly` 标记及整个平台可见性机制（出库是唯一使用者）。
考古结论：该标记 2026-07-12 为首版"桌面端多明细入库工作台"（当时未适配移动端）发明，
同日被占位状态的出库导航照抄；入库 7-13 重构后标记已删，出库的因当时仍是占位页而遗留至今。
出库工作台本身早已按移动端标准实现并验收（`page-outbound.md` 要求 390×844 视口），隐藏入口无现实理由。
