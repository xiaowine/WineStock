# server-mode HTTPS 与证书指纹方案

状态：方案确认，暂未实施。

## 目标

`server-mode` 当前使用 HTTP，登录密码、访问令牌和业务数据可能被局域网监听。
本次将 WineStock 自己提供的 `server-mode` 改为 HTTPS，并让客户端校验服务端身份。

本方案只覆盖 Desktop 和 Android 客户端。纯浏览器暂不支持自动处理自签证书。

## 已确认规则

- `server-mode` 强制使用 HTTPS，不保留 HTTP 兼容监听。
- `self-hosted` 本机模式继续使用 `http://127.0.0.1:<port>`。
- 客户端远端连接只允许 HTTPS。
- 运行设置不要求用户输入协议，只输入 IP/域名和端口，例如：

  ```text
  192.168.1.20:17890
  winestock.local:17890
  ```

- 服务端复制地址界面也使用 IP/域名和端口的形式；程序内部统一补充 `https://`。
- 客户端只保存服务端证书指纹，不保存服务端私钥。
- 指纹使用服务端证书公钥的 SPKI SHA-256 摘要。

## 服务端证书

### 生成和保存

首次切换并保存 `server-mode` 时生成自签名证书和私钥，保存到服务端数据目录：

```text
data/tls/server.key
data/tls/server.crt
```

证书只在 `server-mode` 使用。普通重启、端口修改和局域网地址变化都复用原私钥，
不主动更换服务端身份。

服务启动或保存配置时都要检查证书和私钥：

- 文件不存在：询问用户是否生成新证书；
- 文件损坏或证书与私钥不匹配：询问用户是否重新生成；
- 用户选择不生成：禁用 `server-mode`，切换为仅本机模式；
- 重新生成后：所有客户端都必须重新确认指纹。

私钥不能进入运行快照、Shell Bridge、日志、HTTP 响应或前端存储。

### 证书指纹展示

服务端运行设置显示当前证书指纹：

- 默认显示短指纹，用于人工核对；
- 提供复制完整指纹的操作；
- 不显示或复制私钥。

Server Shell 也应在控制台输出 HTTPS 访问地址和证书指纹。

## 客户端首次连接

客户端在运行设置中保存远端地址时：

1. 根据用户输入的 IP/域名和端口访问 HTTPS 服务。
2. 读取服务端证书并计算指纹。
3. 在界面显示指纹，要求用户与服务端运行设置中的指纹核对。
4. 用户确认后保存地址和指纹。
5. 用户取消或访问失败时，不保存新地址，继续保留旧配置。

首次确认必须发生在运行设置保存流程中，不能自动信任，也不能提供“忽略证书错误”入口。

## 客户端修改地址

客户端修改 IP、域名或端口时，都必须访问新地址并重新校验证书：

- 新地址返回的指纹与已保存指纹一致：保存新地址；
- 指纹不一致：提示用户重新核对，不自动替换旧指纹；
- 无法访问或证书校验失败：保留旧地址和旧指纹。

服务端修改端口不会更换证书。客户端只需要对新端口重新访问和校验。

## 无感证书轮换

证书有效期为 1 年，剩余 30 天时自动轮换。

轮换规则：

- 保留原私钥，只重新生成服务端证书；
- 新旧证书的 SPKI 指纹保持一致；
- 服务端运行中完成 TLS 配置热更新；
- 新连接使用新证书，已有连接继续使用旧连接，不主动断开；
- 局域网 IP 或域名变化导致 SAN 需要更新时，也复用原私钥重新签发证书；
- 轮换成功不提示用户，只写入服务端日志。

轮换失败时继续使用仍有效的旧证书并后台重试。旧证书过期后不能继续提供服务，
服务端通过 notice 提示用户，并禁用 `server-mode`，切换为仅本机模式。

## 主动重置证书

服务端运行设置提供“重置证书”操作：

1. 用户确认危险操作；
2. 删除旧证书和私钥；
3. 生成新的证书和私钥；
4. 重启 HTTPS 服务；
5. 所有客户端因指纹变化而需要重新确认。

重置只允许在服务端本机运行设置中执行，不提供远程 HTTP API。

## 错误提示

前端使用现有 notice 机制，不新增占用页面空间的常驻错误文本。

需要区分以下情况：

- 首次证书获取失败；
- 证书指纹不匹配；
- 服务端证书损坏；
- 证书与私钥不匹配；
- 证书轮换失败；
- 证书已过期。

证书指纹不匹配时，必须停止请求，并提供重新进入运行设置验证的入口；不能直接接受新证书。

## 实施顺序

1. `core` 增加证书生成、加载、校验、指纹计算和 HTTPS 监听。
2. `server` 增加证书目录准备、访问地址和指纹输出。
3. Desktop/Android 增加首次证书获取、指纹校验和 WebView HTTPS 证书处理。
4. 前端运行设置改为 IP/域名 + 端口输入，加入首次确认和错误 notice。
5. 增加证书热轮换、服务端重置和异常降级。

## 最低验收

- `server-mode` 只监听 HTTPS，HTTP 请求不能访问服务。
- 重启和端口修改不会更换证书指纹。
- 首次保存必须人工确认指纹。
- 修改 IP、域名或端口时会重新校验证书。
- 校验失败时旧配置保持不变。
- 自动轮换不改变指纹、不主动断开已有连接。
- 证书损坏、过期或用户拒绝重新生成时，自动切换为仅本机模式。
