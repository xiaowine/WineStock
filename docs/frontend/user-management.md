# 前端用户管理

本文记录 `frontend/` 用户管理页面的当前实现、权限边界和验收范围。

## 页面与路由

- 路由：`/users`
- 路由名：`users`
- 布局：已登录 `AppShell`
- 进入权限：`user.read`
- 桌面使用数据表格，移动端使用同一数据源渲染纵向列表。

一级导航根据当前会话权限快照隐藏无权限入口，路由守卫也会把缺少 `user.read` 的访问返回总览。前端判断只用于交互收敛，Axum 路由仍会读取数据库当前权限并执行最终授权。

## 已接入接口

```text
POST  /api/auth/register
GET   /api/users
DELETE /api/users/{id}
PATCH /api/users/{id}/status
PUT   /api/users/{id}/permissions
POST  /api/users/{id}/password
GET   /api/permissions
```

页面支持：

- 用户名搜索。
- `active`、`disabled` 状态筛选。
- 每页 20 条的服务端分页。
- 创建后续用户；新用户默认没有权限。
- 启用或停用其他用户。
- 软删除其他用户，并在确认界面说明会话吊销、用户名保留和不可撤销影响。
- 整体替换用户权限。
- 为其他用户设置临时密码。
- 加载、空数据、取消旧请求、服务错误和操作结果提示。

## 操作权限

| 操作 | 所需权限 |
| --- | --- |
| 查看页面和列表 | `user.read` |
| 创建用户 | `user.register` |
| 启用或停用用户 | `user.status.update` |
| 软删除用户 | `user.delete` |
| 查看权限定义 | `user.permission.read` |
| 修改用户权限 | `user.permissions.update` + `user.permission.read` |
| 设置临时密码 | `user.password.reset` |

当前页面不提供停用自己、删除自己或为自己设置临时密码的入口。当前用户应使用独立修改密码页修改自己的密码。

前端隐藏入口不是安全边界。后端已经强制禁止停用或删除自己，也禁止为自己设置临时密码，具体错误契约见 `docs/user-management-api.md`。

修改当前用户权限成功后，`auth/session.ts` 会同步内存中的权限快照，使导航和页面操作立即收敛。后续 HTTP 请求仍以服务端实时授权结果为准。

## 密码和账号安全

- 创建密码和临时密码只存在于表单内存和单次 HTTP 请求中，不写入 localStorage。
- 临时密码设置成功后，服务端吊销目标用户 refresh token。
- 目标用户下次登录会被强制导航到 `/change-password`。
- 页面不显示、回读或记录任何明文密码。
- 后端防锁死规则会拒绝停用或删除最后一个权限管理员，或移除其 `user.permissions.update`。

## 代码所有权

- `frontend/src/api/users.ts`：DTO 和 HTTP 请求。
- `frontend/src/auth/permissions.ts`：稳定权限代码和前端只读判断。
- 权限编辑器不硬编码可选权限；后端 `GET /api/permissions` 返回 `user.delete` 后会自动显示并允许分配。
- `frontend/src/pages/UsersPage.vue`：列表、筛选、分页和操作编排。
- `frontend/src/components/users/`：创建、权限、临时密码和启停对话框。
- `frontend/src/components/ModalDialog.vue`：通用模态结构和关闭行为。
- `frontend/src/notices/notice.ts` 与 `frontend/src/components/NoticeViewport.vue`：统一显示用户管理操作的成功和失败反馈。

## 验证重点

- 无 `user.read` 时不显示导航入口，直接访问路由返回总览。
- 创建用户后列表刷新，且新用户权限数为 0。
- 状态筛选和用户名搜索使用真实 API 结果。
- 用户列表使用独立工具栏组件：搜索输入和提交按钮组成搜索控件，清空搜索框后立即恢复未搜索的列表；状态使用分段控制并通过“全部”恢复；结果数量、刷新和创建入口组成列表级操作区，页面标题区不承载操作按钮。
- 权限编辑提交完整权限集合。
- 临时密码登录后必须进入修改密码页面。
- 停用用户后其原有会话失效。
- 删除用户后保留当前筛选并刷新列表；删除末页最后一项时自动回退一页。
- 删除确认明确提示账号无法恢复、用户名不能复用且历史记录会保留。
- 移动端用户卡片只保留单个“管理操作”入口；底部操作面板按列表展示普通操作，并用分隔和危险色单独呈现删除用户。
- 桌面和 390px 移动视口无横向溢出或操作遮挡。
- 桌面表格横向滚动时，左侧用户名和右侧操作列保持固定，仅中间账号信息滚动；两侧固定区域通过底色、边界和阴影与滚动区域区分。超长用户名使用更紧凑的单行省略并保留完整值提示。
- 权限对话框只滚动权限列表；标题、当前账号提示和保存操作保持固定可见。
- 临时密码和账号启停对话框不重复动作标题；目标用户名使用独立账号上下文层级，风险说明与表单正文分离。
- 权限对话框使用相同的固定目标用户上下文；权限分组标题在滚动区域内保持可见，权限行通过分隔和悬浮反馈强化层级，选中状态只由复选框表达。
- 每个权限分类提供独立的“全选 / 取消全选”操作，只修改当前分类并实时更新已选数量。
- 权限选择器只保留分类版本：桌面使用分类侧栏，移动端使用横向分类标签，每次只展示当前分类的权限项。
- 编辑当前账号时，`user.permissions.update` 和 `user.permission.read` 保持原值并禁用单项与分组批量修改；后端仍执行最终安全校验。
- 权限选择区域保持稳定高度；分类切换统一使用 motion token。桌面内容从左侧分类导航方向进入，移动端内容从上方分类标签方向进入，减少动态效果由全局基础样式统一处理。

## 已完成改进

- 页面内的 `page-notice` 已替换为全局 Notice 服务；用户创建、权限保存、临时密码、状态更新、列表刷新和请求失败均使用统一提示。
- Notice 固定在右上角并自动消失，左侧竖条、类型标签和倒计时条使用对应状态色；鼠标悬浮或键盘焦点进入时暂停倒计时。
- Notice 支持标题、可选详情和点击回调；可点击提示支持鼠标、Enter 与 Space，关闭按钮不会触发业务回调。
