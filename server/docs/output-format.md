# Server Shell 输出格式

本文定义 `winestock-server` 命令行输出的组织方式，目标是让首次启动、日常运行和故障排查都能快速找到关键信息。

## 输出目标

Server Shell 是无头服务，不提供前端界面。启动输出需要同时服务于两类使用者：

- 第一次部署的用户：需要知道配置文件在哪里、服务是否启动成功、应该访问哪个地址；
- 日常维护者：需要快速确认监听地址、数据目录、初始化状态和开发文档入口。

输出不应把所有信息平铺成一长串键值列表，也不应输出不能直接访问的地址。

## 启动成功输出

启动成功后按以下顺序输出：

```text
WineStock Server 已启动

配置
  配置文件: D:\WineStock\data\config.json
  配置状态: 已创建默认配置
  数据库: D:\WineStock\data\winestock.sqlite
  文件目录: D:\WineStock\data\files

服务
  监听地址: 0.0.0.0:17890
  本机访问: http://127.0.0.1:17890
  初始化状态: 尚未创建首个用户，请通过注册接口完成初始化

开发文档
  OpenAPI: http://127.0.0.1:17890/api-docs/openapi.json
  Swagger UI: http://127.0.0.1:17890/swagger-ui

按 Ctrl+C 停止服务。
```

### 分组规则

- 标题只出现一次，使用 `WineStock Server 已启动`；
- `配置` 只展示配置和存储位置；
- `服务` 只展示监听状态、可访问地址和初始化状态；
- `开发文档` 仅在 Debug 构建显示；
- 空行用于分隔分组，不使用装饰性边框或大量符号；
- 所有字段使用统一的 `标签: 值` 格式，缩进保持一致。

### 条件输出

- 只有首次创建配置文件时显示 `配置状态: 已创建默认配置`；
- 只有数据库尚未创建首个用户时显示 `初始化状态`；
- Release 构建不显示 OpenAPI 和 Swagger UI；
- Debug 构建未启用 `swagger-ui` feature 时显示启用提示，而不是打印不可访问的地址。

Swagger UI 只在 Debug 且显式启用 `swagger-ui` feature 时编译和显示。正式构建不传该 feature：

```text
cargo +stable build -p winestock-server --release --no-default-features
```

## 地址显示规则

监听地址和访问地址不是同一个概念：

- `监听地址` 表示服务实际绑定的接口；
- `本机访问` 表示当前主机可以直接打开的 URL。

监听地址始终按实际绑定值原样输出，不枚举网卡，也不额外输出局域网 IP。当绑定 `0.0.0.0` 或 `::` 时：

```text
监听地址: 0.0.0.0:17890
本机访问: http://127.0.0.1:17890
```

`0.0.0.0` 或 `::` 只能作为监听地址，不能作为浏览器访问地址。Server Shell 不负责枚举或输出局域网 IP；需要从其它设备访问时，由使用者根据实际网络地址访问对应端口。

## 停止输出

收到 Ctrl+C 后只输出一次关闭提示：

```text
收到退出信号，正在关闭服务...

WineStock Server 已停止。
```

如果服务任务在未收到 Ctrl+C 时意外结束，应优先输出错误并以非零状态退出，不伪装成正常停止。

## 错误输出

错误输出使用中文，并保留底层错误链：

```text
WineStock Server 启动失败: 加载 JSON 配置失败: ...
  原因: ...
```

错误链只使用 `原因:` 作为层级标签，不混用 `caused by`、`source` 等开发内部术语。

## 不应输出的内容

- 密码、会话令牌、JWT 或其它凭据；
- `0.0.0.0`、`::` 作为访问 URL；
- 前端资源路径或 WebView 相关信息；
- 重复打印同一配置路径或服务地址；
- 与当前 Server Shell 无关的桌面、Android 或 Shell Bridge 状态。

## 验收标准

- 默认配置首次启动时，用户能在一屏内找到配置文件、数据库、文件目录和本机访问地址；
- 日常启动时，输出不因缺少可选状态而产生空分组；
- Debug/Release 输出符合构建特性；
- IPv4 wildcard、IPv6 wildcard 和具体绑定地址都有稳定且可读的显示；
- Ctrl+C 后服务完成优雅关闭，并输出明确的停止结果；
- 启动失败时错误信息仍保留完整 source 链。
